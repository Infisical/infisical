Life of a PAM SSH Session

How an SSH account type is defined, how an account of it is created, and how one session reaches the server without the user ever holding its credentials. Step through, click any shape, or press Present to walk through the diagram. Hover anything underlined for a definition.

    Follow one session

    An account type in PAM is mostly data: one config entry whose schemas drive the form, the routes and validation. The interesting part is the session: the client gets a tunnel, the customer's gateway gets the credentials, and for SSH certificate auth those credentials are a certificate minted for this one session. This follows one SSH account from its config entry to the end of a session.

    Where a new account type plugs in
    
        
    What it takes to add a new account type, in the order a session meets it. The first two are required for every type; the rest only when the type needs them.

    required
    
            
      
              
    • Add a PamAccountType value, an ACCOUNT_TYPE_CONFIGS entry (schemas, name, icon, UI hints) and the icon under frontend/public/images/integrations/. Forms, routes and docs follow.

    required
    
            
      
              
    • A case in extractGatewayTarget and in buildGatewayConnectionTest: a real login mode on the gateway, or tcp as the floor.

    Credentials at launch
    
            
    only if needed

    optional
