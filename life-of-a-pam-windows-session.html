Life of a PAM Windows Session

How the Windows and Windows AD account types are defined, how an account is created and tested, how one RDP session reaches a host without the user holding its password, and how that password is rotated. Step through, click any shape, or press Present to walk through the diagram. Hover anything underlined for a definition.

    Follow one session

    Windows in PAM is two account types that share one RDP path to the gateway. What sets them apart from other types is mandatory S3 recording, an RDP client that can run in the browser, and password rotation over WinRM that reaches into other machines. This follows one domain account from its config entry to its next rotation.

    required
    
            
      
              
    • A PamAccountType value, an ACCOUNT_TYPE_CONFIGS entry and an icon. A variant of an existing protocol can alias it in GATEWAY_ACCOUNT_TYPE_ALIASES, as Windows AD does, so the gateway needs nothing new.

    Gateway target and test
    
            
    required
    
            
      
              
    • Cases in extractGatewayTarget and buildGatewayConnectionTest. Windows AD shows a multi-host target and resolveSelectedHost; Windows shows the tcp floor.

    Recording and policies
    
            
    optional
    
            
      
              
    • accountTypeRequiresRecording makes S3 recording mandatory. pam-policies.ts and accountTypeSupportsSessionLogMasking decide which policies apply.

    optional
