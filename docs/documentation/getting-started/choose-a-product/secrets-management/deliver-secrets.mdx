Applications need credentials at runtime, such as database URLs, API keys, and signing keys. These credentials are often stored in `.env` files, in application configuration files, or in environment variables set at deploy time. Infisical can deliver credentials to a running application instead, so the application fetches them from Infisical at startup or on demand rather than reading them from a file.

## Solution

Infisical delivers secrets to running applications through several methods. Each method is suited to a different type of workload.

- The **[CLI](/cli/overview)** provides an `infisical run` command that wraps another command and injects secrets into its environment variables. This method is typically used for local development and simple deployments.
- The **[SDKs](/sdks/overview)** allow application code in Node.js, Python, Go, Java, .NET, C++, Ruby, or Rust to fetch secrets directly from Infisical. This method is used when an application fetches secrets on demand.
- The **[Kubernetes operator](/integrations/platforms/kubernetes/overview)** synchronizes Infisical secrets into native Kubernetes Secrets, or injects them into pods at startup.
- **[Agents](/integrations/platforms/infisical-agent)** are sidecar processes that fetch and refresh secrets into files or into the environment variables of another process.

Select the method that matches how the application runs.

## Get started

1. Follow the [Deliver your first secret](/documentation/platform/secrets-mgmt/quick-starts/deliver-first-secret) guide to store a secret and inject it into a running application.
2. Choose the delivery method that fits your application: [CLI](/cli/overview), [SDKs](/sdks/overview), [Kubernetes](/integrations/platforms/kubernetes/overview), or [CI/CD](/integrations/overview).
