Credentials such as database passwords, API keys, and service account tokens become more likely to be exposed the longer they remain in use, because they accumulate in more locations over time. Rotating a credential manually requires updating its value in every location that uses it, which is error-prone and easy to skip.

## Solution

[Secret rotation](/documentation/platform/secret-rotation/overview) replaces a credential on a schedule that Infisical manages. When a scheduled rotation runs, Infisical generates a new credential on the target platform, updates its value in the Infisical secret store, and applications that fetch the secret receive the new value on their next request. The previous credential remains valid for a configured grace period so that applications can transition to the new value without disruption.

Rotation is supported for several providers, including [PostgreSQL, MySQL, MongoDB, AWS IAM, and Azure](/integrations/secret-rotations).

## Get started

1. Choose a [rotation provider](/integrations/secret-rotations) that matches the credential you want to rotate.
2. Configure the [rotation](/documentation/platform/secret-rotation/overview) with a schedule and the target credential.
