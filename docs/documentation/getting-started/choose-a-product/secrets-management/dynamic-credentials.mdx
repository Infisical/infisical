A credential that persists for a long period becomes more likely to be exposed, because it accumulates in more locations over time. Dynamic secrets are an alternative approach in which a credential is generated at the time of the request and revoked after a short period.

## Solution

[Dynamic secrets](/documentation/platform/dynamic-secrets/overview) generate a credential on demand from a supported provider. Each generated credential represents a distinct entity, such as a new database user, a new IAM role, or a new API key. The credential has a time-to-live (TTL) that Infisical enforces. When the TTL expires, Infisical revokes the credential on the provider so that it can no longer be used.

Dynamic secrets are supported for several categories of providers, including [databases, cloud IAM, message queues, directories, and Kubernetes](/integrations/dynamic-secrets).

## Get started

1. Choose a [dynamic secret provider](/integrations/dynamic-secrets) that matches the resource the application needs to access.
2. Configure the provider and issue your first [dynamic secret](/documentation/platform/dynamic-secrets/overview).
