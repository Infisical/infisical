A webhook channel on a certificate [alert](/documentation/platform/pki/applications/alerting/overview) sends an HTTP POST request to your endpoint whenever the alert fires. Use a webhook to connect certificate alerts to your own systems or to services Infisical doesn't support directly.

## Add a webhook channel to an alert

<Steps>
  <Step>
    [Create an alert](/documentation/platform/pki/applications/alerting/overview#create-an-alert) in your application, or edit an existing one.
  </Step>
  <Step>
    Select **Add Channel** > **Webhook** and enter the **URL** of your endpoint. The URL must use HTTPS.
  </Step>
  <Step>
    Optionally, enter a **Signing Secret** so your endpoint can [verify the signature](#verify-the-signature) of each request.
  </Step>
  <Step>
    Optionally, select **Send test** to send a test notification to the channel.
  </Step>
  <Step>
    Select **Continue**, check the **Review** step, and select **Create Alert**.
  </Step>
</Steps>

## Webhook event types

Each request is a [CloudEvents](https://cloudevents.io/) JSON payload. The `type` and `subject` fields name the event:

| Event | `type` | `subject` |
|-------|--------|-----------|
| Expiration | `com.infisical.cert-manager.application.certificate.expiry` | `cert-manager.application.certificate.expiry` |
| Issuance | `com.infisical.cert-manager.application.certificate.issuance` | `cert-manager.application.certificate.issuance` |
| Renewal | `com.infisical.cert-manager.application.certificate.renewal` | `cert-manager.application.certificate.renewal` |
| Revocation | `com.infisical.cert-manager.application.certificate.revocation` | `cert-manager.application.certificate.revocation` |

## Webhook payload format

`data.items` lists the certificates the alert fired for. Each item has the certificate's ID, its common name as `title`, its serial number as `identifier`, a one-line `summary`, a `severity`, and a list of display `fields`. An expiration request can include several certificates, and `data.alert.condition` holds the alert's lead time as you entered it, such as `30d` or `2w`. Issuance, renewal, and revocation requests include the one certificate the event was about.

<Note>
  Alerts created before certificate alerts moved to this format now send this payload. If your endpoint reads the older `com.infisical.pki.certificate.*` event types or the `data.certificates` list, update it to read `type` and `data.items` as shown here.
</Note>

## Webhook signature verification

If you set a signing secret, Infisical adds an `x-infisical-signature` header to each request:

```
x-infisical-signature: t=<timestamp>,v1=<signature>
```

| Component | Description |
|-----------|-------------|
| `t=<timestamp>` | Unix timestamp in milliseconds when Infisical signed the request |
| `v1=<signature>` | Hex-encoded HMAC SHA256 signature |

### Verify the signature

1. Read the timestamp and the signature from the header
2. Join the timestamp and the raw request body with a dot: `{timestamp}.{raw-body}`
3. Compute the HMAC SHA256 of that string with your signing secret
4. Compare the result with the signature from the header

```javascript
const crypto = require('crypto');

function verifyWebhookSignature(header, body, secret) {
  const parts = header.split(',');
  const timestamp = parts[0].replace('t=', '');
  const signature = parts[1].replace('v1=', '');

  const signaturePayload = `${timestamp}.${body}`;
  const expectedSignature = crypto
    .createHmac('sha256', secret)
    .update(signaturePayload)
    .digest('hex');

  return crypto.timingSafeEqual(
    Buffer.from(signature),
    Buffer.from(expectedSignature)
  );
}
```
