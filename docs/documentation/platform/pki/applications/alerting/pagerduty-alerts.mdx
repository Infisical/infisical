A PagerDuty channel on a certificate [alert](/documentation/platform/pki/applications/alerting/overview) creates PagerDuty incidents through the [Events API v2](https://developer.pagerduty.com/docs/events-api-v2-overview), so your on-call team gets paged when certificates are about to expire or are revoked.

<Info>
  PagerDuty channels are available under Infisical's [Enterprise](https://infisical.com/pricing) plan. If you're self-hosting Infisical, contact sales@infisical.com to purchase an enterprise license.
</Info>

## Prerequisites

- The Certificate Management **Admin** role to create a Certificate Management alert, or the **Admin** [application role](/documentation/platform/pki/applications/overview#application-roles) to create an application alert
- A PagerDuty account that can create services or add integrations to an existing service

## Step 1: Get a PagerDuty integration key

<Steps>
  <Step>
    In PagerDuty, go to **Services** > **Service Directory** and select **New Service**.
  </Step>
  <Step>
    Name the service, for example `Infisical PKI Alerts`, choose **Events API v2** as the integration, and select **Create Service**.

    <Note>
      To use an existing service, open the service and go to **Integrations** > **Add an Integration** > **Events API v2**.
    </Note>
  </Step>
  <Step>
    Copy the 32-character **Integration Key** from the service's **Integrations** tab.

    <Note>
      Anyone with the integration key can send events to your PagerDuty service, so store it like a secret.
    </Note>
  </Step>
</Steps>

## Step 2: Start an alert

<StartAlert />

## Step 3: Add the PagerDuty channel

<Steps>
  <Step>
    Select **Add Channel** > **PagerDuty** and paste the key from [step 1](#step-1-get-a-pagerduty-integration-key) into **Integration key**.
  </Step>
  <Step>
    Optionally, select **Send test** to send a test event to the PagerDuty service.
  </Step>
  <Step>
    Select **Continue**, check the **Review** step, and select **Create Alert**.
  </Step>
</Steps>

<Check>
  Your alert is set up. Infisical opens a PagerDuty incident whenever the alert fires.
</Check>

## Severity mapping

Each incident's PagerDuty severity comes from the alert's event. For expiration alerts, it comes from how close the certificate is to expiry.

### Expiration alerts

| Time until expiry | PagerDuty severity |
|-------------------|-------------------|
| 7 days or less | `critical` |
| 8 to 14 days | `error` |
| 15 to 30 days | `warning` |
| More than 30 days | `info` |

### Other alert events

| Event | PagerDuty severity |
|-------|-------------------|
| Issuance | `info` |
| Renewal | `info` |
| Revocation | `warning` |

## Incident grouping

Each certificate gets its own incident. If the same alert fires again for the same certificate, PagerDuty updates the existing incident instead of opening a new one.

Each PagerDuty channel opens at most 10 incidents per run. If more than 10 certificates are due for an expiration alert, the ones closest to expiry go first and the rest go on the next daily run.
