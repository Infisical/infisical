A PagerDuty channel on a certificate [alert](/documentation/platform/pki/applications/alerting/overview) creates PagerDuty incidents through the [Events API v2](https://developer.pagerduty.com/docs/events-api-v2-overview), so your on-call team gets paged when certificates are about to expire or are revoked.

## Step 1: Get a PagerDuty integration key

<Steps>
  <Step>
    In PagerDuty, go to **Services** > **Service Directory** and select **New Service**.
  </Step>
  <Step>
    Name the service, for example `Infisical PKI Alerts`, choose **Events API v2** as the integration, and select **Create Service**.

    <Note>
      To use an existing service, open the service and go to **Integrations** > **Add an Integration** > **Events API v2**.
    </Note>
  </Step>
  <Step>
    Copy the 32-character **Integration Key** from the service's **Integrations** tab.

    <Note>
      Anyone with the integration key can send events to your PagerDuty service, so store it like a secret.
    </Note>
  </Step>
</Steps>

## Step 2: Add the PagerDuty channel to an alert

<Steps>
  <Step>
    [Create an alert](/documentation/platform/pki/applications/alerting/overview#create-an-alert) in your application, or edit an existing one.
  </Step>
  <Step>
    Select **Add Channel** > **PagerDuty** and paste the integration key.
  </Step>
  <Step>
    Optionally, select **Send test** to send a test notification to the channel.
  </Step>
  <Step>
    Select **Continue**, check the **Review** step, and select **Create Alert**.
  </Step>
</Steps>

## Severity mapping

Infisical sets each incident's PagerDuty severity from the alert's event. For expiration alerts, the severity comes from the certificate closest to expiry in that run.

### Expiration alerts

| Time until expiry | PagerDuty severity |
|-------------------|-------------------|
| 7 days or less | `critical` |
| 8 to 14 days | `error` |
| 15 to 30 days | `warning` |
| More than 30 days | `info` |

### Other alert events

| Event | PagerDuty severity |
|-------|-------------------|
| Issuance | `info` |
| Renewal | `info` |
| Revocation | `warning` |

## Incident grouping

Infisical opens one incident per certificate. If the same alert fires again for the same certificate, PagerDuty updates the existing incident instead of opening a new one.

Each PagerDuty channel opens at most 10 incidents per run. If more than 10 certificates are due for an expiration alert, Infisical sends the certificates closest to expiry first and sends the rest on the next daily run.
