Every Agent Gateway setup starts with the same three things: a secret holding the real credential, a proxied
service saying which host that credential is applied to, and an Agent Gateway that brokers it for the people
allowed to use it. This page creates all three, then points you at the mode that matches where your agent runs.

GitHub is this guide's running example. Any other API works the same way.

## Before you begin

- An Infisical Secrets Management project.
- A GitHub account, to create the token you will broker.

## 1. Add a secret

First, get a GitHub personal access token to broker:

1. Go to [GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens](https://github.com/settings/personal-access-tokens).
2. Click **Generate new token**, give it a name, set an expiration, and choose the resource owner.
3. Leave the permissions at their defaults. The check at the end of this guide calls `GET /user`, which any
   valid token can reach; later, grant only what your agent actually does.
4. Click **Generate token** and copy the `github_pat_…` value. GitHub only shows it once.

Then, in your Infisical project, create a folder for the agent (for example `/coding-agent` in the `dev`
environment) and add a secret named `GITHUB_PAT` with that token as its value. It is a regular Infisical secret.

![The /coding-agent folder with GITHUB_PAT added](/images/platform/agent-gateways/quickstart-add-secret.png)

## 2. Create a proxied service

A proxied service maps a host to the secret the broker applies. Go to **Secrets Management → Agentic → Proxied
Services**, click **Add Proxied Service**, and work through the steps:

<Steps>
  <Step title="Pick the GitHub template">
    The template fills everything in for you: the host `api.github.com` and a **Secret Substitution** rule that
    hands the agent a realistic `ghp_…` placeholder and swaps in the real token on the way out.

    ![The proxied service template picker with GitHub available](/images/platform/agent-gateways/quickstart-template-picker.png)
  </Step>
  <Step title="Details">
    Keep the service name `github` and the host pattern `api.github.com`. Set the environment to `dev` and the
    path to `/coding-agent`, so the credentials in the next step default to where you put the secret.

    ![The Details step with the service name and host pattern](/images/platform/agent-gateways/service-details.png)
  </Step>
  <Step title="Header Rewrites">
    Skipped automatically for GitHub. The token does travel in the `Authorization` header, but this template
    handles that with **Secret Substitution**: the agent itself puts a placeholder in the header, and the broker
    swaps it for the real token.
  </Step>
  <Step title="Secret Substitution">
    Select `GITHUB_PAT` as the secret holding the real value.

    Here is how the pieces fit. When your agent starts, it gets an environment variable `GITHUB_TOKEN` (the
    placeholder name the GitHub template uses) set to the fake `ghp_…` value. The agent uses it like any GitHub
    token and sends `Authorization: Bearer <placeholder>`. As the request passes through the broker, the
    placeholder is replaced with the real value of your `GITHUB_PAT`. The template scopes this swap to headers,
    since that is where GitHub expects the token; a substitution can also target the URL path, query, or body.

    ![The Secret Substitution step swapping a placeholder for the real secret](/images/platform/agent-gateways/secret-substitution.png)
  </Step>
  <Step title="Review and create">
    Double-check the host pattern and the substitution rule, then click **Create Proxied Service**.

    ![The Review step showing the Secret Substitution rule for GITHUB_PAT](/images/platform/agent-gateways/quickstart-review.png)
  </Step>
</Steps>

<Note>
  Not on the template list? Pick **Custom** and configure a
  [header rewrite or secret substitution](/documentation/platform/agent-gateways/proxied-services) by hand.
</Note>

## 3. Create an Agent Gateway

Go to **Secrets Management → Agentic → Agent Gateways** and click **Add Agent Gateway**:

<Steps>
  <Step title="Name it">
    Call it `coding-agent`. This is the name your agents pass to `--name`.
  </Step>
  <Step title="Leave the Gateway as None (local only)">
    You can attach a [Gateway](/documentation/platform/gateways/overview) later, when you want to broker for
    agents running somewhere other than your own machine. Leave **Allow local mode** on.
  </Step>
  <Step title="Connect the proxied service">
    Open the Agent Gateway, and in the **Proxied Services** card click **Connect Services** and pick `github`.
    Connecting it is what authorizes this broker to apply that credential.
  </Step>
  <Step title="Grant yourself access">
    In the **Access Control** card click **Grant Access** and add your own account. Being on this list is what
    lets you open a brokering session; nothing else grants it.
  </Step>
</Steps>

That is the whole configuration. No proxy identity, no agent identity, and no roles to author.

## 4. Pick where the broker runs

The broker has to sit between your agent and the internet, so where it runs follows from where your agent runs.
Pick the one that matches and follow it to the end; each is a complete walkthrough that continues from here.
