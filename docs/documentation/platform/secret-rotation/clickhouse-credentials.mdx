Rotate the passwords of two ClickHouse users on a schedule, and give your applications the active username and password through Infisical secrets.

<Info>
  **Rotation Type: Dual-Phase**

  This rotation maintains two active credential sets with overlapping validity, ensuring zero-downtime during rotation cycles.
</Info>

<Note>
    This rotation needs a [ClickHouse app connection](/integrations/app-connections/clickhouse). This guide walks you through creating a project-scoped app connection.
</Note>

## Prerequisites

- A [project with secrets configured](/documentation/platform/secrets-mgmt/quick-starts/deliver-first-secret)
- A ClickHouse user that can create users and grant privileges, such as `default`
- Network access from Infisical to the HTTP interface of your ClickHouse server, or a [Gateway](/documentation/platform/gateways/overview) that can reach it

## Step 1: Create a ClickHouse user for Infisical

Infisical needs a ClickHouse user with the `ALTER USER` privilege, which lets it change the passwords of the users it rotates.

<CreateUser />

## Step 2: Create the users to rotate

Your applications sign in to ClickHouse as one of two users that you create.

<TwoUserRotation />

<Steps>
    <Step>
        Create the two users with `CREATE USER`. Infisical replaces both passwords when you create the rotation, so any temporary password works:

        ```sql
        CREATE USER infisical_user_1 IDENTIFIED WITH sha256_password BY 'temporary_password';
        CREATE USER infisical_user_2 IDENTIFIED WITH sha256_password BY 'temporary_password';
        ```

        Infisical can't change the password of a user defined in a ClickHouse configuration file such as `users.xml`.
    </Step>
    <Step>
        Grant both users the privileges your applications need, such as:

        ```sql
        GRANT SELECT ON my_database.* TO infisical_user_1, infisical_user_2;
        ```
    </Step>
</Steps>

<Note>
    If you self-host a ClickHouse cluster that stores users separately on each server, Infisical changes the password only on the server it connects to. To apply the change on every server, store users in [replicated user storage](https://clickhouse.com/docs/operations/server-configuration-parameters/settings#user_directories). ClickHouse Cloud already does this.
</Note>

## Step 3: Set up the rotation in Infisical

<Tip>
    To create the rotation using the API, use the [Create ClickHouse Credentials Rotation](/api-reference/endpoints/secret-rotations/clickhouse-credentials/create) endpoint.
</Tip>

<Steps>
    <Step>
        In your Secrets Manager project, open the dashboard and select **Add Secret Rotation** from the actions dropdown.

        ![Add Secret Rotation](/images/secret-rotations-v2/generic/add-secret-rotation.png)

        Then, select the **ClickHouse Credentials** option.
    </Step>
    <Step>
        Under **Configuration**, choose the app connection and when the rotation runs:

        - **Environment**: The project environment the rotated secrets are stored in
        - **ClickHouse Connection**: The app connection the rotation uses
        - **Rotation Interval (In Days)**: The number of days between rotations
        - **Rotate At (Local Time)**: The time of day the rotation runs
        - **Auto-Rotation Enabled**: When enabled, the passwords rotate on the schedule; turn it off to rotate manually only

        <Tabs>
            <Tab title="Create a new app connection">
                Under **ClickHouse Connection**, select **Create ClickHouse Connection** in the dropdown, then fill in:

                <ConnectionFormFields />

                Select **Connect to Database**. Infisical returns you to the rotation form with the new connection selected.

                <Note>
                    This creates a connection scoped to the current project. To share the connection across other projects, [create it at the organization level](/integrations/app-connections/clickhouse#step-2-create-the-app-connection) first, then select it here.
                </Note>
            </Tab>
            <Tab title="Use an existing connection">
                Under **ClickHouse Connection**, select the app connection you'd like to use.
            </Tab>
        </Tabs>

        Then select **Continue**.
    </Step>
    <Step>
        Under **Parameters**, enter the users you [created in Step 2](#step-2-create-the-users-to-rotate):

        - **Database Username 1**: The first user, such as `infisical_user_1`
        - **Database Username 2**: The second user, such as `infisical_user_2`

        Then select **Continue**.
    </Step>
    <Step>
        Under **Mappings**, choose the names of the Infisical secrets that hold the rotated values:

        - **Username**: The name of the secret that holds the username of the active user
        - **Password**: The name of the secret that holds the password of the active user

        Then select **Continue**.
    </Step>
    <Step>
        Give the rotation a **Name** and an optional **Description**. The name must be slug-friendly.

        Then select **Continue**.
    </Step>
    <Step>
        Review your ClickHouse Credentials Rotation configuration, then select **Create secret rotation**.

        <Check>
            The rotated credentials are now available through the mapped secrets. If auto-rotation is enabled, they rotate on your configured schedule.
        </Check>
    </Step>
</Steps>
