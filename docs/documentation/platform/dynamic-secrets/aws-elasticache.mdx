The AWS ElastiCache dynamic secret creates a user on your [ElastiCache](https://aws.amazon.com/elasticache/) cluster each time someone creates a lease, and deletes the user when the lease ends. Use it to give an application or a person their own short-lived username and password for the cluster, instead of sharing one long-lived password.

To learn how leases work across providers, see [Dynamic secrets](/documentation/platform/dynamic-secrets/overview).

## Prerequisites

- An ElastiCache cluster running Redis OSS 6.0 or later, with encryption in transit turned on and set to **Required**
- A cluster that doesn't already use a user group of your own (see [Cluster access controls](#cluster-access-controls))
- A [role](/documentation/platform/access-controls/role-based-access-controls) in the Infisical project that lets you create dynamic secrets

## Cluster access controls

ElastiCache uses [user groups](https://docs.aws.amazon.com/AmazonElastiCache/latest/dg/Clusters.RBAC.html) to decide who can log in to a cluster. Infisical creates a user group for each cluster, named `infisical-` followed by a hash of the cluster name, and attaches the group to the cluster:

- Each lease adds a user to its own cluster's group, so the lease works only on that cluster
- The cluster refuses clients that connect without a username and password
- A cluster can use only one user group, so Infisical can't use a cluster that already has a user group of your own

## Step 1: Create an IAM user for Infisical

Infisical uses an AWS IAM user to create the cluster's user group and the users for each lease.

<Steps>
  <Step>
    In AWS, create an IAM user with the following policy. Replace `<region>` and `<account-id>` with the region and AWS account ID of your cluster.

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": [
            "elasticache:DescribeUsers",
            "elasticache:ModifyUser",
            "elasticache:CreateUser",
            "elasticache:CreateUserGroup",
            "elasticache:DeleteUser",
            "elasticache:DescribeReplicationGroups",
            "elasticache:DescribeUserGroups",
            "elasticache:ModifyReplicationGroup",
            "elasticache:ModifyUserGroup"
          ],
          "Resource": [
            "arn:aws:elasticache:<region>:<account-id>:user:*",
            "arn:aws:elasticache:<region>:<account-id>:usergroup:*",
            "arn:aws:elasticache:<region>:<account-id>:replicationgroup:*"
          ]
        }
      ]
    }
    ```
  </Step>
  <Step>
    Create an access key for the IAM user, and copy the access key ID and the secret access key.
  </Step>
</Steps>

## Step 2: Create the dynamic secret

<Steps>
  <Step>
    In your project, go to the environment and folder where you want the dynamic secret, then select **Add New** > **Add Dynamic Secret**.
  </Step>
  <Step>
    Select **AWS ElastiCache**.
  </Step>
  <Step>
    Fill in the form:

    <ParamField path="Secret Name" type="string" required>
      The name you use to refer to the dynamic secret.
    </ParamField>

    <ParamField path="Default TTL" type="string" required>
      How long a lease lasts if the person creating it doesn't choose a TTL (for example, `1h`).
    </ParamField>

    <ParamField path="Max TTL" type="string">
      The longest TTL anyone can request for a lease (for example, `24h`).
    </ParamField>

    <ParamField path="Cluster Name" type="string" required>
      The name of the ElastiCache cluster, as shown in the ElastiCache console.
    </ParamField>

    <ParamField path="Region" type="string" required>
      The AWS region of the cluster (for example, `us-east-1`).
    </ParamField>

    <ParamField path="Access Key ID" type="string" required>
      The access key ID of the IAM user from [Step 1](#step-1-create-an-iam-user-for-infisical).
    </ParamField>

    <ParamField path="Secret Access Key" type="string" required>
      The secret access key of the IAM user from [Step 1](#step-1-create-an-iam-user-for-infisical).
    </ParamField>
  </Step>
  <Step>
    (Optional) Expand **Modify ElastiCache Statements** to change how Infisical creates each user:

    <DynamicSecretUsernameTemplateParamField />

    <ParamField path="Creation Statement" type="string">
      The settings Infisical sends to AWS to create each user. To limit what a lease can do on the cluster, change `AccessString` (for example, `on ~app:* +@read` allows read commands on keys that start with `app:`).
    </ParamField>

    <ParamField path="Revocation Statement" type="string">
      The settings Infisical sends to AWS to delete each user.
    </ParamField>
  </Step>
  <Step>
    Select **Submit**.

    Infisical checks that the IAM user can reach the cluster, then creates the cluster's user group. ElastiCache takes up to a minute to finish creating the group.
  </Step>
</Steps>

## Step 3: Create a lease

<Steps>
  <Step>
    In the row for the dynamic secret, select **Generate Lease**.
  </Step>
  <Step>
    Enter a **Default TTL** for the lease, then select **Provision Lease**.
  </Step>
  <Step>
    Copy the `DB_USERNAME` and `DB_PASSWORD` values that Infisical shows.
  </Step>
</Steps>

<Note>
  ElastiCache takes about a minute to add a new user to the cluster. Until then, a login with the new password fails, so make your application retry the connection.
</Note>

## Revoke or renew a lease

Select the dynamic secret to see its leases:

- Select **Revoke lease** to delete the lease's user from the cluster before the lease expires
- Select **Renew lease** to extend the lease, up to the **Max TTL** of the dynamic secret

When a lease expires, Infisical deletes its user from the cluster.

## Clusters set up by earlier versions of Infisical

Earlier versions of Infisical attached one shared user group, `infisical-managed-group-elasticache`, to every cluster. If your cluster still uses that group, Infisical keeps using it for new leases, so your existing leases keep working.

To give the cluster its own user group, with the [cluster access controls](#cluster-access-controls):

<Steps>
  <Step>
    Remove the shared user group from the cluster. Existing leases for the cluster stop working.

    ```bash
    aws elasticache modify-replication-group \
      --replication-group-id <cluster-name> \
      --user-group-ids-to-remove infisical-managed-group-elasticache \
      --apply-immediately
    ```
  </Step>
  <Step>
    Create a lease. Infisical creates the cluster's own user group and asks you to try again in a minute.
  </Step>
  <Step>
    Create the lease again. Infisical attaches the cluster's user group to the cluster.
  </Step>
  <Step>
    Revoke the cluster's old leases, then create new leases for the applications that used them.
  </Step>
</Steps>

When no cluster uses `infisical-managed-group-elasticache` anymore, you can delete the group in the ElastiCache console.

## Troubleshooting

<AccordionGroup>
  <Accordion title="A lease fails with 'ElastiCache is still updating the user group for this cluster'">
    ElastiCache takes about a minute to create a cluster's user group, and about a minute to add each new lease's user. Wait a minute, then create the lease again.
  </Accordion>
  <Accordion title="Creating the dynamic secret fails because the cluster already uses a user group">
    A cluster can use only one user group, and Infisical needs its own group to create leases. Remove your user group from the cluster, or use a different cluster.
  </Accordion>
  <Accordion title="An application can't connect and gets 'NOAUTH Authentication required'">
    The cluster refuses clients that connect without a username and password. Configure the application to log in with the `DB_USERNAME` and `DB_PASSWORD` of a lease.
  </Accordion>
</AccordionGroup>
