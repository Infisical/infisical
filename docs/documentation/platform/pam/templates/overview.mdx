An account template sets the rules for connecting to the [accounts](/documentation/platform/pam/accounts/overview) that use it, such as the maximum session length and whether access needs approval. It also sets which [gateway](/documentation/platform/gateways/overview) the accounts connect through and where Infisical stores their [session recordings](/documentation/platform/pam/sessions/session-recording).

Every account uses one template, and the template's account type must match the account's type. When you change a template, the change applies to every account that uses it.

## Default templates

Infisical creates a template for each account type when your organization first opens PAM. The default templates have no policies turned on, so sessions on their accounts last up to one hour, and Infisical stores the recordings in its internal database.

Windows and Windows AD accounts need recordings stored in AWS S3, so before anyone can launch sessions on them, change the default Windows templates to use [external storage](/documentation/platform/pam/sessions/external-storage).

If an account type has no template, such as a type added after your organization started using PAM, the **Account Templates** page shows a message. Select **Add default templates** in the message to create the missing templates.

## Create a template

Create your own template when some accounts need different rules, such as production databases that need approval before anyone connects.

<Steps>
  <Step>
    Go to **Privileged Access Management** > **Account Templates** and select **Create Template**.
  </Step>
  <Step>
    Enter a **Name**, choose the account **Type**, and optionally enter a **Description**, then select **Create Template**.
  </Step>
  <Step>
    On the template's **General** tab, set the [policies](#policies) and [system settings](#system-settings) that the accounts need.
  </Step>
  <Step>
    Select **Save Changes**.
  </Step>
</Steps>

To use the template, choose it when you [add an account](/documentation/platform/pam/accounts/overview).

## Policies

| Policy | What it does |
| --- | --- |
| **Require Approval** | Users must request access, and an approver must approve the request, before they can launch a session or view the account's credentials (see [Access requests](/documentation/platform/pam/access-requests/overview)) |
| **Allow Auto-Approval** | Requests that pass one of the folder's rules are approved as soon as they're submitted (see [Auto-approval](/documentation/platform/pam/access-requests/auto-approval)) |
| **Allow Break-Glass** | Named responders can approve their own access requests in an emergency (see [Break-glass access](/documentation/platform/pam/access-requests/break-glass)) |
| **Require MFA** | Users must complete an MFA challenge before they connect |
| **Require Reason** | Users must give a reason before they connect |
| **Max Session Duration** | Infisical ends the session after this many seconds (60 to 86,400, or 900 to 3,600 for AWS IAM) |
| **Command Blocking** | Infisical rejects commands or SQL statements that match one of these regular expressions (SSH, Snowflake, and ClickHouse only) |

**Allow Auto-Approval** and **Allow Break-Glass** only work together with **Require Approval**. If you turn off **Require Approval**, Infisical also turns off **Allow Break-Glass**.

Machine identities and [AI agents](/documentation/platform/pam/ai-agents/overview) can't complete an MFA challenge, so they can't connect to accounts whose template has **Require MFA** on. If an agent needs an account, use **Require Approval** instead.

## System settings

| Setting | What it does |
| --- | --- |
| **Gateway** | The gateway that the accounts connect through |
| **Storage backend** | Where Infisical stores session recordings: **Internal Database** or **S3 Bucket** (see [External storage](/documentation/platform/pam/sessions/external-storage)) |
| **Session Log Masking** | Hides text that matches these patterns in session recordings |

<Note>
You can [override the gateway](/documentation/platform/pam/accounts/manage#override-the-template’s-settings) for one account on the account's **Advanced** tab. For Windows and Windows AD accounts, you can also override the recording bucket there.
</Note>

The **General** tab also has settings for [credential rotation](/documentation/platform/pam/credential-rotation/overview) and [credential health](/documentation/platform/pam/credential-health/overview) checks, for account types that support them.
