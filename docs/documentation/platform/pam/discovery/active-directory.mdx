Active Directory discovery finds the users in an Active Directory domain, and optionally the local accounts on its Windows servers, so you can import them into PAM. For how discovery works across every source type, see [Discovery](/documentation/platform/pam/discovery/overview).

A scan finds two types of account:

| Account type | What the scan finds | When |
|--------------|---------------------|------|
| [Windows AD](/documentation/platform/pam/accounts/windows-ad) | The domain's user accounts | Every scan |
| [Windows](/documentation/platform/pam/accounts/windows) | The local accounts on the domain's Windows servers | If **Discover local accounts** is on |

The scan can also find the [dependencies](/documentation/platform/pam/credential-rotation/windows#dependencies) of the accounts it finds, which are the services, scheduled tasks, and IIS application pools that run as them.

Infisical connects to the domain controller and the servers through a [Gateway](/documentation/platform/gateways/overview), signed in as a Windows AD account that you choose for the source.

<Accordion title="How a scan works">
  1. Infisical connects to the domain controller over LDAP or LDAPS, using the connection settings of the source's Windows AD account, and lists the domain's users
  2. If **Discover local accounts** or **Discover account dependencies** is on, Infisical also lists the domain's Windows servers, and resolves each server's hostname through the domain controller's DNS
  3. Infisical connects to each server over WinRM to list its local accounts, the dependencies of the accounts it found, or both

  If Infisical can't reach a server over WinRM, the scan reports the server and continues with the others.
</Accordion>

## Prerequisites

- A [Gateway](/documentation/platform/gateways/overview) that can reach your domain controller, and your Windows servers if you turn on **Discover local accounts** or **Discover account dependencies**
- A [Windows AD account](/documentation/platform/pam/accounts/windows-ad) with a password, to sign in to the domain with
- The [Product Admin role](/documentation/platform/pam/concepts/access-control#product-membership) in PAM
- The Connector, Operator, or Admin [role](/documentation/platform/pam/concepts/access-control#folder-and-account-memberships) on that Windows AD account

To find local accounts or dependencies, you also need:

- WinRM turned on for your Windows servers
- A domain controller whose DNS resolves each server's hostname

## Step 1: Create a source

<Steps>
  <Step>
    Go to **Privileged Access Management** > **Discovery** and select **Add Source**.
  </Step>
  <Step>
    Select **Active Directory**, then select **Next**.
  </Step>
  <Step>
    Configure the source:

    | Field | Description |
    |-------|-------------|
    | **Name** | A name for the source, such as `corp-active-directory` |
    | **Credential Account** | The Windows AD account to sign in to the domain with |
    | **Gateway** | The Gateway or Gateway pool to connect through |
    | **Scan Schedule** | **Manual**, **Daily**, or **Weekly** (see [scan schedules](/documentation/platform/pam/discovery/overview#scan-schedules)) |
    | **Discover local accounts** | Find the local accounts on the domain's Windows servers (on by default) |
    | **Discover account dependencies** | Find the services, scheduled tasks, and IIS application pools that run as the accounts the scan finds (off by default) |

    Infisical connects to the domain controller with the domain, address, ports, and LDAPS settings of the Windows AD account.
  </Step>
  <Step>
    If you turned on **Discover local accounts** or **Discover account dependencies**, configure how Infisical connects to your servers over WinRM:

    | Field | Description |
    |-------|-------------|
    | **WinRM Port** | The WinRM port on each server (default `5985`) |
    | **Use HTTPS** | Connect to WinRM over HTTPS |
    | **Reject Unauthorized** | Check each server's TLS certificate (HTTPS only) |
    | **CA Certificate** | The PEM certificate of the private CA that issued the servers' WinRM certificates, if any |
  </Step>
  <Step>
    Select **Add Source**.
  </Step>
</Steps>

## Step 2: Run a scan

On the **Discovery Sources** table, select the options menu on the source's row, then select **Scan Now**. A source can run one scan at a time.

## Step 3: Import accounts

<Steps>
  <Step>
    On the **Discovery Sources** table, select the source.
  </Step>
  <Step>
    On the **Staged Accounts** tab, select the accounts you want, then select **Import Accounts**.
  </Step>
  <Step>
    Select a **Destination Folder**, then a template for each account type in your selection (**Windows AD Template**, **Windows Template**, or both), and select **Import**.
  </Step>
  <Step>
    Go to **Privileged Access Management** > **Accounts**. For each imported account, open the options menu on its row, select **Configure**, and enter its password on the **Configuration** tab. The scan doesn't read passwords, so you can't connect to an imported account until you enter its password.
  </Step>
</Steps>

<Check>
  Your Active Directory accounts are in PAM. Anyone with access to the destination folder can launch sessions on them, and each scan of the source stages any new accounts it finds.
</Check>
