PostgreSQL discovery finds the roles that can sign in to your PostgreSQL instances, so you can import them into PAM as [PostgreSQL accounts](/documentation/platform/pam/accounts/postgresql). For how discovery works across every source type, see [Discovery](/documentation/platform/pam/discovery/overview).

You give the source a list of instances and one or more PostgreSQL accounts to sign in with. Infisical connects to each instance through a [Gateway](/documentation/platform/gateways/overview).

<Accordion title="How a scan works">
  1. Infisical checks that each instance is reachable on the ports of the source's PostgreSQL accounts, and skips the instances it can't reach
  2. For each instance, Infisical first tries the account whose host matches the instance, then tries the other accounts until one signs in
  3. Infisical lists the roles on the instance that can sign in, and stages each one as a PostgreSQL account for that instance

  If two instances each have a role named `postgres`, Infisical stages two separate accounts. If no account can sign in to an instance, the scan reports the instance and continues with the others.
</Accordion>

## Prerequisites

- A [Gateway](/documentation/platform/gateways/overview) that can reach the instances you want to scan
- One or more [PostgreSQL accounts](/documentation/platform/pam/accounts/postgresql) that authenticate with a password, to sign in to the instances with
- The [Product Admin role](/documentation/platform/pam/concepts/access-control#product-membership) in PAM
- The Operator or Admin [role](/documentation/platform/pam/concepts/access-control#folder-and-account-memberships) on those PostgreSQL accounts, because the scan sends their passwords to every instance

The PostgreSQL role that the scan signs in as only needs permission to sign in to the instance. It doesn't need to be a superuser.

A PostgreSQL account that uses AWS IAM authentication can't scan, because its sign-in token works for only one host, port, and user.

<Warning>
  Infisical sends the PostgreSQL account's password to every instance that the source scans, so only list instances you trust.
</Warning>

## Step 1: Create a source

<Steps>
  <Step>
    Go to **Privileged Access Management** > **Discovery** and select **Add Source**.
  </Step>
  <Step>
    Select **PostgreSQL**, then select **Next**.

    <Frame>
      <img src="/images/platform/pam/postgres-discovery-select-source.png" alt="Add Discovery Source panel with PostgreSQL selected" />
    </Frame>
  </Step>
  <Step>
    Configure the source:

    | Field | Description |
    |-------|-------------|
    | **Name** | A name for the source, such as `prod-databases` |
    | **Credential Accounts** | The PostgreSQL accounts to sign in to the instances with |
    | **Gateway** | The Gateway or Gateway pool to connect through |
    | **Scan Schedule** | **Manual**, **Daily**, or **Weekly** (see [scan schedules](/documentation/platform/pam/discovery/overview#scan-schedules)) |
    | **Targets** | The IP addresses or hostnames of the instances to scan, one per line or separated by commas (the Gateway resolves hostnames) |

    Infisical connects to each instance with the port, database, and TLS settings of the PostgreSQL account it signs in with.

    <Frame>
      <img src="/images/platform/pam/postgres-discovery-configure-source.png" alt="PostgreSQL discovery source configuration with name, credential accounts, gateway, scan schedule, and targets fields" />
    </Frame>
  </Step>
  <Step>
    Select **Add Source**.
  </Step>
</Steps>

## Step 2: Run a scan

On the **Discovery Sources** table, select the options menu on the source's row, then select **Scan Now**. A source can run one scan at a time.

<Frame>
  <img src="/images/platform/pam/postgres-discovery-scan-now.png" alt="PostgreSQL discovery source row menu showing Scan Now" />
</Frame>

The scan stages only roles that can sign in. Roles are shared across all databases on an instance, so the database that the PostgreSQL account connects to doesn't change which roles the scan finds.

## Step 3: Import accounts

<Steps>
  <Step>
    On the **Discovery Sources** table, select the source.
  </Step>
  <Step>
    On the **Staged Accounts** tab, select the accounts you want, then select **Import Accounts**.

    <Frame>
      <img src="/images/platform/pam/postgres-discovery-staged-accounts.png" alt="Staged Accounts tab with four PostgreSQL accounts selected and the Import Accounts button" />
    </Frame>
  </Step>
  <Step>
    Select a **Destination Folder** and a **PostgreSQL Template**, then select **Import**.

    <Frame>
      <img src="/images/platform/pam/postgres-discovery-import-accounts.png" alt="Import 4 Accounts dialog with Production as the destination folder and PostgreSQL Standard as the template" />
    </Frame>
  </Step>
  <Step>
    Go to **Privileged Access Management** > **Accounts**. For each imported account, open the options menu on its row, select **Configure**, and enter the password for its PostgreSQL role on the **Configuration** tab. The scan doesn't read passwords, so you can't connect to an imported account until you enter its password.
  </Step>
</Steps>

<Check>
  Your PostgreSQL roles are in PAM. Anyone with access to the destination folder can launch sessions on them, and each scan of the source stages any new roles it finds.
</Check>
