An AWS IAM account lets people work in AWS as an IAM role without holding long-lived access keys. When someone launches a session, Infisical assumes the role through AWS STS and gives them temporary credentials. They can open the AWS Management Console in the browser or use the credentials with the AWS CLI.

AWS IAM accounts don't use a [Gateway](/documentation/platform/gateways/overview), because Infisical calls AWS STS directly.

## Prerequisites

- The Admin [role](/documentation/platform/pam/concepts/access-control) on the [folder](/documentation/platform/pam/folders/overview) you'll add the account to
- Permission to create IAM roles in the AWS account
- Your Infisical organization ID, which you can copy from **Organization ID** in your organization's settings

## Create an IAM role

Each account assumes one IAM role. The role's trust policy lets Infisical assume the role only when Infisical sends your organization ID as the [external ID](https://docs.aws.amazon.com/IAM/latest/UserGuide/confused-deputy.html), so no other Infisical customer can get Infisical to assume it.

<Steps>
  <Step>
    In AWS, create an IAM role, such as `infisical-pam-readonly`, with the following trust policy:

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [{
        "Effect": "Allow",
        "Principal": {
          "AWS": "arn:aws:iam::<infisical-aws-account-id>:root"
        },
        "Action": "sts:AssumeRole",
        "Condition": {
          "StringEquals": {
            "sts:ExternalId": "<your-infisical-organization-id>"
          }
        }
      }]
    }
    ```

    Replace `<infisical-aws-account-id>` with the AWS account that Infisical runs in:

    | Infisical instance | AWS account ID |
    |--------------------|----------------|
    | Infisical Cloud (US) | `381492033652` |
    | Infisical Cloud (EU) | `345594589636` |
    | Dedicated instance | Ask Infisical support for your instance's account ID |
    | Self-hosted | The AWS account your Infisical instance runs in |
  </Step>
  <Step>
    Attach permission policies to the role. People who access the account get exactly these permissions in AWS.
  </Step>
  <Step>
    Set the role's **Maximum session duration** to cover the longest session you'll allow, as described in [Session duration](#session-duration).
  </Step>
</Steps>

## Create an account

<Steps>
  <Step>
    Go to **Privileged Access Management** > **Accounts** and select **Add Account**.
  </Step>
  <Step>
    Select the **Folder** to add the account to and an AWS IAM **Account Template**, such as the default `aws-iam` [template](/documentation/platform/pam/templates/overview), then select **Next**.
  </Step>
  <Step>
    Enter a **Name** for the account and the **Role ARN** of the role you created, such as `arn:aws:iam::123456789012:role/infisical-pam-readonly`.
  </Step>
  <Step>
    Select **Create**.
  </Step>
</Steps>

To offer the same role in more than one folder, create an account with the same **Role ARN** in each folder.

## Session duration

A session lasts for the template's maximum session duration, unless the person requests a shorter one. AWS rejects a session that's shorter than 15 minutes or longer than the role's maximum session duration, so make sure both limits allow the sessions you expect.

<Warning>
  You can't end an AWS Management Console session early. Terminating the session in Infisical doesn't sign the person out of the console, which stays signed in until the session expires. To cut off access sooner, [revoke the role's active sessions](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_use_revoke-sessions.html) in AWS.
</Warning>

## Connect

To learn how to launch a session, see [Connect to an account](/documentation/platform/pam/accounts/connect). In the browser, the session opens the AWS Management Console, signed in as the role.

The CLI writes temporary credentials to `~/.aws/credentials` as a profile named `infisical-pam/<folder>/<account>`:

```bash
infisical pam access <folder>/<account>
```

Pass the profile to the AWS CLI, or set `AWS_PROFILE` to use it for every command:

```bash
export AWS_PROFILE="infisical-pam/<folder>/<account>"
aws sts get-caller-identity
```

Press `Ctrl+C` to end the session. The CLI then removes the profile.

## Track activity in AWS

Infisical names each STS session after the email of the person who launched it, or after the name of the [machine identity](/documentation/platform/identities/machine-identities). In [AWS CloudTrail](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/cloudtrail-user-guide.html), the session name shows who made each call.
