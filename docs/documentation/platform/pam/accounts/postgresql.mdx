A PostgreSQL [account](/documentation/platform/pam/accounts/overview) stores the credentials for one PostgreSQL database user. Members connect to the database in the browser or through the Infisical CLI, and Infisical records every query they run.

The account can sign in with a password, or with [AWS IAM authentication](#aws-iam-authentication) if the database runs on Amazon RDS or Aurora.

## Prerequisites

- The Admin [role](/documentation/platform/pam/concepts/access-control) on the [folder](/documentation/platform/pam/folders/overview) you'll add the account to
- A [gateway](/documentation/platform/gateways/overview) that can reach the database
- A PostgreSQL [account template](/documentation/platform/pam/templates/overview)

## Create the account

<Steps>
  <Step>
    Go to **Privileged Access Management** > **Accounts** and select **Add Account**.
  </Step>
  <Step>
    Select the **Folder** and a PostgreSQL **Account Template**, then select **Next**.
  </Step>
  <Step>
    Enter a **Name** and the connection details:

    | Field | Description |
    | --- | --- |
    | **Host** | The database's hostname or IP address |
    | **Port** | The database's port (defaults to `5432`) |
    | **Database** | The database that sessions connect to |
    | **SSL Enabled** | Whether to connect over TLS |
    | **Reject Unauthorized** | Whether to reject a server certificate that can't be verified (shown when **SSL Enabled** is on) |
    | **SSL Certificate** | The CA certificate that signed the server's certificate (shown when **SSL Enabled** is on) |

    If you have a connection string, such as `postgresql://user:password@host:5432/database`, paste it into **Host**. Infisical fills in the other fields from the connection string, including the credentials.
  </Step>
  <Step>
    Select the **Auth Method** and enter the credentials:

    <Tabs>
      <Tab title="Password">
        | Field | Description |
        | --- | --- |
        | **Username** | The PostgreSQL user |
        | **Password** | The user's password |
      </Tab>
      <Tab title="AWS IAM (RDS / Aurora)">
        Set up [AWS IAM authentication](#aws-iam-authentication) first.

        | Field | Description |
        | --- | --- |
        | **Username** | The database user that has the `rds_iam` role |
        | **AWS Region** | The region of the RDS instance or Aurora cluster, such as `us-east-1` |
        | **Role ARN** | The IAM role that Infisical assumes to generate an authentication token |
      </Tab>
    </Tabs>
  </Step>
  <Step>
    Select **Create**.
  </Step>
</Steps>

## AWS IAM authentication

With AWS IAM authentication, Infisical doesn't store a password for the database user. Instead, Infisical assumes an IAM role in your AWS account and uses it to generate a short-lived authentication token for each connection.

Set up the database and the IAM role before you create the account:

<Steps>
  <Step>
    In the RDS console, turn on **IAM database authentication** for the RDS instance or Aurora cluster.
  </Step>
  <Step>
    Create the database user and grant it the `rds_iam` role:

    ```sql
    CREATE USER app_user WITH LOGIN;
    GRANT rds_iam TO app_user;
    ```
  </Step>
  <Step>
    Create an IAM role with the following trust policy:

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [{
        "Effect": "Allow",
        "Principal": { "AWS": "arn:aws:iam::<INFISICAL_AWS_ACCOUNT_ID>:root" },
        "Action": "sts:AssumeRole",
        "Condition": {
          "StringEquals": { "sts:ExternalId": "<YOUR_INFISICAL_ORG_ID>" }
        }
      }]
    }
    ```

    Replace the placeholders:

    - `<INFISICAL_AWS_ACCOUNT_ID>`: `381492033652` for Infisical Cloud (US), `345594589636` for Infisical Cloud (EU), or the ID of the AWS account that runs your instance if you self-host Infisical
    - `<YOUR_INFISICAL_ORG_ID>`: your organization ID, which the tooltip on the **Role ARN** field shows

    The `sts:ExternalId` condition stops other Infisical organizations from using your role, so don't remove it.
  </Step>
  <Step>
    Attach a policy to the role that lets it connect as the database user:

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [{
        "Effect": "Allow",
        "Action": "rds-db:connect",
        "Resource": "arn:aws:rds-db:<REGION>:<AWS_ACCOUNT_ID>:dbuser:<DB_RESOURCE_ID>/app_user"
      }]
    }
    ```

    `<DB_RESOURCE_ID>` is the instance's resource ID, which starts with `db-`, not the instance's name. The RDS console shows the resource ID on the instance's **Configuration** tab.
  </Step>
</Steps>

When you create the account, set the following fields:

- **Host**: the endpoint of the RDS instance or Aurora cluster, not a CNAME or other alias, because AWS signs each token for that exact endpoint
- **SSL Enabled**: always on, because IAM authentication requires TLS
- **SSL Certificate**: to verify the server, turn on **Reject Unauthorized** and paste the RDS certificate bundle for your region, such as `https://truststore.pki.rds.amazonaws.com/us-east-1/us-east-1-bundle.pem`

Accounts that use AWS IAM have no stored password, so [credential rotation](/documentation/platform/pam/credential-rotation/overview) doesn't apply to them.

If a session fails with `PAM authentication failed for user`, AWS rejected the token. Check that the `rds-db:connect` resource ARN uses the instance's current resource ID, the right region, and the same database user as the account.

## Connect

To open a session, follow [Connect to an account](/documentation/platform/pam/accounts/connect).

<Tabs>
  <Tab title="Browser">
    The browser session has a table browser, where you can view, filter, edit, and export rows, and a SQL editor for running queries.
  </Tab>
  <Tab title="CLI">
    Start the local proxy:

    ```bash
    infisical pam access backend-team/orders-db
    ```

    The proxy keeps running in that terminal and prints its port. In a second terminal, connect your PostgreSQL client to that port:

    ```bash
    psql "postgresql://localhost:<port>/orders"
    ```

    The proxy signs in for you, so `psql` doesn't need a password.
  </Tab>
</Tabs>
