An account is one set of credentials for a database, server, cluster, or cloud provider, along with the details Infisical needs to reach it. People and [AI agents](/documentation/platform/pam/ai-agents/overview) connect to an account through Infisical. A [gateway](/documentation/platform/gateways/overview) supplies the credential, so whoever connects never sees it.

Each account belongs to one [folder](/documentation/platform/pam/folders/overview), which sets who can use the account. Each account also uses one [account template](/documentation/platform/pam/templates/overview), which sets the account type and the rules for its sessions.

## Account types

Each account type has its own page that describes the connection details, the credentials, and how to connect.

| Account type | Connects to | Web access |
| --- | --- | --- |
| [PostgreSQL](/documentation/platform/pam/accounts/postgresql) | PostgreSQL databases | Yes |
| [MySQL](/documentation/platform/pam/accounts/mysql) | MySQL databases | Yes |
| [Microsoft SQL Server](/documentation/platform/pam/accounts/mssql) | Microsoft SQL Server databases | No |
| [Oracle](/documentation/platform/pam/accounts/oracledb) | Oracle databases | No |
| [MongoDB](/documentation/platform/pam/accounts/mongodb) | MongoDB databases | No |
| [Redis](/documentation/platform/pam/accounts/redis) | Redis databases | Yes |
| [Snowflake](/documentation/platform/pam/accounts/snowflake) | Snowflake accounts | Yes |
| [ClickHouse](/documentation/platform/pam/accounts/clickhouse) | ClickHouse databases | Yes |
| [SSH](/documentation/platform/pam/accounts/ssh) | Linux and Unix servers | Yes |
| [Kubernetes](/documentation/platform/pam/accounts/kubernetes) | Kubernetes clusters | No |
| [AWS IAM](/documentation/platform/pam/accounts/aws-iam) | AWS accounts, through an IAM role | Yes |
| [GCP service account](/documentation/platform/pam/accounts/gcp-service-account) | GCP service accounts | No |
| [Azure CLI](/documentation/platform/pam/accounts/azure-cli) | Azure, through a service principal | No |
| [Windows](/documentation/platform/pam/accounts/windows) | Windows servers, over RDP | Yes |
| [Windows AD](/documentation/platform/pam/accounts/windows-ad) | Windows servers, through Active Directory | Yes |

You can [connect](#connect-to-an-account) to every account type with the Infisical CLI. Account types with web access also open in the browser.

## Add an account

### Prerequisites

- The Admin [role](/documentation/platform/pam/concepts/access-control) on the folder that the account goes in
- An [account template](/documentation/platform/pam/templates/overview) for the account type
- A [gateway](/documentation/platform/gateways/overview) that can reach the database or server (AWS IAM accounts don't need one)

### Steps

<Steps>
  <Step>
    Go to **Privileged Access Management** > **Accounts** and select **Add Account**.
  </Step>
  <Step>
    Select the **Folder** and the **Account Template**, then select **Next**. The template sets the account type.
  </Step>
  <Step>
    Enter a **Name** and the connection details. If the template doesn't set a gateway, select a **Gateway**.

    The page for each [account type](#account-types) describes its fields.
  </Step>
  <Step>
    Enter the credentials, then select **Create**.
  </Step>
</Steps>

## Grant access to one account

A role on a folder applies to every account in the folder. To give a user, group, or machine identity access to one account only, assign them a role on the account:

<Steps>
  <Step>
    Open the account and go to the **Permissions** tab.
  </Step>
  <Step>
    Select **Assign Access**.
  </Step>
  <Step>
    Select the **Assignee** and the **Role**. To make the access temporary, select an **Expiry**.
  </Step>
  <Step>
    Select **Assign**.
  </Step>
</Steps>

To learn what each role allows, see [Access control](/documentation/platform/pam/concepts/access-control).

## Connect to an account

You can connect to an account in your browser or with the Infisical CLI. Either way, Infisical opens a [session](/documentation/platform/pam/sessions/overview), and a [gateway](/documentation/platform/gateways/overview) supplies the account's credential so that you never see it. Infisical records everything you do in the session.

<Tip>
To give an AI agent access to accounts, use [`infisical pam agentic access`](/documentation/platform/pam/ai-agents/overview) instead.
</Tip>

### Prerequisites

- The Admin, Operator, or Connector [role](/documentation/platform/pam/concepts/access-control) on the account or its folder
- An approved [access request](/documentation/platform/pam/access-requests/overview), if the account's template requires approval
- To connect with the CLI, the [Infisical CLI](/cli/overview) installed and logged in with [`infisical login`](/cli/reference#login)

### Launch a session

<Steps>
  <Step>
    Go to **Privileged Access Management** > **Accounts** and find the account.
  </Step>
  <Step>
    Select the rocket icon on the account's row.

    If the row shows a key icon instead, the account requires approval. Select the key icon to [request access](/documentation/platform/pam/access-requests/overview), and launch the session once an approver approves the request.
  </Step>
  <Step>
    Select a launch method, then connect:

    <Tabs>
      <Tab title="Browser">
        Select **Browser**, then select **Connect in Browser**. The session opens in a new tab.

        What the tab shows depends on the account type:

        - **PostgreSQL, MySQL, Snowflake, and ClickHouse**: a table browser and a SQL editor
        - **Redis**: a console for Redis commands
        - **SSH**: a terminal
        - **Windows and Windows AD**: a remote desktop
        - **AWS IAM**: the AWS Management Console

        <Note>
        Only some [account types](#account-types) support the browser.
        </Note>
      </Tab>
      <Tab title="CLI">
        Select **CLI**, then copy the command and run it in your terminal. The command has this form:

        ```bash
        infisical pam access <folder>/<account>
        ```

        What happens next depends on the account type:

        - **SSH**: The CLI opens a shell on the server (add `--proxy` to use your own SSH client instead)
        - **AWS IAM**: The CLI writes temporary credentials to your AWS credentials file
        - **Every other account type**: The CLI starts a local proxy on `127.0.0.1` and prints its port

        If the CLI starts a proxy, connect your own client, such as `psql` or `kubectl`, to the printed port. The proxy signs in for you, so the client doesn't need a password.

        The session lasts one hour unless you set `--duration`. For the other flags, see the [CLI reference](/cli/reference#pam-access).
      </Tab>
    </Tabs>
  </Step>
</Steps>

If the account's template requires a reason, Infisical asks for one before the session starts. If the template requires MFA, Infisical asks you to complete MFA in your browser.

### End a session

A session ends when:

- You close the browser tab, or press `Ctrl+C` in the terminal that runs the CLI
- The session reaches the maximum duration set by the account's [template](/documentation/platform/pam/templates/overview)
- Someone with the Admin role on the account or its folder [terminates the session](/documentation/platform/pam/sessions/overview)

## View credentials

Some tasks need the credential itself instead of a [session](#connect-to-an-account), such as signing in with a desktop client that Infisical can't connect through, or configuring an appliance by hand. For these tasks, you can reveal the password or key stored for an account.

<Warning>
  Once you reveal a credential, Infisical can't control how it's used. Infisical doesn't record what you do with the credential or block any commands, and revoking your access doesn't invalidate a copy of it. Use a session when you can, and [rotate the credential](/documentation/platform/pam/credential-rotation/overview) after someone reveals it.
</Warning>

### Prerequisites

- The Admin or Operator [role](/documentation/platform/pam/concepts/access-control) on the account or its folder
- An approved credential request, if the account's template requires approval (see [Request access to the credential](#request-access-to-the-credential))

### Reveal the credential

<Steps>
  <Step>
    Go to **Privileged Access Management** > **Accounts**, then open the options menu on the account's row and select **View Credentials**.
  </Step>
  <Step>
    Enter a **Reason** and select **Reveal**. If the account's template requires MFA, complete MFA in the window that opens.
  </Step>
  <Step>
    To show a masked value, select the eye icon next to it.
  </Step>
</Steps>

If an account's auth method doesn't store a password or key, such as an SSH certificate or AWS IAM, the account has no **View Credentials** option.

### Request access to the credential

If the account's template requires approval, the options menu shows **Request Credentials** instead of **View Credentials**. Select **Request Credentials** to file a request, and reveal the credential after an approver approves it. To learn how requests are reviewed, see [Access requests](/documentation/platform/pam/access-requests/overview).

Infisical approves credential requests and session requests separately. An approved session request doesn't let you reveal the credential, and an approved credential request doesn't let you launch a session.

### Audit log entries

Each time someone reveals a credential, Infisical adds a **View PAM Account Credentials** event to the [audit log](/documentation/platform/pam/auditing). The event names the member, the account, and the reason they gave.
