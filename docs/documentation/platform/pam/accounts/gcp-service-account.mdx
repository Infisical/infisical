A GCP service account lets people use `gcloud` as a service account without handing out a service account key. When someone launches a session, Infisical gets a short-lived access token for the service account. Their Google Cloud requests go through a [Gateway](/documentation/platform/gateways/overview), which adds the token to each request, and Infisical records each request's method, URL, and response status.

GCP service accounts only support the CLI, not browser access.

## Prerequisites

- The Admin [role](/documentation/platform/pam/concepts/access-control) on the [folder](/documentation/platform/pam/folders/overview) you'll add the account to
- A Gateway that can reach `googleapis.com` on port `443`
- The [`gcloud` CLI](https://cloud.google.com/sdk/docs/install) on the machine of each person who connects

## Choose an authentication method

The account gets tokens for the target service account in one of two ways:

- **Impersonation (Recommended)**: Infisical [impersonates](https://cloud.google.com/iam/docs/service-account-impersonation) the target service account with its own Google Cloud service account, so no key is created or stored
- **Static Key**: Infisical stores a service account key, either for the target service account or for another service account that's allowed to impersonate it

### Set up impersonation

<Steps>
  <Step>
    In the Google Cloud project of the target service account, enable the IAM Service Account Credentials API (`iamcredentials.googleapis.com`). Without this API, sessions fail when Infisical requests a token.
  </Step>
  <Step>
    Find the service account that Infisical impersonates with:

    | Infisical instance | Infisical's service account |
    |--------------------|-----------------------------|
    | Infisical Cloud (US) | `infisical-us@infisical-us.iam.gserviceaccount.com` |
    | Infisical Cloud (EU) | `infisical-eu@infisical-eu.iam.gserviceaccount.com` |
    | Self-hosted | The service account in your instance's `INF_APP_CONNECTION_GCP_SERVICE_ACCOUNT_CREDENTIAL` environment variable |

    If you self-host Infisical and haven't set that variable, follow the self-hosted steps in [GCP connection](/integrations/app-connections/gcp) first.
  </Step>
  <Step>
    In the Google Cloud console, go to **IAM & Admin** > **Service Accounts** and select the target service account.
  </Step>
  <Step>
    On the **Permissions** tab, select **Grant access**. Add Infisical's service account as a principal with the **Service Account Token Creator** role (`roles/iam.serviceAccountTokenCreator`).
  </Step>
</Steps>

### Set up a static key

<Steps>
  <Step>
    In the Google Cloud console, go to **IAM & Admin** > **Service Accounts** and select the service account whose key you'll store.
  </Step>
  <Step>
    On the **Keys** tab, select **Add key** > **Create new key**, choose **JSON**, and select **Create**. The key file downloads to your machine.
  </Step>
</Steps>

## Create an account

<Steps>
  <Step>
    Go to **Privileged Access Management** > **Accounts** and select **Add Account**.
  </Step>
  <Step>
    Select the **Folder** to add the account to. Under **Account Template**, select a GCP service account [template](/documentation/platform/pam/templates/overview), such as the default `gcp-service-account` template, then select **Next**.
  </Step>
  <Step>
    Enter a **Name** for the account and the **Service Account Email** of the target service account, which ends in `.iam.gserviceaccount.com`. If the template doesn't set a Gateway, select one under **Gateway**.
  </Step>
  <Step>
    Select the **Auth Method** you set up. For **Static Key**, paste the contents of the key file into **Service Account Key JSON**.
  </Step>
  <Step>
    Select **Create**.
  </Step>
</Steps>

## Connect

To learn how to launch a session, see [Connect to an account](/documentation/platform/pam/accounts/connect). The CLI command for the account is:

```bash
infisical pam access <folder>/<account>
```

The CLI points `gcloud` at a local proxy for the session, so `gcloud` works without any other setup:

```bash
gcloud compute instances list
```

Press `Ctrl+C` to end the session. The CLI then restores your `gcloud` configuration.
