By default, Infisical stores [session recordings](/documentation/platform/pam/sessions/session-recording) in its own database. If you need to control where recordings are kept and for how long, such as for data residency or compliance, store them in your own Amazon S3 bucket instead.

Windows and Windows AD accounts require an S3 bucket. Until their [template](/documentation/platform/pam/templates/overview) uses one, you can create these accounts but can't launch sessions on them.

## Prerequisites

- An S3 bucket
- An [AWS connection](/integrations/app-connections/aws) whose credentials have the [permissions on the bucket](#bucket-permissions)
- The **Product Admin** [role](/documentation/platform/pam/concepts/access-control) in PAM, to edit templates

## Step 1: Prepare the bucket

### Bucket permissions

Give the AWS connection's credentials these permissions, replacing `<bucket-name>` with the name of your bucket:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::<bucket-name>/*"
    },
    {
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::<bucket-name>"
    }
  ]
}
```

When you save a template, Infisical writes a test object to the bucket and then deletes it, to check that it can store recordings there.

### CORS policy

Your browser downloads recordings directly from the bucket when you view a session, so the bucket needs a CORS policy that allows requests from Infisical:

```json
[
  {
    "AllowedHeaders": ["*"],
    "AllowedMethods": ["GET"],
    "AllowedOrigins": ["https://app.infisical.com"],
    "MaxAgeSeconds": 3600
  }
]
```

If you use a different Infisical URL, such as `https://eu.infisical.com` or your own domain, replace `https://app.infisical.com` with that URL.

To add the policy in the AWS console, open the bucket, go to **Permissions** > **Cross-origin resource sharing (CORS)**, select **Edit**, and paste the policy.

## Step 2: Configure the template

Each template sets the storage for every account that uses it, so you can use different buckets for different templates.

<Steps>
  <Step>
    Go to **Privileged Access Management** > **Account Templates** and select the template.
  </Step>
  <Step>
    On the **General** tab, under **Session Recording**, set **Storage backend** to **AWS S3**.
  </Step>
  <Step>
    Fill in the bucket details:

    - **AWS Connection**: The AWS connection with access to the bucket
    - **S3 Bucket**: The name of the bucket
    - **Region**: The bucket's AWS region, such as `us-east-1`
    - **Key prefix (optional)**: A folder in the bucket to store recordings in, such as `pam-recordings/`
  </Step>
  <Step>
    Select **Save Changes**.
  </Step>
</Steps>

If Infisical can't reach the bucket, the template isn't saved and the error message says which permission is missing. If the bucket has no CORS policy that allows your Infisical URL, Infisical saves the template and shows a **Bucket CORS not configured** warning.

<Warning>
  If you change the bucket or key prefix on a template, you can no longer view the recordings already stored in the old location. To keep them viewable, move the objects to the new location yourself.
</Warning>

### Use a different bucket for one account

To store one account's recordings somewhere other than its template's bucket, open the account, go to the **Advanced** tab, and select **Override** under **Recording Settings**.

## Managing retention

Infisical never deletes recordings from your bucket, so you decide how long to keep them. To delete or archive recordings after a set time, add an [S3 lifecycle rule](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lifecycle-mgmt.html) to the bucket.

Infisical stores each session's recording under its own path in the bucket:

```text
<key-prefix>/<project-id>/<session-id>/
```

Once a lifecycle rule deletes a session's objects, you can't view that session's recording in Infisical.

The objects in the bucket are already encrypted when they arrive, because the [Gateway](/documentation/platform/gateways/overview) encrypts each part of the recording before it uploads it. You can also turn on S3 server-side encryption on the bucket.
