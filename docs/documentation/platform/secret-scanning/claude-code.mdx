To stop your developers from sending secrets to Claude Code, create a Claude Code [data source](/documentation/platform/secret-scanning/scan-repositories) in Infisical, and install the Infisical plugin in Claude Code.

The plugin scans each prompt on the developer's machine before Claude Code sends it. If the prompt contains a new secret, the plugin records the secret in Infisical as a [finding](/documentation/platform/secret-scanning/findings). By default, the plugin also blocks the prompt. After a reviewer marks the finding as **False Positive** or **Ignore**, the prompt can go through. If you only want to monitor, you can set the data source to report secrets and let the prompts continue.

<Info>
  Secret Scanning data sources are available under Infisical's [Enterprise](https://infisical.com/pricing) plan. If you're self-hosting Infisical, contact sales@infisical.com to purchase an enterprise license.
</Info>

## How it works

1. A developer submits a prompt in Claude Code.
2. The plugin scans the prompt on the developer's machine with `infisical scan --pipe`. If the scan finds no secret, the prompt goes through, and the plugin doesn't call Infisical.
3. If the scan finds secrets, the plugin sends only the secret values, and the IDs of the rules that found them, to Infisical. The plugin doesn't send the prompt in this step.
4. Infisical calculates a [blind index](#how-infisical-matches-secrets) of each secret value, and finds the newest finding with that blind index in the project. The status of that finding gives the secret one of these statuses:
    - **New finding**: No finding for the secret exists, or the newest finding is **Resolved**
    - **Allowed**: The newest finding is **False Positive** or **Ignore**
    - **Pending resolution**: The newest finding is **Unresolved**

    For more information, see [How Infisical handles a detected secret](#how-infisical-handles-a-detected-secret).
5. Infisical tells the plugin if the prompt can continue, and if Infisical needs the prompt. Infisical needs the prompt only when at least one secret is a new finding.
6. If Infisical needs the prompt, the plugin then sends the full prompt. Infisical encrypts the prompt with the project's KMS key and scans it in the background with the project's [scanning configuration](/documentation/platform/secret-scanning/configuration). The scan records each new secret that it finds as a finding. If no secret is new, the plugin doesn't send the prompt, and the prompt never leaves the developer's machine.
7. If every secret is allowed, the prompt goes through. If not, the [**When a Secret Is Detected**](#block-or-report-secrets) setting of the data source decides what happens:
    - **Block the prompt**: Infisical blocks the prompt, and Claude Code shows a link to the findings page and tells the developer that the secret is waiting for review in Infisical (or that the plugin just reported the secret for review)
    - **Report only**: Infisical allows the prompt and Claude Code sends it to the model; for each secret that is new or pending resolution, Claude Code shows the developer a warning with a link to the findings page (only the developer sees the warning, not Claude)
8. A reviewer changes the finding's status. If the new status is **False Positive** or **Ignore**, Infisical allows prompts that contain that secret from then on, for every developer in the project. If the new status is **Resolved**, the next prompt that contains the secret creates a new finding.

## How Infisical handles a detected secret

Infisical uses only the newest finding for a secret to decide what happens. The same rules apply to every Claude Code data source:

| Newest finding for the secret | Status | Plugin sends the prompt to Infisical | Infisical records a new finding | With **Block the prompt** | With **Report only** |
| --- | --- | --- | --- | --- | --- |
| None | New finding | Yes | Yes | Prompt is blocked | Prompt continues, and the developer sees a warning |
| **Resolved** | New finding | Yes | Yes. The **Resolved** finding stays as history. | Prompt is blocked | Prompt continues, and the developer sees a warning |
| **False Positive** or **Ignore** | Allowed | No | No | Prompt continues | Prompt continues |
| **Unresolved** | Pending resolution | No | No | Prompt is blocked | Prompt continues, and the developer sees a warning |

A finding is usually **Resolved** because a reviewer revoked or rotated the secret. If the same secret appears in a prompt again, it's a new incident, so Infisical records a new finding. **False Positive** and **Ignore** mean that a reviewer accepted the secret, so Infisical doesn't report it again.

To let developers use a secret in Claude Code, mark its finding as **False Positive** or **Ignore**. Don't mark it as **Resolved**.

If a prompt contains more than one secret, the plugin sends the prompt to Infisical when at least one secret is a new finding. With **Block the prompt**, the prompt continues only when every secret in it is allowed.

## How Infisical matches secrets

Infisical matches a secret to its findings with a blind index. A blind index is an HMAC of the secret value with your organization's key. Infisical calculates it the same way as the blind index of secret values in Secrets Management.

- The blind index depends only on the secret value, so the same secret in a later prompt from any developer in the project matches the same findings (Infisical uses the newest of these findings to decide what happens to the secret)
- When the plugin sends secret values to get their statuses, Infisical uses the values only to calculate the blind indexes; Infisical doesn't store or log the values or the blind indexes from this step, and the API doesn't return them
- A finding stores the blind index of the secret and the secret value encrypted with the project's KMS key (the API never returns the encrypted value or the blind index)
- The fingerprint of a finding comes from where the secret is in the prompt (`<prompt submission>:<rule>:<line>:<column>`), in the same way that the fingerprint of a finding in a repository comes from the commit, the file, and the line

Infisical stores the encrypted secret value so that it can later match findings against your secrets in Secrets Management.

## Block or report secrets

The **When a Secret Is Detected** setting of a Claude Code data source controls what the plugin does with a prompt that contains a secret that isn't allowed:

- **Block the prompt** (default): The plugin blocks the prompt until the newest finding of every secret in it is **False Positive** or **Ignore**
- **Report only**: The prompt continues to Claude; Infisical still scans new secrets and records them as findings, and the developer sees a warning with a link to the findings for each secret that is new or pending resolution

This is the only setting that controls how the plugin handles a secret. The [rules for each finding status](#how-infisical-handles-a-detected-secret) are the same for every data source.

<Warning>
  With **Report only**, the prompt and the secret in it reach the model provider of Claude Code. Use **Report only** when you want to monitor which secrets your developers send, for example before you start to block prompts.
</Warning>

You select this setting when you create the data source. To change it later, edit the data source's settings.

The **When a Secret Is Detected** setting applies only to prompts that contain a secret. If the plugin itself fails, it blocks the prompt with both options. See [Failure behavior](#failure-behavior).

## Prerequisites

Each developer who uses Claude Code needs:

- The [Infisical CLI](/cli/install) version 0.44.9 or later, logged in with [`infisical login`](/cli/reference#login) (the plugin blocks every prompt while the CLI is older)
- [`jq`](https://jqlang.org/download/) and `curl`
- A role in the Secret Scanning project with the [permissions](#permissions) to submit prompts

The plugin uses the domain of your active CLI profile. For EU Cloud or a self-hosted instance, log in to that instance, for example with `infisical login --domain=https://eu.infisical.com`.

## Step 1: Create a Claude Code data source in Infisical

<Steps>
  <Step>
    Go to **Secret Scanning** > **Data Sources** and select **Add Data Source**.
  </Step>
  <Step>
    Select **Claude Code**.

    A Claude Code data source doesn't need an app connection or scan settings, because the plugin sends the prompts to Infisical.
  </Step>
  <Step>
    Under **When a Secret Is Detected**, select what the plugin does with a prompt that contains a secret that isn't allowed:

    - **Block the prompt** (default): Block the prompt until a reviewer marks the finding of each secret in it as **False Positive** or **Ignore**
    - **Report only**: Let the prompt continue to Claude, record the secret as a finding, and warn the developer

    For more information, see [Block or report secrets](#block-or-report-secrets).
  </Step>
  <Step>
    Enter a name and, optionally, a description for the data source, then select **Next**.

    - **Name**: A name that contains only lowercase letters, numbers, and hyphens (developers see this name when they select the data source in the setup command)
    - **Description** (optional): A description of the data source
  </Step>
  <Step>
    Review the data source, then select **Create Data Source**.
  </Step>
  <Step>
    Select the data source. Next to the data source type label, the data source's page shows the command to install the plugin, with a copy button. Send this command and the name of the data source to each developer.
  </Step>
</Steps>

## Step 2: Set up the plugin in Claude Code

Each developer does these steps on their own machine.

<Steps>
  <Step>
    Log in to Infisical with the Infisical CLI:

    ```bash
    infisical login
    ```

    The plugin gets its access token with `infisical user get token`, so it always acts as the logged-in user.
  </Step>
  <Step>
    Add the Infisical plugin marketplace and install the plugin.

    <Tabs>
      <Tab title="Terminal">
        ```bash
        claude plugin marketplace add Infisical/claude-code-plugin
        claude plugin install infisical-secret-scan@infisical
        ```

        Then start Claude Code. If Claude Code is already running, restart it.
      </Tab>
      <Tab title="Claude Code">
        ```
        /plugin marketplace add Infisical/claude-code-plugin
        /plugin install infisical-secret-scan@infisical
        ```
      </Tab>
    </Tabs>
  </Step>
  <Step>
    In Claude Code, run the setup command:

    ```
    /infisical-secret-scan:setup
    ```

    The setup command:

    1. Checks that the Infisical CLI, `jq`, and `curl` are installed.
    2. Checks that the Infisical CLI is logged in. If it isn't, the command tells you to run `infisical login` in a terminal. Log in, then run the setup command again.
    3. Shows the names of the Claude Code data sources in your organization's Secret Scanning project. Use the arrow keys to select the data source that your administrator gave you. You can select only a data source from the list.

    The plugin saves your selection in its data folder on your machine, so the setup command asks only once. To select a different data source, run the setup command again.

    <Note>
      Until you run the setup command, the plugin blocks every prompt and tells you to run `/infisical-secret-scan:setup`. The plugin never blocks the setup command.
    </Note>

    If your administrator [set the data source for you](#set-the-data-source-for-every-developer), the setup command doesn't ask you to select a data source.
  </Step>
  <Step>
    To test the setup, send a prompt that contains a test secret. The new finding appears in **Secret Scanning** > **Findings**.

    - With **Block the prompt**, Claude Code blocks the prompt, tells you that the secret was reported for review, and shows a link to the findings page
    - With **Report only**, Claude Code sends the prompt and shows a warning with a link to the findings page
  </Step>
</Steps>

<Tip>
  To install the plugin for a team, add the marketplace and the plugin to a Claude Code settings file that your team shares, such as the project's `.claude/settings.json` or a managed settings file:

  ```json
  {
    "extraKnownMarketplaces": {
      "infisical": {
        "source": {
          "source": "github",
          "repo": "Infisical/claude-code-plugin"
        }
      }
    },
    "enabledPlugins": {
      "infisical-secret-scan@infisical": true
    }
  }
  ```

  Each developer must still install the Infisical CLI, `jq`, and `curl`, log in with `infisical login`, and run `/infisical-secret-scan:setup`. To select the data source for every developer, [set it in a managed settings file](#set-the-data-source-for-every-developer).
</Tip>

### Set the data source for every developer

An administrator can make the plugin use one data source on every machine. Set `INFISICAL_CLAUDE_CODE_DATA_SOURCE_ID` to the ID of the data source in the `env` object of a [managed settings file](https://code.claude.com/docs/en/settings#settings-files). You can copy the ID from the data source's page.

```json
{
  "env": {
    "INFISICAL_CLAUDE_CODE_DATA_SOURCE_ID": "<data-source-id>"
  }
}
```

When this variable is set:

- The plugin always uses this data source, and ignores the data source that the developer selected with the setup command
- The setup command doesn't ask the developer to select a data source

Developers can't change a managed settings file. This way, a developer can't select a different data source, for example a **Report only** data source instead of one that blocks prompts.

<Note>
  You can also set the variable in a settings file that your team shares, such as the project's `.claude/settings.json`. But a developer can override that file with their own settings.
</Note>

## Review findings

When the plugin detects a new secret, the secret appears as a finding in **Secret Scanning** > **Findings**. To review it:

<Steps>
  <Step>
    Select the finding, and examine where the secret is in the prompt and who submitted it.
  </Step>
  <Step>
    Select **Update Status**, then select a status:

    - **Resolved**: You've dealt with the leak, for example by revoking or rotating the secret (if the secret appears in a prompt again, Infisical records a new finding)
    - **False Positive**: The value isn't a secret, and developers can use the value in Claude Code
    - **Ignore**: The value is a secret, but you've decided it's safe to send to Claude Code (such as a test credential), and developers can use the secret in Claude Code
  </Step>
  <Step>
    Select **Update Status**. With **Block the prompt**, if the new status is **False Positive** or **Ignore**, the developer can now submit the prompt again.
  </Step>
</Steps>

A review applies to the secret, not to one prompt. After you mark a finding as **False Positive** or **Ignore**, Infisical allows the same secret in prompts from every developer in the project. To learn more about statuses, see [How Infisical handles a detected secret](#how-infisical-handles-a-detected-secret) and [Findings](/documentation/platform/secret-scanning/findings#finding-statuses).

<Note>
  With **Block the prompt**, Infisical blocks every prompt that contains the secret until its newest finding is **False Positive** or **Ignore**. Changing the prompt doesn't help unless the developer removes the secret.

  With **Report only**, the prompt already reached the model provider when the finding appears. Review the finding to decide if you must revoke the secret. After you change the status from **Unresolved** to **False Positive** or **Ignore**, the plugin stops warning developers about the secret. After you change it to **Resolved**, the next prompt that contains the secret creates a new finding, and the plugin warns the developer again.
</Note>

## Resources and scans

Each developer who submits a prompt with a new secret becomes one resource of the data source. The name of the resource is the developer's email address. To see the resources and the scan history, select the data source.

You can't add resources to a Claude Code data source yourself, and you can't trigger a scan manually. Infisical scans a prompt only when the plugin sends it.

## What Infisical stores

Infisical doesn't keep the prompt after the scan.

- When the plugin sends secret values to get their statuses, Infisical uses the values only to calculate the [blind indexes](#how-infisical-matches-secrets), and doesn't store or log the values or the blind indexes from this step
- The plugin sends the prompt only when the prompt contains a new secret, or a secret whose newest finding is **Resolved**; Infisical encrypts the prompt with the project's KMS key, and keeps it only in the queued scan until the scan runs

For each secret that the scan finds, the finding records:

- The rule that found the secret, and its description
- Where the secret is in the prompt: the start and end line, and the start and end column
- The entropy of the secret
- The name and email address of the developer who submitted the prompt
- When the developer submitted the prompt
- The working directory of the Claude Code session
- The Claude Code session ID
- The blind index of the secret value
- The secret value, encrypted with the project's KMS key

The API never returns the encrypted secret value or the blind index. Infisical stores the encrypted value so that it can later match the finding against your secrets in Secrets Management.

## Scanning configuration

If the project has a custom [scanning configuration](/documentation/platform/secret-scanning/configuration), the plugin downloads it and uses it for the scans on the developer's machine. This way, the plugin and Infisical find the same secrets.

- The plugin downloads the configuration at most once every 24 hours
- The download runs in the background, and doesn't delay prompts
- On the first prompt after setup, the plugin downloads the configuration before it scans, and blocks the prompt if the download fails
- If the plugin can't download the configuration for 48 hours, it tries again before the next scan, and blocks the prompt if that download fails
- If the project has no custom configuration, the plugin and Infisical both use the default rules of the Infisical CLI

<Note>
  A change to the scanning configuration can take up to 24 hours to reach each developer's machine.
</Note>

## Permissions

Each developer needs these permissions in the Secret Scanning project:

| Permission | Why the plugin needs it |
| --- | --- |
| **Secret Scanning Data Sources** > **Trigger Scans** | To send the secrets that the plugin finds, and prompts with new secrets, to Infisical |
| **Secret Scanning Data Sources** > **Read Data Sources** | To show the data sources in the setup command, and to find the project of the data source |
| **Secret Scanning Config** > **Read Config** | To download the scanning configuration |

Reviewers need **Secret Scanning Findings** > **Update Findings** to change the status of a finding.

The default **Admin** and **Member** roles have all of these permissions. The default **Viewer** role can't trigger scans, so the plugin blocks every prompt with a secret for a viewer, even with **Report only**.

## Failure behavior

The plugin fails closed. If any part of its setup is broken, it blocks every prompt (including prompts without secrets) and shows the cause. This way, a developer can't get around the review. The plugin blocks prompts when:

- The Infisical CLI, `jq`, or `curl` isn't installed
- The developer hasn't run `/infisical-secret-scan:setup`, and `INFISICAL_CLAUDE_CODE_DATA_SOURCE_ID` isn't set
- The Infisical CLI isn't logged in (the plugin checks this on each prompt)
- The data source no longer exists, or the plugin can't read it (if the developer selected the data source with the setup command, they must run the setup command again)
- The plugin must download the scanning configuration and the download fails, for example because the request is denied or Infisical can't be reached
- The local scan fails
- A prompt contains a secret, and the request to Infisical fails
- The check doesn't finish within 45 seconds

These failures block prompts with **Block the prompt** and with **Report only**. The plugin never blocks the setup command, so a developer can always run it to fix the setup.

When the setup works and the configuration is up to date, prompts without secrets never call Infisical.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The Infisical CLI is too old">
    The plugin needs the Infisical CLI version 0.44.9 or later, and blocks every prompt while the CLI is older. Run `infisical --version` to see your version, then [update the CLI](/cli/install).
  </Accordion>
  <Accordion title="The Infisical CLI isn't installed">
    The plugin needs the Infisical CLI to scan prompts. [Install the CLI](/cli/install), make sure that `infisical` is on your `PATH`, then restart Claude Code.
  </Accordion>
  <Accordion title="jq or curl isn't installed">
    The plugin needs `jq` to read the prompt and `curl` to call Infisical. [Install jq](https://jqlang.org/download/) or curl, make sure that both are on your `PATH`, then restart Claude Code.
  </Accordion>
  <Accordion title="You aren't logged in">
    The plugin checks on each prompt that the Infisical CLI is logged in, and gets an access token with `infisical user get token`. If you aren't logged in, run `infisical login` in a terminal, then submit the prompt again. If the setup command told you to log in, run `/infisical-secret-scan:setup` again after you log in. For EU Cloud or a self-hosted instance, log in to that instance with `--domain`.
  </Accordion>
  <Accordion title="Setup hasn't been run">
    The plugin blocks every prompt until you select a data source. In Claude Code, run `/infisical-secret-scan:setup` and select the data source that your administrator gave you. If the list is empty, ask your administrator to create a Claude Code data source, or to give you the [permissions](#permissions) to read data sources.
  </Accordion>
  <Accordion title="The selected data source was deleted">
    If the data source that you selected was deleted, or you can't read it anymore, the plugin blocks every prompt. Run `/infisical-secret-scan:setup` again and select a different data source. If your administrator [set the data source for you](#set-the-data-source-for-every-developer), ask them to update `INFISICAL_CLAUDE_CODE_DATA_SOURCE_ID`.
  </Accordion>
  <Accordion title="Infisical can't be reached">
    The plugin calls Infisical when a prompt contains a secret and when it downloads the scanning configuration. Make sure that your machine can reach the Infisical instance that you logged in to with `infisical login`.
  </Accordion>
  <Accordion title="The request is denied">
    Your role doesn't have the [permissions](#permissions) that the plugin needs, or the data source belongs to a project that you aren't a member of. Ask a project admin to give you the permissions, or run `/infisical-secret-scan:setup` again and select a different data source.
  </Accordion>
  <Accordion title="The prompt is still blocked after a review">
    Make sure that the newest finding of every secret in the prompt is **False Positive** or **Ignore**. Only these two statuses let developers use a secret. **Resolved** doesn't: if a secret with a **Resolved** finding appears in a prompt again, Infisical records a new **Unresolved** finding and blocks the prompt. Mark the new finding as **False Positive** or **Ignore** to allow the secret. If the prompt contains a different secret, it creates a new finding that needs a review.
  </Accordion>
  <Accordion title="Claude Code shows a warning, but doesn't block the prompt">
    The data source uses **Report only**. Infisical records the secret as a finding, and the prompt continues to Claude. To block prompts that contain secrets, change **When a Secret Is Detected** to **Block the prompt** in the data source's settings.
  </Accordion>
  <Accordion title="The plugin and Infisical find different secrets">
    The plugin downloads the scanning configuration at most once every 24 hours. After a change to the configuration, the plugin can use the earlier configuration for up to 24 hours.
  </Accordion>
</AccordionGroup>
