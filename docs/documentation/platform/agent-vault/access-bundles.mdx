---
title: "Access bundles"
description: "Lists of services that AI agents can access during a session."
---

An access bundle defines the list of [services](/documentation/platform/agent-vault/services) that an AI agent can access during a [session](/documentation/platform/agent-vault/sessions). Services belong to the Agent Vault project, so you define each service once and add it to every access bundle that needs it.

You can reuse access bundles across as many sessions as you like. This makes them useful for scoping what services an agent can access depending on its task. For example, you might have:

- A **code-review** bundle that grants access to GitHub and Slack
- A **customer-feedback** bundle that grants access to Discord, Resend, and Slack
- A **marketing** bundle that grants access to Twilio and Google Docs

## Create an access bundle

To create a new access bundle:

<Steps>
  <Step>
    In your Agent Vault project, go to **Access Bundles** and select **Create Access Bundle**.
  </Step>
  <Step>
    Give the bundle a name that says what job it's for, like **code-review** or **marketing**, and optionally a **Description**.

    <Frame>
      <img src="/images/platform/agent-vault/access-bundle-create.png" alt="The Create Access Bundle dialog with deploy-checks as the name and a description" />
    </Frame>

  </Step>
  <Step>
    Select **Create Access Bundle**. The access bundle appears in the list.
  </Step>
</Steps>

Now you can [add services](/documentation/platform/agent-vault/services#add-a-service-to-an-access-bundle) to the access bundle so agents using it can make authenticated requests. You can also [add skills](/documentation/platform/agent-vault/skills#add-a-skill-to-an-access-bundle) to the access bundle, so the CLI installs your team's instructions for every agent that starts with it.

## Who can use an access bundle

Access bundles give agents credentials for external APIs, so members of a project can't create sessions with an access bundle until one of their [roles](/documentation/platform/agent-vault/access-control#roles) lets them use it. A role that can use an access bundle can use every service and skill in the bundle.

To let someone use an access bundle:

<Steps>
  <Step>
    Make sure the user, group, or machine identity is a member of the Agent Vault project. If not, [add them under Access Control](/documentation/platform/agent-vault/access-control#add-members).
  </Step>
  <Step>
    Give them a role with **Use** on the access bundle. If no role has it yet, [create a custom role](/documentation/platform/agent-vault/access-control#create-a-custom-role) with **Use** on this access bundle.
  </Step>
</Steps>

To see who can use an access bundle, open it from **Access Bundles**. The **Who Can Use This Bundle** section lists each role that can use the bundle and how many members hold the role.

<Frame>
  <img src="/images/platform/agent-vault/access-bundle-who-can-use.png" alt="The code-review access bundle's page, with its services and skills and a Who Can Use This Bundle section that lists the built-in Admin role and the custom Release Engineers role, each held by one member" />
</Frame>

To stop someone from using an access bundle, take away each of their roles that can use it. If any of their agents are running, those agents lose the bundle's credentials within one [poll interval](/documentation/platform/agent-vault/proxies#poll-interval).

## Set up your personal values

Some services ask you for part of their credential, such as your own API key (see [member-provided values](/documentation/platform/agent-vault/http-apis#member-provided-values)), or ask you to connect your own account to an [MCP server](/documentation/platform/agent-vault/mcp-servers#member-provided-credentials). Until you set up your personal values for one of these services, your sessions can't use it, and the service shows **Requires Setup**. This applies to admins too.

You set up your personal values once per service, and they apply in every access bundle that holds the service.

To set up your personal values:

<Steps>
  <Step>
    In your Agent Vault project, go to **Services**. To list only the services that need your values, select **View Services** in the banner at the top of the page, or open the filter menu next to the search box and select **Requires Setup**.

    <Frame>
      <img src="/images/platform/agent-vault/services-requires-setup.png" alt="The Services page for a member, filtered to the services that need their values: a banner that says 3 services require your personal values, and github, notion, and orders-db marked Requires Setup" />
    </Frame>
  </Step>
  <Step>
    Select **Requires Setup** next to the service, or open the service's actions menu and select **Set Up My Personal Values**.
  </Step>
  <Step>
    Enter each value. To use one of your [personal variables](/documentation/platform/agent-vault/variables#personal-variables), type `{{` or select the arrow at the end of the field, then pick a variable from the list.

    <Frame>
      <img src="/images/platform/agent-vault/personal-values.png" alt="The Set Up Personal Values for slack dialog, with a partly typed reference in the Slack token field and the SLACK_USER_TOKEN personal variable in the list" />
    </Frame>

    For an MCP service that uses OAuth, select **Connect Account** instead, then sign in to the provider in the pop-up window and approve access. When you approve, Infisical saves the connection, closes the dialog, and the service shows **Configured**.

    <Frame>
      <img src="/images/platform/agent-vault/personal-values-oauth.png" alt="The Set Up Personal Values for notion dialog, showing that your mcp.notion.com account isn't connected yet, with a Connect Account button" />
    </Frame>
  </Step>
  <Step>
    If you entered values, select **Save**. The service shows **Configured**.
  </Step>
</Steps>

If the provider stops accepting your login, the service shows **Requires Setup** again. If an agent needs scopes that your connection doesn't grant, the service shows **Missing Scopes**. In either case, select **Requires Setup** or **Missing Scopes** next to the service, then select **Reconnect**. If the message under your connection says the provider refused the service's OAuth app, reconnecting won't help. Ask a project [admin](/documentation/platform/agent-vault/access-control) to update the service.

Infisical never shows your personal values to anyone else, admins included.

Infisical keeps your personal values until you leave the project. If you lose access to a service, your sessions stop using your values for it, and they use them again if you get access back.

- To change your personal values, open the service's actions menu, select **Update My Personal Values**, and enter the values you want to change
- To delete your personal values, select **Remove** in the same dialog, then select **Remove Personal Values** (**Disconnect Account** for an OAuth service)

A machine identity sets up its personal values with [the set personal values endpoint](/api-reference/endpoints/agent-vault-services/set-personal-values), and keeps its own personal variables with [the create variable endpoint](/api-reference/endpoints/agent-vault-variables/create). A machine identity can't connect an OAuth account. For an MCP service where each member connects their own account, have the machine identity create the session [on behalf of a user](/documentation/platform/agent-vault/sessions-on-behalf-of-users) who has connected theirs.
