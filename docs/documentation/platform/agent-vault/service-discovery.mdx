---
title: "Service discovery"
description: "Let an AI agent find the services its session can use."
---

If an agent runs behind the Agent Vault [proxy](/documentation/platform/agent-vault/proxies), it holds no API keys, so its environment doesn't list the APIs and MCP servers it can use. Without help, the agent often stops and asks you for a key, even though the proxy would have added the real one.

Agent Vault provides two things so that an agent can find its services on its own:

- A [list of the services](#get-the-list) its [session](/documentation/platform/agent-vault/sessions) can use, which the agent gets from Infisical through the proxy
- Agent Vault's [built-in skill](#the-built-in-skill), which tells the agent to check the list before it asks for a key, and explains how to work behind the proxy

## Get the list

The agent gets the list by calling the [List session services](/api-reference/endpoints/agent-vault-sessions/list-session-services) endpoint:

<CodeGroup>
```bash US Cloud
curl -sS --noproxy "" "https://app.infisical.com/api/v1/agent-vault/session/services"
```

```bash EU Cloud
curl -sS --noproxy "" "https://eu.infisical.com/api/v1/agent-vault/session/services"
```

```bash Self-hosted
curl -sS --noproxy "" "<your-instance-url>/api/v1/agent-vault/session/services"
```
</CodeGroup>

<Note>
  `--noproxy ""` sends the request through the proxy even if the `NO_PROXY` environment variable lists your Infisical instance's host. The proxy adds the session's token to the request, so without it, Infisical refuses the request.
</Note>

Each request for the list appears in the session's [logs](/documentation/platform/agent-vault/session-logs#log-contents) with the outcome **Passthrough**.

## List contents

This shortened example shows a GitHub service that allows only `GET` requests:

```json
{
  "session": { "expiresAt": "2026-11-05T02:00:00Z", "accessBundle": "engineering" },
  "services": [
    {
      "name": "github",
      "description": "GitHub REST API for the acme-corp organization.",
      "type": "http",
      "hosts": ["api.github.com"],
      "url": "https://api.github.com",
      "status": "ready",
      "credential": { "type": "bearer", "header": "Authorization", "addedByProxy": true, "memberProvided": false },
      "allowedMethods": ["GET"],
      "howToUse": "Call https://api.github.com directly. The proxy sets the Authorization header, so send no key, or any placeholder value if a client or SDK insists on one. A key you send in that header is replaced. Only GET requests are allowed; the proxy refuses any other method."
    }
  ]
}
```

For the full reference, see the [List session services](/api-reference/endpoints/agent-vault-sessions/list-session-services) endpoint.

<Note>
  The list never includes a credential, a custom header's value, or a substitution's value.
</Note>

## The built-in skill

`infisical-agent-vault` is a [skill](/documentation/platform/agent-vault/skills) that Agent Vault provides for every agent. The skill tells the agent to:

- Expect no API keys in its environment, and check its list of services before it asks you for a key or gives up on a task
- Give a placeholder key, such as `agent-vault`, to a tool or SDK that won't start without one, and write a service's substitution placeholder where the secret goes
- Call an MCP service with plain HTTP requests if the agent's MCP client only loads servers when the client starts
- Read the `X-Agent-Vault-Decision` header to tell the proxy's responses apart from the API's (see [Responses from the proxy](/documentation/platform/agent-vault/proxies#responses-from-the-proxy))
- Read Infisical's documentation for agents only when a task is about Infisical itself
- Never bypass the proxy, turn off TLS verification, or print the proxy URL, which holds the session token

The skill tells the agent to request the list first, and to ignore the skill if `INFISICAL_AGENT_VAULT_URL` isn't set, such as when an agent later runs on the same host without Agent Vault.

### Read the built-in skill

To read the built-in skill, call the [Get built-in skill](/api-reference/endpoints/agent-vault-skills/get-builtin) endpoint. After `infisical agent-vault run` installs the skill, its files are also on the agent's host, in the [folder where the CLI installs skills](/documentation/platform/agent-vault/skills#skill-folders).

Infisical provides the built-in skill, so you can't edit it or delete it. To leave it out, [turn it off](#turn-off-the-built-in-skill).

### Built-in skill installation

- `infisical agent-vault run` installs the built-in skill along with the session's [other skills](/documentation/platform/agent-vault/skills#skill-installation)
- If your code starts agents without `infisical agent-vault run`, such as in an [E2B sandbox](/documentation/platform/agent-vault/guides/e2b#step-4-run-a-command-in-a-sandbox), install the skills that the [List session skills](/api-reference/endpoints/agent-vault-skills/list-session-skills) endpoint returns (they include the built-in skill), and set `INFISICAL_AGENT_VAULT_URL` to the URL of the Infisical instance that the proxy connects to

### Turn off the built-in skill

- With `infisical agent-vault run`, pass [`--no-agent-vault-skill`](/cli/reference#agent-vault-run--flag-no-agent-vault-skill) to leave out only the built-in skill, or [`--no-skills`](/cli/reference#agent-vault-run--flag-no-skills) to leave out every skill
- With the [List session skills](/api-reference/endpoints/agent-vault-skills/list-session-skills) endpoint, pass `includeBuiltin=false`

To replace the built-in skill with your own, turn the built-in skill off and give your skill another name. A skill you add can't use the name `infisical-agent-vault`.
