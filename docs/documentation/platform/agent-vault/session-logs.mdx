<Info>
  Session logs are a paid feature.

  If you're using Infisical Cloud, they're available under the **Enterprise Tier**. If you're self-hosting Infisical, contact sales@infisical.com to purchase an enterprise license to use them.

A session log is a record of every request an agent makes during a [session](/documentation/platform/agent-vault/sessions): the method, host, path, status code, and whether the proxy attached a credential. The [proxy](/documentation/platform/agent-vault/proxies) adds every request it receives to the session log, including requests to hosts that no [access bundle](/documentation/platform/agent-vault/access-bundles) covers.

The proxy encrypts the records before they leave your network and uploads them to an Amazon S3 bucket you own.

## Setting up session logs

Infisical reaches your bucket through an [AWS app connection](/integrations/app-connections/aws/), which signs in to AWS by assuming an IAM role you create.

You'll switch between Infisical and AWS during setup: Infisical generates the AWS policy for your bucket, you set up the bucket and role in AWS, and then you create the connection in Infisical with the role's ARN.

### Prerequisites

- The [Admin role](/documentation/platform/agent-vault/access-control) in Agent Vault
- An [Amazon S3 bucket](https://docs.aws.amazon.com/AmazonS3/latest/userguide/create-bucket-overview.html) to store the records in
- Permission in AWS to edit the bucket's CORS configuration, create IAM roles, and attach policies to them

### Step 1: Start in Infisical

<Steps>
  <Step>
    In Agent Vault, go to **Administration** > **Settings** and select **Set Up Session Logs**.
  </Step>
  <Step>
    Enter the **Region** and **Bucket** of your S3 bucket.
  </Step>
  <Step>
    Optionally, enter a **Key Prefix** to store session logs under one path in a bucket you also use for other data.
  </Step>
  <Step>
    Select **View AWS Setup**. Infisical shows an **IAM policy** with your bucket and key prefix already filled in, so you can paste it into AWS as it is.
  </Step>
</Steps>

Leave the **Session Logs** dialog open. You'll fill in **AWS Connection** in [Step 3](#step-3-finish-in-infisical), after you create the role it uses. Open AWS in another browser tab.

## Viewing session logs

You can view a session's logs if you created the session or you're an Agent Vault admin.

<Tabs>
<Tab title="In Infisical">
  Go to **Sessions** and select **View Session Logs** on the session's row. You can filter and search the requests, and while the session is active, new requests appear as the proxy uploads them.

  <Frame>
    <img src="/images/platform/agent-vault/session-logs-view.png" alt="The Session Logs sheet for an active session, listing each request's time, method, host, path, upstream status, and outcome" />
  </Frame>
</Tab>
<Tab title="Through the API" id="reading-session-logs-through-the-api">
  The API returns a session's logs as chunks. A chunk is one encrypted batch of [records](#what-gets-recorded) that a proxy uploaded to your bucket.

  <Steps>
    <Step>
      Call [the endpoint that lists session logs](/api-reference/endpoints/agent-vault-session-logs/list). It returns the newest chunks first. To get older chunks, call it again with the response's `nextCursor` as `cursor`.

      <Note>
        If Infisical can't read the bucket, the response has no chunks, and `sessionLogs.storageUnavailable` holds the reason.
      </Note>
    </Step>
    <Step>
      Download each chunk from its `presignedGetUrl` within 5 minutes, before the URL expires.
    </Step>
    <Step>
      Decrypt the chunk with AES-256-GCM. The key is `sessionLogs.sessionKey`, base64 decoded. The first 12 bytes of the chunk are the IV, and the last 16 bytes are the authentication tag. The associated data is the SHA-256 digest of `<sessionId>|<chunkId>|v1`.
    </Step>
    <Step>
      Parse the decrypted bytes as JSON. Each chunk holds an array of records, and `decision` holds the [outcome](#what-gets-recorded) in lowercase:

      ```json
      {
        "ts": "2026-09-16T10:31:04.221Z",
        "seq": 8412,
        "proxyId": "<proxy-id>",
        "method": "POST",
        "host": "api.github.com",
        "port": "443",
        "path": "/repos/acme/web/issues",
        "status": 201,
        "decision": "brokered",
        "service": "github",
        "accessBundle": "code-review"
      }
      ```
    </Step>
  </Steps>

  This Node.js script reads the newest page of a session's logs:

  ```javascript expandable
  import { createDecipheriv, createHash } from "node:crypto";

  const token = "<your-access-token>";
  const sessionId = "<session-id>".toLowerCase();

  const res = await fetch(`https://app.infisical.com/api/v1/agent-vault/sessions/${sessionId}/logs`, {
    headers: { Authorization: `Bearer ${token}` }
  });
  const { sessionLogs, chunks } = await res.json();

  for (const chunk of chunks) {
    const body = Buffer.from(await (await fetch(chunk.presignedGetUrl)).arrayBuffer());

    const aad = createHash("sha256").update(`${sessionId}|${chunk.chunkId}|v1`).digest();
    const decipher = createDecipheriv(
      "aes-256-gcm",
      Buffer.from(sessionLogs.sessionKey, "base64"),
      body.subarray(0, 12)
    );
    decipher.setAAD(aad);
    decipher.setAuthTag(body.subarray(-16));
    const plaintext = Buffer.concat([decipher.update(body.subarray(12, -16)), decipher.final()]);

    console.log(JSON.parse(plaintext.toString("utf8")));
  }
  ```

  <Note>
  The script runs outside a browser, so the bucket's CORS rule doesn't apply to it.
  </Note>

  To receive new logs as they arrive, call [the endpoint that tails session logs](/api-reference/endpoints/agent-vault-session-logs/tail) without a cursor, then call it every few seconds with the previous response's `nextCursor`. The first response can repeat chunks you already read from [the endpoint that lists session logs](/api-reference/endpoints/agent-vault-session-logs/list), so skip any chunk whose `chunkId` and `proxyId` you've already read. If a chunk's download returns 404, the proxy hasn't finished uploading it, so try again a few seconds later.
</Tab>
</Tabs>

## What gets recorded

Each request produces one record with:

| Field | What it holds |
| --- | --- |
| **Time** | When the request was made |
| **Method**, **Host**, **Path** | Where the request went, for example `POST api.github.com/repos/acme/web/issues` |
| **Upstream status** | The HTTP status code the API returned, such as `201`. For **Blocked** and **Error** requests, it's the status code the proxy returned, such as `403` or `502` |
| **Outcome** | What the proxy did with the request |
| **Service** | The service that matched the request, if any |

The outcome is one of four:

| Outcome | What happened |
| --- | --- |
| **Brokered** | A service matched and the proxy attached its credential to the request |
| **Passthrough** | No service matched, or the matching service has no credential. The proxy forwarded the request without a credential |
| **Blocked** | The proxy refused the request, for one of the reasons in [Blocked requests](/documentation/platform/agent-vault/proxies#blocked-requests) |
| **Error** | The proxy couldn't reach the destination host |

Request and response bodies, headers, and query strings aren't recorded.

## Managing session logs

### Connections

Session logs use one AWS connection at a time, which you select in the **Session Logs** dialog.

To update the connection's AWS credentials, open the menu next to **Configure** on the **Session Logs** card and select **Edit AWS Credentials**. If the connection belongs to your organization, update its credentials under **Integrations** in your organization instead.

To add or delete Agent Vault's AWS connections, select **Manage Connections** from the same menu:

<Frame>
  <img src="/images/platform/agent-vault/session-logs-connections.png" alt="The Manage Connections sheet listing Agent Vault's AWS connections, with the one session logs use marked In Use" />
</Frame>

You can't delete a connection while session logs use it. To delete the connection, select a different one in the **Session Logs** dialog first.

### Changing the bucket or prefix

Infisical doesn't copy existing records when you change the bucket or the key prefix. Records written before the change don't show in Infisical until you switch back to that bucket and prefix.

### Retention

Infisical never deletes sessions or their session logs. To delete older logs automatically, add an [S3 Lifecycle rule](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lifecycle-mgmt.html) to the bucket.

## Troubleshooting

If the AWS connection returns an error, a red dot appears next to **Settings** in the Agent Vault sidebar, and the **Settings** page shows the error.
