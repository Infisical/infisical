---
title: "Variables"
description: "Values you store once in an access bundle and use in any of its services."
---

A variable is a value that you can reuse across all the [services](/documentation/platform/agent-vault/services) within an [access bundle](/documentation/platform/agent-vault/access-bundles). You define the variable once and give it a key, such as `GITHUB_TOKEN`. Then, any service in the access bundle can use the variable by referencing the key within double braces: `{{GITHUB_TOKEN}}`.

When an agent sends a request, the [proxy](/documentation/platform/agent-vault/proxies) replaces each reference with the variable's value.

<Info>
  Only [Agent Vault admins]((/documentation/platform/agent-vault/access-control#product-membership)) can view and update variables.
</Info>

## Add a variable

To add a variable to an access bundle:

<Steps>
  <Step>
    In Agent Vault, go to **Access Bundles** and select your access bundle.

    <Frame>
      <img src="/images/platform/agent-vault/access-bundle-variables-empty.png" alt="The on-call access bundle's page, with its Services list and an empty Variables card with an Add Variable button" />
    </Frame>

  </Step>
  <Step>
    Under **Variables**, select **Add Variable**.

    <Frame>
      <img src="/images/platform/agent-vault/variable-create.png" alt="The Add Variable dialog with GITHUB_TOKEN as the key, a hidden value, and Secret selected" />
    </Frame>

  </Step>
  <Step>
    Enter a **Key** and a **Value**.

    <Note>
    A key must start with a letter, use only uppercase letters, numbers, and underscores, and can be up to 64 characters long. Two variables in the same access bundle can't have the same key.
    </Note>

  </Step>
  <Step>
    Leave **Secret** selected to hide the value once you save it. If you're storing something that isn't sensitive, such as an organization ID, clear **Secret** so the value stays visible in the list.
  </Step>
  <Step>
    Select **Add Variable**. The variable appears in the **Variables** list.

    <Frame>
      <img src="/images/platform/agent-vault/access-bundle-variables.png" alt="The on-call access bundle's Variables list with GITHUB_TOKEN, its value hidden, and Unused in the Used By column" />
    </Frame>

  </Step>
</Steps>

<Note>
An access bundle can hold up to 100 variables.
</Note>

## Use a variable in a service

You can use a variable in the following fields when [configuring a service](/documentation/platform/agent-vault/services#add-a-service):

- **Token** in a [Bearer](/documentation/platform/agent-vault/services#bearer) credential
- **Username** and **Password** in a [Basic](/documentation/platform/agent-vault/services#basic) credential
- **Value** in a [custom header](/documentation/platform/agent-vault/services#custom-headers)
- **With** in a [substitution](/documentation/platform/agent-vault/services#substitutions)

To use a variable:

<Steps>
  <Step>
    [Add a service](/documentation/platform/agent-vault/services#add-a-service), or open an existing service's actions menu and select **Edit**. Then go to the **Credential** step.
  </Step>
  <Step>
    In a field that accepts variables, type `{{`. A list of the bundle's variables appears.

    <Frame>
      <img src="/images/platform/agent-vault/service-variable-picker.png" alt="The Credential step of a GitHub service, with a partly typed reference in the Token field and a list showing GITHUB_TOKEN and Create GITHUB_" />
    </Frame>

  </Step>
  <Step>
    Select a variable from the list. Infisical inserts the reference, such as `{{GITHUB_TOKEN}}`.

    <Tip>
    You can also create a variable without leaving the service. Type its key, then select **Create** at the end of the list. The **Add Variable** dialog opens with the key filled in, so you only need to enter a **Value**.
    </Tip>

    <Frame>
      <img src="/images/platform/agent-vault/service-variable-reference.png" alt="The Credential step of a GitHub service with a GITHUB_TOKEN reference as the Token, and the Sends preview showing the reference after Authorization: Bearer" />
    </Frame>

    A reference can fill a whole field or part of one. For example, if a custom header's **Value** is `org-{{ORG_ID}}`, the proxy sends `org-` followed by the value of `ORG_ID`.
  </Step>
</Steps>

## Check variable usage

To check which services are using a variable:

<Steps>
  <Step>
    In Agent Vault, go to **Access Bundles** and select the variable's access bundle.
  </Step>
  <Step>
    In the **Variables** list, find the variable's **Used By** column. The column shows an icon for each service that uses the variable, or **Unused** if no service uses it.
  </Step>
  <Step>
    Hover over an icon to view the service's name.
  </Step>
</Steps>

## Update a variable

To update a variable:

<Steps>
  <Step>
    In Agent Vault, go to **Access Bundles** and select the variable's access bundle.
  </Step>
  <Step>
    In the **Variables** list, open the variable's actions menu and select **Edit**.
  </Step>
  <Step>
    Update the key, the value, or whether the value is secret. If the variable is secret, leave **Value** blank to keep the current value.
  </Step>
  <Step>
    Select **Save**.
  </Step>
</Steps>

<Note>
If you rename a variable, the services that use it keep working without changes. If you change a variable's value, the proxy sends the new value within one [poll interval](/documentation/platform/agent-vault/proxies#poll-interval) (60 seconds by default). Any running agents will begin using the new value automatically.
</Note>

## Delete a variable

To delete a variable:

<Steps>
  <Step>
    In Agent Vault, go to **Access Bundles** and select the variable's access bundle.
  </Step>
  <Step>
    In the **Variables** list, open the variable's actions menu and select **Delete**.
  </Step>
  <Step>
    Select **Delete Variable**.
  </Step>
</Steps>

 <Note>
If any service still uses the variable, the dialog lists those services, and you can't delete the variable until you [remove the reference](#use-a-variable-in-a-service) from each one.
</Note>
