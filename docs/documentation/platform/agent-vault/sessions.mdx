---
title: "Sessions"
description: "Mint the token an agent runs with, choose how long it lives, and revoke it while the agent is running."
---

A session is the token an agent runs with. It carries a fixed set of access bundles, in order, and an expiry. On every request the proxy uses it to decide which connections the agent may use right now, and applies their credentials on the way out.

## Minting a session

Anyone with a grant on at least one bundle can mint a session. Admins can mint over any bundle.

<Tabs>
  <Tab title="Dashboard">
    Go to **Sessions** and select **Create Session**. Add the bundles the agent needs, set how long the session lives, and select **Create Session**. The token is shown once, with the command to run:

    ```bash
    infisical av run --session-token <session-token> --proxy <proxy-address> -- claude
    ```

    Copy it now. The dialog can't be reopened.

    This is the way to start an agent on a machine that has no Infisical login. The token is the only thing you hand over.
  </Tab>
  <Tab title="CLI">
    `infisical av run` mints a session for you when you name the bundles:

    ```bash
    infisical av run --access-bundle coding-agent --proxy <proxy-address> -- claude
    ```

    The CLI mints as your login, or as a machine identity if you pass `--client-id` and `--client-secret`. It revokes the session when the agent exits unless you pass `--keep-session`.

    This suits a machine that's already signed in, or a machine identity that runs agents in a loop.
  </Tab>
</Tabs>

### Bundle order

When two bundles cover the same host with identical patterns, the bundle listed first wins. The Create Session sheet lets you reorder them, and the CLI takes the order you pass `--access-bundle`. An exact host in a later bundle still beats a wildcard in an earlier one.

### How long a session lives

Pick 1 hour, 8 hours, 24 hours, 7 days, or never. Seven days is the default. A session that never expires keeps working until someone revokes it, so revoke it once the agent that used it has finished.

## What a running agent can reach

The bundles on a session are fixed at mint. What the agent can actually reach is re-checked against the current grants on every proxy poll, 60 seconds by default, and it can only shrink:

- Remove someone from a bundle, and every session they minted over it loses that bundle's connections.
- Remove them from Agent Vault, and their sessions stop reaching anything. Add them back and the sessions work again.
- Demote an admin to member, and their sessions keep only the bundles they were explicitly granted.
- Delete a bundle, and it contributes nothing to any session that carried it. The session still lists the bundle's name so you can see what it was.

Nothing on the agent's machine needs to be restarted for any of this.

## Revoking and expiry

Select the session's menu on the Sessions page and choose **Revoke Session**. The proxy stops applying credentials for it on its next poll. Revoking is permanent.

An expired session stops the same way. The Sessions page shows sessions as **Active**, **Revoked**, or **Expired**, and keeps expired and revoked sessions for 30 days so you can see what an agent could reach.

Admins can switch the list between **All Sessions** and **My Sessions**. Members see only their own.

## Audit trail

Minting, revoking, and expiry each write an audit event, as does every change to a bundle, connection, or proxy. Open **Audit Logs** in Agent Vault, or scope an [audit log stream](/documentation/platform/audit-log-streams/audit-log-streams) to the Agent Vault product.
