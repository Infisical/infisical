---
title: "Sessions"
description: "Time-bound grants that let AI agents access services without holding real credentials."
---

A session is a time-bound grant in an [Agent Vault project](/documentation/platform/agent-vault/projects), and it works only through a proxy in that project. It's scoped to one [access bundle](/documentation/platform/agent-vault/access-bundles), to [inline services](/documentation/platform/agent-vault/inline-services) that an admin sends with the session, or to both. Infisical returns a session token that identifies the session, and the agent uses that token to authenticate to the [proxy](/documentation/platform/agent-vault/proxies) on every outbound request. The proxy then attaches the real credential from the matching [service](/documentation/platform/agent-vault/services) before it forwards the request.

You choose how long a session lasts when you create it. After the session expires, or after [you revoke it](/documentation/platform/agent-vault/revoke-a-session), the proxy stops attaching credentials to the agent's requests within one [poll interval](/documentation/platform/agent-vault/proxies#poll-interval).

## Label a session

A label is a short description of what a session is for, such as `nightly deploy` or `support ticket triage`. If one identity creates many sessions, you can use the labels to tell the sessions apart on the **Sessions** page and to search for them. A label can be up to 128 characters, and can't contain line breaks, tabs, or invisible characters such as zero-width spaces.

You can set a label when you [create the session](/documentation/platform/agent-vault/create-a-session#session-options). You can also add, change, or remove a session's label later, even after the session expires or is revoked:

- In your Agent Vault project, go to **Sessions**, open the session's menu, and select **Add Label** or **Edit Label**
- From an agent or a script, call the [Update session](/api-reference/endpoints/agent-vault-sessions/update) endpoint, for example to record the agent's current task

## View session logs

[Session logs](/documentation/platform/agent-vault/session-logs) record every request an agent makes during a session. To view them, go to **Sessions** in your Agent Vault project and select **View Session Logs** on the session's row. You can filter and search the requests, and while the session is active, new logs keep appearing.

## Access changes

You choose the access bundle and any inline services when you create the session, and you can't change them afterwards. However, the proxy checks each session's access again once every [poll interval](/documentation/platform/agent-vault/proxies#poll-interval) (60 seconds by default). Here's how common access changes affect a session:

- If someone no longer has any grant on an access bundle, directly or through a group, their sessions for that bundle stop getting credentials
- If someone still has another grant on the bundle, such as through a group, revoking one grant doesn't affect their sessions
- If you delete an access bundle, every session scoped to it stops getting credentials (the session still lists the bundle's name)
- If you remove a service from an access bundle, or delete the service, the bundle's sessions stop getting that service's credential
- If you remove someone from the project, the proxy refuses every request on their sessions
- If the user or machine identity that created a session loses the **Admin** role in the project, the session stops getting credentials for its [inline services](/documentation/platform/agent-vault/inline-services)

None of these changes removes the [skills](/documentation/platform/agent-vault/skills) that the CLI already installed on the agent's host. To stop agents from using those skills, [delete the installed copies](/documentation/platform/agent-vault/skills#remove-installed-skills).

<Note>
If a session stops getting credentials because of a lost grant, a deleted bundle, or a lost **Admin** role, the proxy still forwards the agent's requests, without credentials. The proxy's [traffic policy](/documentation/platform/agent-vault/proxies#traffic-policy) sets which hosts those requests can still reach.
</Note>

## Audit trail

When you create a session, change its label, or revoke it, Infisical writes an audit event. To review these events, open **Audit Logs** in your Agent Vault project, or scope an [audit log stream](/documentation/platform/audit-log-streams/audit-log-streams) to the Agent Vault product.

Audit events record changes in Infisical, not the agent's requests. To see the requests an agent made while its session was running, [view its session logs](#view-session-logs).
