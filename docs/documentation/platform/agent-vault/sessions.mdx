---
title: "Sessions"
description: "Time-bound grants that let AI agents access services without holding real credentials."
---

A session is a time-bound grant in an [Agent Vault project](/documentation/platform/agent-vault/projects), and it works only through a proxy in that project. It's scoped to the [services](/documentation/platform/agent-vault/services) you give it when you create it. Infisical returns a session token that identifies the session, and the agent uses that token to authenticate to the [proxy](/documentation/platform/agent-vault/proxies) on every outbound request. The proxy then attaches the real credential from the matching service before it forwards the request.

A session also gives the agent [skills](/documentation/platform/agent-vault/skills): its access bundle's, skills in the project that you pick, and skills you send with the session. The CLI installs them when the agent starts.

You choose how long a session lasts when you create it. After the session expires, or after [you revoke it](/documentation/platform/agent-vault/revoke-a-session), the proxy stops attaching credentials to the agent's requests within one [poll interval](/documentation/platform/agent-vault/proxies#poll-interval).

## Label a session and add metadata

A label is a short description of what a session is for, such as `nightly deploy` or `support ticket triage`. If one identity creates many sessions, you can use the labels to tell the sessions apart on the **Sessions** page and to search for them. A label can be up to 128 characters, and can't contain line breaks, tabs, or invisible characters such as zero-width spaces.

Metadata is a set of keys and values that record which run a session belongs to, such as the run ID, the ticket, or the user or Slack channel the agent works for. A session can have up to 20 metadata keys. A key can be up to 255 characters and a value up to 1020, and neither can contain line breaks, tabs, or invisible characters. A value can't be empty, and a key can't contain `=`.

To add a label and metadata when you create a session:

<Tabs>
  <Tab title="Dashboard">
    In the **Create Session** dialog, on the **Create Now** tab, enter a **Label**. To add metadata, select **Add Metadata**, then enter a key and a value. Select **Add Metadata** again for each other key.
  </Tab>
  <Tab title="CLI">
    Pass `--label`, and pass `--metadata` once for each key, as `key=value`. The value is everything after the first `=`. Both flags work with `infisical agent-vault sessions create` and with `infisical agent-vault run --access-bundle`:

    ```bash
    infisical agent-vault sessions create --access-bundle <bundle-name> \
      --label "nightly deploy" --metadata runId=8812 --metadata ticket=OPS-142
    ```
  </Tab>
  <Tab title="Python SDK">
    Pass `label` and a `metadata` dictionary to `client.agent_vault.sessions.create`:

    ```python
    session = client.agent_vault.sessions.create(
        project_id="<project-id>",
        access_bundle="<access-bundle-name>",
        label="nightly deploy",
        metadata={"runId": "8812"}
    )
    ```
  </Tab>
</Tabs>

You can change a session's label and metadata later, even after the session expires or is revoked:

- In your Agent Vault project, go to **Sessions**, open the session's menu, and select **Edit Session**
- From an agent or a script, call the [Update session](/api-reference/endpoints/agent-vault-sessions/update) endpoint, for example to record what the agent is working on (if you send `metadata`, it replaces all of the session's metadata)

<Frame>
  <img src="/images/platform/agent-vault/session-actions.png" alt="The Sessions page with the menu of the Nightly deploy session open, showing View Session Logs, Edit Label, and Revoke Session" />
</Frame>

To find the sessions of a run, list sessions by metadata with the [List sessions](/api-reference/endpoints/agent-vault-sessions/list) endpoint or an SDK. A session is listed only if it matches every key and value you pass:

<Tabs>
  <Tab title="Python SDK">
    ```python
    sessions = client.agent_vault.sessions.list(project_id="<project-id>", metadata={"runId": "8812"})
    ```
  </Tab>
  <Tab title="Node SDK">
    ```typescript
    const { sessions } = await client.agentVault().sessions.list({ projectId: "<project-id>", metadata: { runId: "8812" } });
    ```
  </Tab>
</Tabs>

## View session logs

[Session logs](/documentation/platform/agent-vault/session-logs) record every request an agent makes during a session. To view them, go to **Sessions** in your Agent Vault project and select **View Session Logs** on the session's row. You can filter and search the requests, and while the session is active, new logs keep appearing.

## Access changes

You choose a session's services and skills when you create it, and you can't change them afterwards. However, the proxy checks each session's access again once every [poll interval](/documentation/platform/agent-vault/proxies#poll-interval) (60 seconds by default). Here's how common access changes affect a session:

- If someone no longer has any grant on an access bundle, directly or through a group, their sessions for that bundle stop getting credentials
- If someone still has another grant on the bundle, such as through a group, revoking one grant doesn't affect their sessions
- If you delete an access bundle, every session scoped to it stops getting credentials (the session still lists the bundle's name)
- If you remove a service from an access bundle, the bundle's sessions stop getting that service's credential
- If you delete a service, every session that uses it stops getting the service's credential
- If someone loses access to a service they picked for a session, the session stops getting that service's credential
- If you remove someone from the project, the proxy refuses every request on their sessions
- If the user or machine identity that created a session loses the **Admin** role in the project, the session stops getting credentials for its [inline services](/documentation/platform/agent-vault/inline-services)
- If someone loses access to a skill they picked for a session, agents that start with the session afterwards don't get the skill
- If you delete a skill, agents that start afterwards don't get it

None of these changes removes the [skills](/documentation/platform/agent-vault/skills) that the CLI already installed on the agent's host. To stop agents from using those skills, delete the installed copies.

<Note>
If a session stops getting credentials because of a lost grant, a deleted bundle, or a lost **Admin** role, the proxy still forwards the agent's requests, without credentials. The proxy's [traffic policy](/documentation/platform/agent-vault/proxies#traffic-policy) sets which hosts those requests can still reach.
</Note>

## Audit trail

When you create a session, change its label, or revoke it, Infisical writes an audit event. To review these events, open **Audit Logs** in your Agent Vault project, or scope an [audit log stream](/documentation/platform/audit-log-streams/audit-log-streams) to the Agent Vault product.

Audit events record changes in Infisical, not the agent's requests. To see the requests an agent made while its session was running, [view its session logs](#view-session-logs).
