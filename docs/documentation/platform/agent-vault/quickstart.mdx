This quickstart walks you through the setup shared by every Agent Vault workflow. You'll create an [Agent Vault project](/documentation/platform/agent-vault/projects), create an [access bundle](/documentation/platform/agent-vault/access-bundles), add a [service](/documentation/platform/agent-vault/services) for each key your agent uses, and then continue with the guide for where your agent runs.

## Prerequisites

- An Infisical organization where you can create projects (organization admins and members can by default)
- The API keys your agent uses, such as its model provider's key

## Step 1: Create an Agent Vault project

An Agent Vault project holds the credentials, members, and proxies for one agentic system or team. If you already have a project for this agent, such as **My first project**, open it and skip to [Step 2](#step-2-add-your-credentials).

<Steps>
  <Step>
    On your organization's overview in Infisical, select **Agent Vault**.
  </Step>
  <Step>
    Select **New Project**, enter a **Project Name**, then select **Create Project**.

    <Frame>
      <img src="/images/platform/agent-vault/project-create.png" alt="The Create a New Agent Vault Project dialog, with a project name, a description, and a Create Project button" />
    </Frame>
  </Step>
</Steps>

You become the project's admin.

## Step 2: Add your credentials

<Tabs>
  <Tab title="Infisical dashboard">
    ### Create an access bundle

    In Agent Vault, an [access bundle](/documentation/platform/agent-vault/access-bundles) defines the [services](/documentation/platform/agent-vault/services) your agents can reach. To create an access bundle:

    <Steps>
      <Step>
        In your Agent Vault project, go to **Access Bundles**.
      </Step>
      <Step>
        Select **Create Access Bundle**. Give the access bundle a **Name**, such as `code-review`, then select **Create Access Bundle**.

        <Frame>
          <img src="/images/platform/agent-vault/access-bundle-create.png" alt="The Create Access Bundle dialog with a name and a description entered" />
        </Frame>
      </Step>
    </Steps>

    ### Add a service

    Next, add a service for each key your agent uses.

    <Accordion title="What services do I need?">
      - Its model provider's API key, such as `ANTHROPIC_API_KEY`, if the agent uses one
      - Each API it calls, such as GitHub
      - For a messaging gateway, the platform's token (see the keys that [Hermes](/documentation/platform/agent-vault/guides/hermes-gateway#step-1-list-the-api-keys-hermes-uses) or [OpenClaw](/documentation/platform/agent-vault/guides/openclaw-gateway#step-1-list-the-api-keys-openclaw-uses) uses)
      - Each remote MCP server it connects to, such as Linear's, which you can sign in to with OAuth instead of a key (see [add an MCP server](/documentation/platform/agent-vault/mcp-servers#add-an-mcp-server))
    </Accordion>

    <Steps>
      <Step>
        In the access bundle, select **Add Service**.
      </Step>
      <Step>
        On the **Choose a template** panel, pick the template for the API, or select **Custom HTTP API**.

        <Frame>
          <img src="/images/platform/agent-vault/service-template-picker.png" alt="The Choose a template panel with MCP server templates and HTTP API templates, GitHub among them" />
        </Frame>
      </Step>
      <Step>
        On the **Details** step, check the hosts the service covers, or enter the API's host if you selected **Custom HTTP API**. Select **Continue**.

        <Frame>
          <img src="/images/platform/agent-vault/service-details.png" alt="The Details step of a GitHub service, with api.github.com as the host" />
        </Frame>
      </Step>
      <Step>
        On the **Credential** step, paste the real key, then select **Continue**.

        <Note>
          If the API takes the key somewhere other than a header, such as a bot token in the URL, [add a substitution](/documentation/platform/agent-vault/http-apis#add-a-substitution) instead. Your agent sends the placeholder you enter in **Replace**.
        </Note>
      </Step>
      <Step>
        On the **Review** step, select **Add Service**. Repeat from the first step for each remaining key.
      </Step>
    </Steps>
  </Tab>
  <Tab title="API">
    ### Log in as a machine identity

    You call the Infisical API as a [machine identity](/documentation/platform/identities/machine-identities) with the **Admin** role in your Agent Vault project.

    <Steps>
      <Step>
        In your Agent Vault project, go to **Access Control** > **Machine Identities** and select **Add Machine Identity**.
      </Step>
      <Step>
        On the **Create New** tab, enter a **Name**, choose **Admin** in **Role**, then select **Create**.
      </Step>
      <Step>
        On the machine identity's page, select **Universal Auth** under **Authentication**. Copy the **Client ID**, then select **Add Client Secret** and copy the client secret.
      </Step>
    </Steps>

    Use this machine identity only for setup. If your agents' sessions come from code, the guide for your agents has you create a separate machine identity with access to only one access bundle.

    Call [the login endpoint for Universal Auth](/api-reference/endpoints/universal-auth/login) with the client ID and client secret:

    <CodeGroup>
      ```bash US Cloud
      curl -X POST https://app.infisical.com/api/v1/auth/universal-auth/login \
        -H "Content-Type: application/json" \
        -d '{"clientId": "<client-id>", "clientSecret": "<client-secret>"}'
      ```

      ```bash EU Cloud
      curl -X POST https://eu.infisical.com/api/v1/auth/universal-auth/login \
        -H "Content-Type: application/json" \
        -d '{"clientId": "<client-id>", "clientSecret": "<client-secret>"}'
      ```

      ```bash Self-hosted
      curl -X POST <your-instance-url>/api/v1/auth/universal-auth/login \
        -H "Content-Type: application/json" \
        -d '{"clientId": "<client-id>", "clientSecret": "<client-secret>"}'
      ```
    </CodeGroup>

    The response includes an `accessToken`, which you send with each request in the next steps.

    ### Copy the project ID

    Requests that create something in Agent Vault take the ID of the project to create it in. In your Agent Vault project, go to **Administration** > **Settings** and copy the **Project ID**.

    <Frame>
      <img src="/images/platform/agent-vault/project-settings-general.png" alt="The General settings of an Agent Vault project, with the Project ID and its copy button in the Project Overview card" />
    </Frame>

    ### Create an access bundle

    In Agent Vault, an [access bundle](/documentation/platform/agent-vault/access-bundles) defines the [services](/documentation/platform/agent-vault/services) your agents can reach. Call [the endpoint to create an access bundle](/api-reference/endpoints/agent-vault-access-bundles/create), replacing `<access-token>` with the `accessToken` from the login response and `<project-id>` with the project ID. In the body, send the project ID and a name for the access bundle:

    <CodeGroup>
      ```bash US Cloud
      curl -X POST https://app.infisical.com/api/v1/agent-vault/access-bundles \
        -H "Authorization: Bearer <access-token>" \
        -H "Content-Type: application/json" \
        -d '{"projectId": "<project-id>", "name": "code-review"}'
      ```

      ```bash EU Cloud
      curl -X POST https://eu.infisical.com/api/v1/agent-vault/access-bundles \
        -H "Authorization: Bearer <access-token>" \
        -H "Content-Type: application/json" \
        -d '{"projectId": "<project-id>", "name": "code-review"}'
      ```

      ```bash Self-hosted
      curl -X POST <your-instance-url>/api/v1/agent-vault/access-bundles \
        -H "Authorization: Bearer <access-token>" \
        -H "Content-Type: application/json" \
        -d '{"projectId": "<project-id>", "name": "code-review"}'
      ```
    </CodeGroup>

    The response includes the access bundle's `id`, which you need to add a service.

    ### Add a service

    Add a service for each key your agent uses.

    <Accordion title="What services do I need?">
      - Its model provider's API key, such as `ANTHROPIC_API_KEY`, if the agent uses one
      - Each API it calls, such as GitHub
      - For a messaging gateway, the platform's token (see the keys that [Hermes](/documentation/platform/agent-vault/guides/hermes-gateway#step-1-list-the-api-keys-hermes-uses) or [OpenClaw](/documentation/platform/agent-vault/guides/openclaw-gateway#step-1-list-the-api-keys-openclaw-uses) uses)
      - Each remote MCP server it connects to, such as Linear's (see [add an MCP server](/documentation/platform/agent-vault/mcp-servers#add-an-mcp-server))
    </Accordion>

    Call [the endpoint to create a service](/api-reference/endpoints/agent-vault-services/create), replacing `<access-bundle-id>` in the URL with the `id` from the previous step and `<access-token>` with the `accessToken` from the login response.
    
    In the body, send the hosts that the credential applies to and the credential itself. For example, to add a GitHub personal access token:

    <CodeGroup>
      ```bash US Cloud
      curl -X POST https://app.infisical.com/api/v1/agent-vault/access-bundles/<access-bundle-id>/services \
        -H "Authorization: Bearer <access-token>" \
        -H "Content-Type: application/json" \
        -d '{
          "type": "http",
          "name": "github",
          "hostPattern": "api.github.com, github.com",
          "credential": {
            "type": "basic",
            "username": "x-access-token",
            "password": "<github-token>"
          }
        }'
      ```

      ```bash EU Cloud
      curl -X POST https://eu.infisical.com/api/v1/agent-vault/access-bundles/<access-bundle-id>/services \
        -H "Authorization: Bearer <access-token>" \
        -H "Content-Type: application/json" \
        -d '{
          "type": "http",
          "name": "github",
          "hostPattern": "api.github.com, github.com",
          "credential": {
            "type": "basic",
            "username": "x-access-token",
            "password": "<github-token>"
          }
        }'
      ```

      ```bash Self-hosted
      curl -X POST <your-instance-url>/api/v1/agent-vault/access-bundles/<access-bundle-id>/services \
        -H "Authorization: Bearer <access-token>" \
        -H "Content-Type: application/json" \
        -d '{
          "type": "http",
          "name": "github",
          "hostPattern": "api.github.com, github.com",
          "credential": {
            "type": "basic",
            "username": "x-access-token",
            "password": "<github-token>"
          }
        }'
      ```
    </CodeGroup>

    Set `credential.type` to `bearer` for an API that takes a token in a header, `basic` for an API that takes a username and password, or `passthrough` for a host that the agent can call without a credential.
    
    <Note>
    For a key that goes somewhere other than a header, set `credential` to `{"type": "passthrough"}` and send the key as a [substitution](/documentation/platform/agent-vault/http-apis#substitutions):

    ```json
    "credential": { "type": "passthrough" },
    "substitutions": [
      { "placeholder": "__TELEGRAM_BOT_TOKEN__", "surfaces": ["path"], "value": "<telegram-bot-token>" }
    ]
    ```
    </Note>

    Repeat this request for each remaining key.
  </Tab>
</Tabs>
