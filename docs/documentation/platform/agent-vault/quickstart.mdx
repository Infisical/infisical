By the end of this page an agent calls the GitHub API through an Agent Vault proxy, and the only thing the agent ever holds is a session token that works nowhere else.

You'll do four things: create an access bundle with one connection, enroll a proxy, mint a session, and run an agent with it.

## Prerequisites

- An Infisical organization where you're an Agent Vault admin. Org admins are Agent Vault admins by default.
- The [Infisical CLI](/cli/overview) installed where the proxy will run and where the agent will run. For this page that can be one machine.
- A GitHub personal access token to use as the credential. Any token that can call `GET /user` will do.

## 1. Create an access bundle with a connection

In the dashboard, open **Agent Vault** from the product switcher and go to **Access Bundles**. Select **Create Access Bundle**, name it `coding-agent`, and open it.

Select **Add Connection**. Pick the **GitHub** template, keep the hosts it fills in, paste your token into **Token**, and select **Add Connection** on the review step.

The connection now says what the proxy will send: `Authorization: Bearer <your token>` on requests to `api.github.com`, and nothing anywhere else.

<Note>
  The template fills in the hosts and how the header is built. A custom connection lets you set the header name and prefix yourself, for APIs that expect `X-API-Key` or a bare token. See [Access bundles and connections](/documentation/platform/agent-vault/access-bundles).
</Note>

You're an admin, so you can already mint sessions over this bundle. To let a teammate run agents with it, select **Grant Access** on the bundle and pick their user, machine identity, or group. They have to be a member of Agent Vault first, under **Access Control**.

## 2. Create and enroll a proxy

Go to **Proxies** and select **Create Proxy**. Name it `egress`, leave **Uncovered Hosts** on **Allow**, and select **Create Proxy**.

The dialog that follows shows a one-time enrollment token and the command to run. On the machine that will be the proxy:

```bash
infisical av proxy --enrollment-token <enrollment-token>
```

The proxy enrolls, generates its own certificate authority, and starts listening on port `17323`. Leave it running. Its status on the Proxies page turns to **Healthy** within a minute.

<Note>
  The enrollment token is shown once and expires in an hour. Run the same command again on a restart: the proxy remembers it has enrolled and serves without asking Infisical for a new token. For Docker and systemd the same dialog has ready-made snippets.
</Note>

## 3. Mint a session

Go to **Sessions** and select **Create Session**. Add `coding-agent`, leave the lifetime at 7 days, and select **Create Session**.

The token appears once, with the command to run. Copy it now: nothing stores the token, and the dialog can't be reopened.

A session carries a fixed set of bundles and an expiry, and nothing else. The proxy re-checks what the agent may use on every poll, so revoking the session or removing a grant stops the credentials flowing within a minute. See [Sessions](/documentation/platform/agent-vault/sessions).

## 4. Run an agent with it

On the machine where the agent runs, pass the token and the proxy address:

```bash
infisical av run --token <session-token> --proxy 10.0.1.5:17323 -- claude
```

The CLI fetches the proxy's certificate authority, trusts it for the agent, and starts `claude` with its HTTP traffic routed through the proxy. Everything after `--` is the agent's own command.

That machine needs no Infisical login. The only thing on it is the session token, which identifies the agent to a proxy in your organization. The credentials stay on the proxy.

Use the address the proxy answers on from where the agent runs. The same proxy has a different address from every network, which is why you pass it rather than pick it from a list.

<Note>
  Working on your own machine and signed in with `infisical login`? You can skip the dashboard. `infisical av run --access-bundle coding-agent --proxy 10.0.1.5:17323 -- claude` mints a session over the bundle and revokes it when the agent exits.
</Note>

## Verify it works

Inside the agent, ask it to call GitHub:

> Run `curl -sS https://api.github.com/user` and show me the output.

GitHub answers with your profile. The agent sent no `Authorization` header; the proxy added it on the way out. Run the same `curl` outside the agent and GitHub answers `401`, because the agent never held the token.

Not driving an interactive agent? Run the check directly:

```bash
infisical av run --token <session-token> --proxy 10.0.1.5:17323 -- curl -sS https://api.github.com/user
```

The CLI prints which hosts the session can reach before the agent starts, so a `401` from GitHub with `api.github.com:443` missing from that list means the bundle no longer covers it, and a `401` with it present means the token itself is wrong.
