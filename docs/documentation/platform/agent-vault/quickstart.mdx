By the end of this page an agent calls the GitHub API through an Agent Vault proxy. The only thing the agent holds is a session token that works nowhere else.

## Prerequisites

- An Infisical organization where you're an Agent Vault admin. Organization admins are Agent Vault admins by default.
- The [Infisical CLI](/cli/overview) installed on the machine that will run the proxy and on the machine that will run the agent. For this page they can be the same machine.
- A GitHub personal access token. Any token that can call `GET /user` will do.

<Steps>
  <Step title="Create an access bundle with a connection">
    Open **Agent Vault** from the product switcher and go to **Access Bundles**. Select **Create Access Bundle**, name it `coding-agent`, and open it.

    Select **Add Connection**, pick the **GitHub** template, paste your token into **Token**, and select **Add Connection** on the review step.

    The connection now sends `Authorization: Bearer <your token>` on requests to `api.github.com`, and nothing anywhere else.
  </Step>

  <Step title="Create and enroll a proxy">
    Go to **Proxies**, select **Create Proxy**, name it `egress`, and select **Create Proxy**.

    The dialog shows a one-time enrollment token and the command to run. On the machine that will be the proxy:

    ```bash
    infisical av proxy --enrollment-token <enrollment-token>
    ```

    The proxy enrolls and starts listening on port `17323`. Leave it running. Within a minute its status on the Proxies page turns to **Healthy**.

    <Note>
      The enrollment token expires in an hour. Running the same command again on a restart is fine: the proxy remembers it has enrolled. The dialog also has Docker and systemd snippets.
    </Note>
  </Step>

  <Step title="Mint a session">
    Go to **Sessions**, select **Create Session**, add `coding-agent`, and select **Create Session**.

    The token appears once, with the command to run. Copy it now.
  </Step>

  <Step title="Run the agent">
    On the machine where the agent runs:

    ```bash
    infisical av run --session-token <session-token> --proxy 10.0.1.5:17323 -- claude
    ```

    Use the address the proxy answers on from where the agent runs. Everything after `--` is the agent's own command.

    The CLI trusts the proxy's certificate for the agent and starts `claude` with its HTTP traffic routed through the proxy. That machine needs no Infisical login.
  </Step>
</Steps>

## Verify it works

Inside the agent, ask it to call GitHub:

> Run `curl -sS https://api.github.com/user` and show me the output.

GitHub answers with your profile. The agent sent no `Authorization` header; the proxy added it on the way out. Run the same `curl` outside the agent and GitHub answers `401`.

To check without an interactive agent:

```bash
infisical av run --session-token <session-token> --proxy 10.0.1.5:17323 -- curl -sS https://api.github.com/user
```

<Note>
  Working on your own machine and signed in with `infisical login`? Skip the Sessions page: `infisical av run --access-bundle coding-agent --proxy 10.0.1.5:17323 -- claude` mints a session for you and revokes it when the agent exits. A machine identity can do the same with `--client-id` and `--client-secret`.
</Note>
