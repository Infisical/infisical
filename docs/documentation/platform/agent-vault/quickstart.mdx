This quickstart walks you through the setup shared by every Agent Vault workflow. You'll create an [access bundle](/documentation/platform/agent-vault/access-bundles), add a [service](/documentation/platform/agent-vault/services) with the real credentials for each API your agents call, and then continue with the guide for where your agents run.

## Prerequisites

- An Infisical organization where you're an [Agent Vault admin](/documentation/platform/agent-vault/access-control#product-membership)
- Credentials for each API you want your agents to call (such as an API token)

## Step 1: Add your credentials

<Tabs>
  <Tab title="Infisical dashboard">
    ### Create an access bundle

   In Agent Vault, an [access bundle](/documentation/platform/agent-vault/access-bundles) defines the [services](/documentation/platform/agent-vault/services) your agents can reach. To create an access bundle:

    <Steps>
      <Step>
        In Infisical, open **Agent Vault** from the product switcher and go to **Access Bundles**.
      </Step>
      <Step>
        Select **Create Access Bundle**. Give the access bundle a **Name**, then select **Create Access Bundle**.

        <Frame>
          <img src="/images/platform/agent-vault/access-bundle-create.png" alt="The Create Access Bundle dialog with code-review entered as the name" />
        </Frame>
      </Step>
    </Steps>

    ### Add a service

    <Steps>
      <Step>
        Select the access bundle you just created, then select **Add Service**.
      </Step>
      <Step>
        Find the template for the API you want your agents to call, then select it.

        <Frame>
          <img src="/images/platform/agent-vault/service-template-picker.png" alt="The Choose a template panel with GitHub among the available services" />
        </Frame>

        If the API isn't on the list, select **Custom** and set the host, header name, and prefix yourself.
      </Step>
      <Step>
        The template fills in the host and the header that the API expects. Paste your credential in the **Credential** section.
      </Step>
      <Step>
        Select **Add Service**.
      </Step>
    </Steps>

    Repeat these steps for each API your agents call.
  </Tab>
  <Tab title="API">
    ### Log in as a machine identity

    You call the Infisical API as a [machine identity](/documentation/platform/identities/machine-identities) with the **Admin** role in Agent Vault.

    <Steps>
      <Step>
        In Agent Vault, go to **Access Control** > **Machine Identities** and select **Add Machine Identity**.
      </Step>
      <Step>
        On the **Create New** tab, enter a **Name**, choose **Admin** in **Role**, then select **Create**.
      </Step>
      <Step>
        On the machine identity's page, select **Universal Auth** under **Authentication**. Copy the **Client ID**, then select **Add Client Secret** and copy the client secret.
      </Step>
    </Steps>

    Call [the login endpoint for Universal Auth](/api-reference/endpoints/universal-auth/login) with the client ID and client secret:

    <CodeGroup>
      ```bash US Cloud
      curl -X POST https://app.infisical.com/api/v1/auth/universal-auth/login \
        -H "Content-Type: application/json" \
        -d '{"clientId": "<client-id>", "clientSecret": "<client-secret>"}'
      ```

      ```bash EU Cloud
      curl -X POST https://eu.infisical.com/api/v1/auth/universal-auth/login \
        -H "Content-Type: application/json" \
        -d '{"clientId": "<client-id>", "clientSecret": "<client-secret>"}'
      ```

      ```bash Self-hosted
      curl -X POST <your-instance-url>/api/v1/auth/universal-auth/login \
        -H "Content-Type: application/json" \
        -d '{"clientId": "<client-id>", "clientSecret": "<client-secret>"}'
      ```
    </CodeGroup>

    The response includes an `accessToken`, which you send with each request in the next steps.

    ### Create an access bundle

    Call [the endpoint to create an access bundle](/api-reference/endpoints/agent-vault-access-bundles/create), replacing `<access-token>` with the `accessToken` from the login response. In the body, send a name for the access bundle:

    <CodeGroup>
      ```bash US Cloud
      curl -X POST https://app.infisical.com/api/v1/agent-vault/access-bundles \
        -H "Authorization: Bearer <access-token>" \
        -H "Content-Type: application/json" \
        -d '{"name": "code-review"}'
      ```

      ```bash EU Cloud
      curl -X POST https://eu.infisical.com/api/v1/agent-vault/access-bundles \
        -H "Authorization: Bearer <access-token>" \
        -H "Content-Type: application/json" \
        -d '{"name": "code-review"}'
      ```

      ```bash Self-hosted
      curl -X POST <your-instance-url>/api/v1/agent-vault/access-bundles \
        -H "Authorization: Bearer <access-token>" \
        -H "Content-Type: application/json" \
        -d '{"name": "code-review"}'
      ```
    </CodeGroup>

    The response includes the access bundle's `id`, which you need to add a service.

    ### Add a service

    Call [the endpoint to create a service](/api-reference/endpoints/agent-vault-services/create), replacing `<access-bundle-id>` in the URL with the `id` from the previous step and `<access-token>` with the `accessToken` from the login response.
    
    In the body, send the hosts that the credential applies to and the credential itself. For example, to add a GitHub personal access token:

    <CodeGroup>
      ```bash US Cloud
      curl -X POST https://app.infisical.com/api/v1/agent-vault/access-bundles/<access-bundle-id>/services \
        -H "Authorization: Bearer <access-token>" \
        -H "Content-Type: application/json" \
        -d '{
          "name": "github",
          "hostPattern": "api.github.com, github.com",
          "credential": {
            "type": "basic",
            "username": "x-access-token",
            "password": "<github-token>"
          }
        }'
      ```

      ```bash EU Cloud
      curl -X POST https://eu.infisical.com/api/v1/agent-vault/access-bundles/<access-bundle-id>/services \
        -H "Authorization: Bearer <access-token>" \
        -H "Content-Type: application/json" \
        -d '{
          "name": "github",
          "hostPattern": "api.github.com, github.com",
          "credential": {
            "type": "basic",
            "username": "x-access-token",
            "password": "<github-token>"
          }
        }'
      ```

      ```bash Self-hosted
      curl -X POST <your-instance-url>/api/v1/agent-vault/access-bundles/<access-bundle-id>/services \
        -H "Authorization: Bearer <access-token>" \
        -H "Content-Type: application/json" \
        -d '{
          "name": "github",
          "hostPattern": "api.github.com, github.com",
          "credential": {
            "type": "basic",
            "username": "x-access-token",
            "password": "<github-token>"
          }
        }'
      ```
    </CodeGroup>

    Set `credential.type` to `bearer` for an API that takes a token in a header, `basic` for an API that takes a username and password, or `passthrough` for a host that the agent can call without a credential.

    Repeat this request for each API your agents call.
  </Tab>
</Tabs>

## Step 2: Connect your agents

Pick the guide for where your agents run. Each guide walks you through setting up a [proxy](/documentation/platform/agent-vault/proxies) and creating [sessions](/documentation/platform/agent-vault/sessions) for your agents.

<Tip>
If you're not sure which guide fits, [plan your setup](/documentation/platform/agent-vault/plan-your-setup) to get a recommendation.
</Tip>
