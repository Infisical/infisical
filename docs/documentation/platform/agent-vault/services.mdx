---

A service is something your agent talks to during a [session](/documentation/platform/agent-vault/sessions), such as an API, an MCP server, a database, or an SSH server, that Agent Vault brokers credentials for. You store the real credential on the service, and the [proxy](/documentation/platform/agent-vault/proxies) adds it to the agent's requests to that service, or logs in with it. The agent can authenticate to the service without ever holding the credential.

You can configure services within an [access bundle](/documentation/platform/agent-vault/access-bundles), or an admin can send them with a session as [inline services](/documentation/platform/agent-vault/inline-services) when creating it through the API. For example, you might create a **code-review** access bundle and add services for Slack, GitHub, and Anthropic:

## Service types

You choose a service's type when you pick its template:

<CardGroup cols={2}>
  <Card title="HTTP APIs" icon="globe" href="/documentation/platform/agent-vault/http-apis">
    Web APIs that the agent calls directly, such as GitHub, Slack, and Anthropic.
  </Card>
  <Card title="MCP servers" icon="server" href="/documentation/platform/agent-vault/mcp-servers">
    Remote MCP servers whose tools the agent calls, such as Linear and Notion.
  </Card>
  <Card title="Databases and SSH" icon="database" href="/documentation/platform/agent-vault/databases-and-ssh">
    PostgreSQL databases, MySQL databases, and SSH servers that the agent reaches with psql, mysql, or ssh.
  </Card>
</CardGroup>

## Service descriptions

To tell agents what a service is for, enter a **Description** on the **Details** step when you add or edit the service. Agents see the description when they [list the services their session can use](/documentation/platform/agent-vault/service-discovery), so don't put credentials or other secrets in a description.
