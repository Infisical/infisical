title: "Services"
description: "Anything an AI agent talks to during a session, such as an API, an MCP server, a database, or an SSH server."
---

A service is something your agent talks to during a [session](/documentation/platform/agent-vault/sessions), such as an API, an MCP server, a database, or an SSH server, that Agent Vault brokers credentials for. You store the real credential on the service, and the [proxy](/documentation/platform/agent-vault/proxies) adds it to the agent's requests to that service, or logs in with it. The agent can authenticate to the service without ever holding the credential.

Each service belongs to an [Agent Vault project](/documentation/platform/agent-vault/projects). You define a service once, then add it to any number of [access bundles](/documentation/platform/agent-vault/access-bundles), and a session can use the services in its access bundle. For example, the **code-review** and **on-call** access bundles can both hold the same Slack service. An admin can also send services with a session as [inline services](/documentation/platform/agent-vault/inline-services) when creating the session through the API.

Every project member can open the **Services** page. A member sees the services that their access bundles give them, and [sets up their personal values](/documentation/platform/agent-vault/access-bundles#set-up-your-personal-values) for the services that need them. An admin sees every service in the project.

## Prerequisites

- The [Admin role](/documentation/platform/agent-vault/access-control#product-membership) in your Agent Vault project, to add, edit, and delete services, and to add them to access bundles

## Service types

You choose a service's type when you pick its template:

<CardGroup cols={2}>
  <Card title="HTTP APIs" icon="globe" href="/documentation/platform/agent-vault/http-apis">

  <Card title="MCP servers" icon="server" href="/documentation/platform/agent-vault/mcp-servers">

## Add a service

<Steps>
  <Step>
    In your Agent Vault project, go to **Services** and select **Add Service**.
  </Step>
  <Step>
    On the **Choose a template** panel, pick a template. The page for each [service type](#service-types) describes its steps and fields.
  </Step>
  <Step>
    On the **Review** step, select **Add Service**. The service appears in the list, and agents can use it once you [add it to an access bundle](#add-a-service-to-an-access-bundle).
  </Step>
</Steps>

To add a service through the API, call the [Create service](/api-reference/endpoints/agent-vault-services/create) endpoint. To add the new service to access bundles in the same request, send their IDs in `accessBundleIds`.

## Add a service to an access bundle

<Steps>
  <Step>
    In your Agent Vault project, go to **Access Bundles**, select the access bundle, then select **Add Service**.
  </Step>
  <Step>
    In the **Services** list, pick one or more services from the project. To create a service instead, select **Create New Service** and follow the steps for its [service type](#service-types). Infisical adds the new service to the access bundle when you save it.

    <Frame>
      <img src="/images/platform/agent-vault/access-bundle-add-services.png" alt="The Add Services dialog on the support access bundle, with orders-db and sentry picked and an Add 2 Services button" />
    </Frame>
  </Step>
  <Step>
    If you picked existing services, select **Add Service**, or **Add 2 Services** if you picked two. Sessions on the access bundle can use the services within one [poll interval](/documentation/platform/agent-vault/proxies#poll-interval).
  </Step>
</Steps>

An access bundle can't hold two services that cover the same host with the same pattern (see [host conflicts](/documentation/platform/agent-vault/http-apis#host-conflicts)). If one of the services you picked would break that rule, Infisical adds none of them, and the error names the service.

To add services through the API, call the [Add services to access bundle](/api-reference/endpoints/agent-vault-access-bundles/add-services) endpoint with up to 25 service IDs.

## Edit a service

To edit a service, go to **Services**, open the service's actions menu, and select **Edit**. A change to a service applies in every access bundle that holds it.

## Remove or delete a service

Open the service's actions menu and select one of these:

- **Remove from Bundle**, on an access bundle's page, takes the service out of that access bundle only (the service stays in the project)
- **Delete**, on the **Services** page, deletes the service from the project and from every access bundle that holds it

Sessions stop getting the service's credential within one [poll interval](/documentation/platform/agent-vault/proxies#poll-interval). If a member can no longer reach the service through any access bundle, Infisical also deletes their [personal values](/documentation/platform/agent-vault/access-bundles#set-up-your-personal-values) for it.

## Service names

Each service's name is unique in its project. Before services belonged to the project, two access bundles could each hold a service with the same name. When Infisical upgraded existing projects, the older of the two services kept its name, and Infisical renamed the other to `<name>-<access bundle name>`, such as `github-on-call`.

The agent connects to a [database or SSH service](/documentation/platform/agent-vault/databases-and-ssh) by its name, so if Infisical renamed one, update the name in your agents' `infisical agent-vault connect` commands.

## Service descriptions

To tell agents what a service is for, enter a **Description** on the **Details** step when you add or edit the service. Agents see the description when they [list the services their session can use](/documentation/platform/agent-vault/service-discovery), so don't put credentials or other secrets in a description.
