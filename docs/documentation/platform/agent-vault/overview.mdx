**Infisical Agent Vault** is where you equip AI agents with what they need to do work, starting with secure access to the services they call, including LLM providers, GitHub, Slack, and more.

Agent Vault brokers that access. Agents like Claude Code or OpenClaw route HTTP requests through an Agent Vault proxy, which attaches the real credential before forwarding the request to the target service. The agent never holds it.

```text
            Your private network                                  Public internet

+----------+                 +-------------------+                +------------------+
| AI agent | --------------> | Agent Vault proxy | -------------> |  api.slack.com   |
+----------+  request with a +-------------------+ request with   |  api.github.com  |
             session token            |          the credential   |  ...             |
                                      |                           +------------------+
                                      |  checks what this session
                                      |  may reach, and fetches
                                      |  the credentials
                                      v
                               +-------------+
                               |  Infisical  |
                               +-------------+
```

## Why Agent Vault

Traditional secrets management involves returning credentials back to applications and services.

This is not suitable for AI agents because they are vulnerable to credential exfiltration via [prompt injection](https://en.wikipedia.org/wiki/Prompt_injection); an attacker could craft a malicious prompt or payload and exfiltrate credentials from an agent back to the attacker.

Enter Infisical Agent Vault: a proxy backed by Infisical that prevents credential exfiltration by brokering access to credentials at the network boundary. The agent gets a session token that works only through your proxy, only for the services you allowed, and only until you revoke it. Access is checked while the agent runs, so pulling it takes effect within a minute, with nothing to restart.

## How it works

An admin creates an access bundle, everything an agent needs for a job granted as one unit. Today a bundle holds a connection for each service the agent may reach, with the credential the proxy applies, and names the people, machine identities, and groups allowed to run agents with it. Someone with the grant mints a session, a token that carries the bundle and an expiry, and launches the agent with it. The agent needs no code changes: the [Infisical CLI](/cli/overview) starts it with its HTTP clients pointed at a proxy you run in your own network, and the proxy applies the real credential to matching requests on the way out.
