title: "Integrations"
description: "Connect Agent Vault to the third-party services it needs, and decide whether a credential belongs to Agent Vault or to the whole organization."
---

A few Agent Vault features reach a service outside Infisical. [Activity logs](/documentation/platform/agent-vault/activity-logs) write to an S3 bucket you own, and that takes AWS credentials. Those credentials are stored as an [app connection](/documentation/getting-started/concepts/app-connections), and **Integrations** is where Agent Vault's live.

The page is visible to Agent Vault administrators only.

## Two places a connection can live

A connection is scoped either to your organization or to Agent Vault, and the choice decides who else can reach it.

| Scope | Where you create it | Which products can use it |
| --- | --- | --- |
| Organization | **Integrations** at the organization level | every product, including Agent Vault |
| Agent Vault | **Integrations** under Agent Vault | Agent Vault only |

Both scopes are available to Agent Vault. Every connection dropdown in the product lists its own connections alongside the organization's, with the organization's marked so the two are easy to tell apart.

Pick the Agent Vault scope when the credential exists for Agent Vault and nothing else, so a bucket holding session activity isn't reachable from a secret sync. Pick the organization scope for a credential several products share.

Scope is fixed when the connection is created. Moving one means creating it again in the other scope and updating whatever used it, so it's worth a moment's thought up front.

## Adding a connection

Go to **Integrations** under Agent Vault, select **Add Connection**, and follow the form for the service you're connecting to.

You can also add one without leaving the feature that needs it. Under **Settings** → **Activity Logging** → **Configure**, the **AWS Connection** dropdown offers **Create New Connection**, and the connection it creates is scoped to Agent Vault and selected for you.

## Supported services

Agent Vault supports **AWS** connections. Activity log storage is the only feature that reaches an outside service today, and it writes to S3.

Organization-level connections of any type still appear in those dropdowns. The limit is on what you can create under Agent Vault, not on what it can use.

## Managing connections through the API

Agent Vault has its own endpoints, under `/api/v1/agent-vault/app-connections`. Use them rather than the general app connection endpoints, which need a project ID that Agent Vault doesn't expose.

```bash
curl --request POST \
  --url https://app.infisical.com/api/v1/agent-vault/app-connections/aws \
  --header 'Authorization: Bearer <token>' \
  --header 'Content-Type: application/json' \
  --data '{
    "name": "agent-vault-activity",
    "method": "access-key",
    "credentials": {
      "accessKeyId": "<access-key-id>",
      "secretAccessKey": "<secret-access-key>"
    }
  }'
```

Everything these endpoints return is scoped to Agent Vault. A connection belonging to your organization answers `404` here; manage it through the organization's own endpoints instead.

To reach an existing connection, add its ID: `GET`, `PATCH` and `DELETE` on
`/api/v1/agent-vault/app-connections/aws/<connection-id>`, and `POST` on
`/api/v1/agent-vault/app-connections/aws/<connection-id>/rotate-credentials`.

## Deleting a connection

Nothing blocks you from deleting a connection activity logging is using, and recording stops within one poll interval on every proxy. The bucket and prefix survive, so the credential is the only missing piece: pick another connection under **Settings** → **Activity Logging** and recording resumes.

Nothing already written to your bucket is deleted. Those objects stay where they are, and Infisical can't read them until a connection that reaches the bucket is configured again.
