A skill is a folder of instructions that an AI agent loads when a task needs it, such as how your team reviews pull requests or how to cut a release. Skills follow the [Agent Skills](https://agentskills.io) format, so the same folder works in Claude Code, Codex, and other agents that support it.

An [access bundle](/documentation/platform/agent-vault/access-bundles) defines which APIs an agent can call. If you attach a skill to an access bundle, the CLI installs the skill for each agent that you start with that access bundle through `infisical agent-vault run`. Agents get their skills when they start, so to pick up a change to a skill, restart the agent.

<Info>
  Only Agent Vault admins can add, change, attach, and delete skills. [Agent Vault members](/documentation/platform/agent-vault/access-control#product-membership) can view the latest version of each skill attached to the access bundles granted to them.
</Info>

## Skill format

A skill is a folder with a `SKILL.md` file at its root. `SKILL.md` starts with a header that names and describes the skill, followed by the instructions in Markdown:

```markdown
---
name: code-review
description: Reviews a pull request against the team checklist. Use when asked to review code.
---

# Code review

1. Read the diff and the linked issue.
2. Check each item in checklist.md.
```

- `name`: the name agents know the skill by, with up to 64 lowercase letters, numbers, and single hyphens. The name can't be one that Windows reserves for devices, such as `con`, `aux`, or `com1`
- `description`: the text an agent reads to decide when to use the skill (up to 1,024 characters)

The folder can also hold other files that the instructions refer to, such as scripts, templates, or reference documents. Each skill can hold:

- Up to 50 files
- Up to 256 KB per file
- Up to 1 MB in total

## Add a skill

You can push a skill folder with the CLI, or create the skill in Infisical.

<Tabs>
  <Tab title="CLI">
    Log in to the CLI as an Agent Vault admin, then run the following command on the host that has the skill folder:

    ```bash
    infisical agent-vault skills push <path-to-skill-folder>
    ```

    The CLI reads the skill's name from `SKILL.md`. If no skill has that name yet, the CLI creates the skill. Otherwise, the CLI publishes the folder as a new version of the existing skill.

    To push from a script or CI, authenticate as a [machine identity](/documentation/platform/identities/machine-identities) with the Admin role in Agent Vault. For the flags, see [infisical agent-vault skills push](/cli/reference#agent-vault-skills-push).
  </Tab>
  <Tab title="Infisical">
    <Steps>
      <Step>
        In Agent Vault, go to **Skills** and select **Create Skill**.
      </Step>
      <Step>
        To start from a skill you already have, select **Upload** and drop a zipped skill folder or a Markdown file into the dialog. Infisical fills in the **Name**, the **Description**, and the files from the upload.

        To write the skill instead, enter a **Name** and a **Description**, then write the instructions in `SKILL.md`. To add more files, follow the steps in [Change the files](#change-the-files).

        The header at the top of `SKILL.md` always matches the **Name** and **Description** fields, so you can change the name and the description in either place.
      </Step>
      <Step>
        Check the files, then select **Create Skill**.
      </Step>
    </Steps>
  </Tab>
</Tabs>

### Scripts in a skill

If you push a skill with the CLI, its scripts stay executable. If you upload a skill or write it in Infisical, its scripts aren't executable, so have `SKILL.md` tell the agent to run each script with an interpreter, such as `bash scripts/check.sh` or `python scripts/check.py`.

## Attach a skill to an access bundle

To install skills for agents, attach them to an access bundle:

<Steps>
  <Step>
    In Agent Vault, go to **Access Bundles** and select the access bundle.
  </Step>
  <Step>
    In the **Skills** section, select **Add Skills**.
  </Step>
  <Step>
    Pick one or more skills from the list, then confirm.

    <Tip>
      To add a skill that isn't in Agent Vault yet, select **Create New Skill** at the end of the list. Infisical attaches the skill to the access bundle once you create it.
    </Tip>
  </Step>
</Steps>

An access bundle can have up to 25 skills.

To detach a skill, open its actions menu in the **Skills** section, select **Remove From Bundle**, and confirm. The CLI doesn't delete copies of the skill that it already installed, so to stop agents from using the skill, [delete the installed copies](#remove-installed-skills).

## How agents get skills

When you start an agent with [`infisical agent-vault run`](/cli/reference#agent-vault-run), the CLI downloads the latest version of each skill attached to the session's access bundle from Infisical, and installs the skills before the agent starts. The CLI downloads the skills with the session's token, so the agent's host needs to reach your Infisical instance, as it already does when the CLI creates the session. If you start the agent with a session token and you don't use Infisical Cloud, set your instance with [`--domain`](/cli/reference#global-flags--flag-domain).

The CLI installs each skill in `~/.agents/skills/<skill-name>`, where Codex, OpenCode, and OpenClaw look for skills.

The CLI also adds a link to each skill in the `skills` folder of Claude Code and of Hermes, if that agent's folder exists on the host:

- Claude Code: `$CLAUDE_CONFIG_DIR`, or `~/.claude` if `CLAUDE_CONFIG_DIR` isn't set
- Hermes: `$HERMES_HOME`, or `~/.hermes` if `HERMES_HOME` isn't set

To install the skills in a different folder, pass [`--skills-dir`](/cli/reference#agent-vault-run--flag-skills-dir) with the folder's path. The CLI then installs the skills only in that folder and doesn't add links for Claude Code or Hermes.

The agent keeps the skills it started with. If you publish a new version or attach a skill, restart the agent to pick up the change.

### Installed skills stay on the host

The CLI doesn't delete the skills it installs when the agent exits, so later runs of any agent on the host can still use them.

<Warning>
  If `~/.agents/skills`, the folder you passed to `--skills-dir`, or the Claude Code or Hermes `skills` folder already has a folder with the same name as an attached skill, the CLI replaces that folder with the attached skill.
</Warning>

### Remove installed skills

If you detach a skill, delete it, or rename it, the CLI doesn't delete the copies it already installed. On each host that ran an agent with the skill, delete the skill's folder from `~/.agents/skills`, or from the folder you passed to `--skills-dir`. Also delete the skill's link from the Claude Code and Hermes `skills` folders, if the link exists.

If you renamed the skill, the installed folder has the skill's old name.

### If an agent starts without skills

The CLI always starts the agent, even if it can't install the skills:

- If the CLI can't download or install the skills, it prints why the agent started without them
- If the Infisical CLI on the agent's host is too old to support skills, the agent starts without skills and the CLI doesn't print anything about them
- If your self-hosted Infisical instance is too old to support skills, the agent starts without skills, and the CLI only reports why if you pass [`--log-level=debug`](/cli/reference#global-flags--flag-log-level)

To use skills, upgrade the [Infisical CLI](/cli/install) on the agent's host. If you self-host Infisical, also [upgrade your instance](/self-hosting/guides/upgrading-infisical).

## View a skill

To open a skill, go to **Skills** in Agent Vault and select the skill. You can also open it from an access bundle: in the **Skills** section, open the skill's actions menu and select **View Skill**.

If you're an Agent Vault member, open the skill from an access bundle that's granted to you. The **Skills** page is only for admins.

The skill opens in a side panel that shows the latest version of its files. To get a copy of the files, open the options menu in the panel and select **Download**. Infisical downloads the files as a zip file, and scripts that are executable in Infisical stay executable.

## Edit a skill

To change a skill's files in Infisical:

<Steps>
  <Step>
    In Agent Vault, go to **Skills** and select the skill. To edit a Markdown file, select **Code**.
  </Step>
  <Step>
    Change the files in the editor, as described in [Change the files](#change-the-files).
  </Step>
  <Step>
    Select **Save Version** at the bottom, check the changes to each file, and select **Save Version** again. To throw your changes away instead, select **Discard**.
  </Step>
</Steps>

Each time you save, push, or upload a skill with different files, Infisical saves the files as a new version. Infisical keeps the last 20 versions of each skill. If the files are the same as the latest version, Infisical doesn't create a version.

If someone publishes a new version while you're editing, the review of your changes tells you. If you save anyway, your version becomes the latest version.


### Change the files

The editor lists the skill's files on the left and shows the selected file on the right:

- To change a file, select the file and edit its content. For Markdown files, select **Code** first
- To add a file or a folder, select **New File** or **New Folder**, or right-click an empty part of the file list, then type the name and press Enter
- To add a file or a folder inside a folder, right-click the folder and select **New File** or **New Folder**
- To rename or remove a file or a folder, right-click it and select **Rename**, **Delete File**, or **Delete Folder**

You can't rename or delete `SKILL.md`.

## Upload a new version

To replace a skill's files with a zipped folder or a Markdown file:

<Steps>
  <Step>
    In Agent Vault, go to **Skills** and select the skill.
  </Step>
  <Step>
    Open the options menu, select **Upload New Version**, and drop the zipped folder or the Markdown file into the dialog.
  </Step>
  <Step>
    Select **Save Version**.
  </Step>
</Steps>

A zipped folder replaces every file in the skill. A Markdown file replaces only `SKILL.md` and keeps the skill's other files.

You can also publish a new version from the CLI with [infisical agent-vault skills push](/cli/reference#agent-vault-skills-push).

## Rename a skill

To rename a skill, change the `name` in its `SKILL.md`, then [save the change](#edit-a-skill) or [upload](#upload-a-new-version) the new `SKILL.md`. Before you save, Infisical shows the skill's old name and its new name.

You can't rename a skill with the CLI. If you push a folder whose `SKILL.md` has a new name, the CLI creates a new skill with that name.

Agents that start after the rename get the skill under its new name. The CLI doesn't delete the copy it installed under the old name, so [delete the installed copies](#remove-installed-skills) on each host.

## Restore a previous version

To roll a skill back:

<Steps>
  <Step>
    In Agent Vault, go to **Skills** and select the skill.
  </Step>
  <Step>
    Open the options menu and select **Version History**.
  </Step>
  <Step>
    Select the version you want, check its files, and select **Roll Back**.
  </Step>
</Steps>

Infisical publishes a copy of that version as the new latest version. Agents that start after the rollback get that version. If the version you roll back to has the same files as the latest version, Infisical doesn't create a new version.

A rollback keeps the skill's current name. If the older version has a different name, Infisical changes the `name` in that version's `SKILL.md` to the current name.

## Delete a skill

To delete a skill and every version of it:

<Steps>
  <Step>
    In Agent Vault, go to **Skills** and select the skill.
  </Step>
  <Step>
    Open the options menu and select **Delete Skill**. The dialog lists the access bundles the skill is attached to.
  </Step>
  <Step>
    Type the skill's name and select **Delete**.
  </Step>
</Steps>

Infisical detaches the skill from every access bundle. The CLI doesn't delete copies of the skill that it already installed, so to stop agents from using the skill, [delete the installed copies](#remove-installed-skills).
