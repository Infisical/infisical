### Choosing cluster-wide or namespace-scoped

The installation mode decides whether a resource in one namespace can use credentials from another namespace:

| Mode | Trust boundary | Cross-namespace references | Use when |
| --- | --- | --- | --- |
| Cluster-wide (default) | The cluster | Allowed. A resource can reference a service account, `InfisicalAuth`, or secret in any namespace. | You trust everyone who can create operator resources to read secrets in every namespace, such as a platform team that manages authentication from one central namespace. |
| Namespace-scoped | The namespace | Blocked. The operator only has a Role in the namespace it watches, so the Kubernetes API server rejects the operator's requests for secrets and service account tokens in any other namespace. | Several teams share a cluster and each team owns a namespace. |

To keep teams apart on a shared cluster, install a separate namespace-scoped operator in each team's namespace.

<Accordion title="Blocking cross-namespace references in a cluster-wide installation">
  If you keep a cluster-wide installation and still want to keep namespaces apart, use an admission policy, such as a [ValidatingAdmissionPolicy](https://kubernetes.io/docs/reference/access-authn-authz/validating-admission-policy/), to reject resources that set one of these fields to a namespace other than their own:

  | Resource | Fields |
  | --- | --- |
  | `InfisicalAuth` | `spec.kubernetes.serviceAccountRef.namespace`, and the `namespace` of each credential reference: `clientIdRef` and `clientSecretRef` under `spec.universal`, `usernameRef` and `passwordRef` under `spec.ldap`, and `identityIdRef` under every auth method |
  | `InfisicalStaticSecret` | `spec.infisicalAuthRef.namespace` and `spec.targets[].namespace` |
  | `InfisicalSecret`, `InfisicalDynamicSecret`, and `InfisicalPushSecret` | `spec.authentication.kubernetesAuth.serviceAccountRef.namespace` |
  | `InfisicalPushSecret` | `spec.push.secret.secretNamespace` |

  Other fields can also name another namespace, such as `infisicalConnectionRef.namespace`, TLS CA certificate references, and the managed secret references on v1alpha1 resources. These fields don't give access to another namespace's credentials, but add them to the policy if you need full isolation.
</Accordion>

      </Tab>

        Limit the operator's permissions to only specific namespaces instead of cluster-wide access. Useful for multi-tenant clusters or environments requiring strict resource isolation.

        Before you install, check these settings:

        - Set `scopedRBAC=true` (if you set only `scopedNamespaces`, the operator still gets a ClusterRole and watches every namespace)
        - Set `installCRDs=true` only on the first install (CRDs are cluster-wide resources, so later installs must set `installCRDs=false`)

        **Single namespace:**
        ```bash
        helm install operator-namespaced infisical-helm-charts/secrets-operator \
          --namespace single-namespace \
          --set scopedNamespaces=single-namespace \
          --set scopedRBAC=true
        ```

        <Accordion title="Using values.yaml file">
        ```yaml values.yaml
          scopedNamespaces: single-namespace
          scopedRBAC: true
          installCRDs: true
        ```
        </Accordion>

        **Multiple namespaces (separate operators):**
        ```bash
        helm install operator-1 infisical-helm-charts/secrets-operator \
          --namespace ns1 \
          --set scopedNamespaces=ns1 \
          --set scopedRBAC=true \
          --set installCRDs=true # Only install CRDs once in the cluster (default is true)

        helm install operator-namespace2 infisical-helm-charts/secrets-operator \
          --namespace ns2 \
          --set scopedNamespaces=ns2 \
          --set scopedRBAC=true \
          --set installCRDs=false # Do not install CRDs in subsequent namespace installations
        ```

        <Accordion title="Using values.yaml file">
        ```yaml values-operator1.yaml
          scopedNamespaces: ns1
          scopedRBAC: true
          installCRDs: true
        ```

        ```yaml values-operator2.yaml
          scopedNamespaces: ns2
          scopedRBAC: true
          installCRDs: false
        ```
        </Accordion>

        **Multiple namespaces (single operator):**

        With one operator for several namespaces, a resource in any of those namespaces can reference a service account, `InfisicalAuth`, or secret in the others. Use separate operators if those namespaces belong to different teams.

        ```bash
        helm install operator infisical-helm-charts/secrets-operator \
          --namespace operator-namespace \
          --set "scopedNamespaces={ns1,ns2,ns3}" \
          --set scopedRBAC=true
        ```

        <Accordion title="Using values.yaml file">
        ```yaml values.yaml
          scopedNamespaces:
            - ns1
        ```

### Using your own service account

By default a service account is created for the operator based on the release name.
You can bring your own service account by setting `controllerManager.serviceAccount.create` to `false` and `controllerManager.serviceAccount.name` to the name of your existing service account.

```yaml values.yaml
controllerManager:
  serviceAccount:
    create: false
    name: my-service-account
```

<Note>
  The service account must already exist in the namespace you're installing the operator in.
</Note>

<Tip>
  Custom service accounts are supported in chart version `0.10.11` and above.
</Tip>

### Syncing resources in parallel

By default, the operator syncs one resource at a time.
To speed up syncing, set `maxConcurrency` at the top level of `values.yaml` to the number of resources the operator should sync at the same time.

```yaml values.yaml
maxConcurrency: 5
```

The value must be at least `1`, and a higher value sends more requests to Infisical at the same time.
`maxConcurrency` is supported in chart version `0.11.15` and above.

<Note>
  `maxConcurrency` currently only applies to [InfisicalStaticSecret](/integrations/platforms/kubernetes/infisical-static-secret-crd) resources. The operator still syncs every other resource type one at a time.
</Note>
