This guide walks you through using Agent Vault to launch an agent that calls HTTP APIs and MCP servers without having access to their credentials.

<AgentIntroNote />

## Prerequisites

<ul>
  <li>An [Agent Vault project](/documentation/platform/agent-vault/projects) where you have the [**Admin** role](/documentation/platform/agent-vault/access-control#product-membership)</li>
  <li>An [access bundle](/documentation/platform/agent-vault/access-bundles) in the project, with a service for each API the agent calls (see the [quickstart](/documentation/platform/agent-vault/quickstart))</li>
  <li>The [Infisical CLI](/cli/install) installed on the host that will run the Agent Vault proxy and on the machine that will run the agent</li>
  <AgentPrereqLine />
</ul>

<Note>
  Run the proxy on a different machine from the agent, on the same private network. If they run on the same machine, the agent can read the proxy token and the private key of the proxy's certificate authority. If they're on different networks, every request the agent makes takes longer.
</Note>

## Step 1: Set up in Infisical

### Create a proxy

First, create a [proxy](/documentation/platform/agent-vault/proxies) to intercept API calls from your agent. Create the proxy in the same project as your access bundle, because a session only works through a proxy in its own project.

<Steps>
  <Step>
    In your Agent Vault project, go to **Proxies** and select **Create Proxy**.
  </Step>
  <Step>
    Give the proxy a **Name**, then select **Create**. The **Proxy Token** dialog shows the proxy token once, with a command to start the proxy. Copy the command from the **CLI** tab for the next step.

    <Frame>
      <img src="/images/platform/agent-vault/proxy-token.png" alt="The Proxy Token dialog showing the proxy token once, with the CLI command to start the proxy" />
    </Frame>
  </Step>
  <Step>
    On the host that will act as the proxy, run the command from the previous step.

    ```bash
    INFISICAL_AGENT_VAULT_PROXY_TOKEN=<proxy-token> \
    infisical agent-vault proxy \
      --domain <your-instance-url>
    ```

    The proxy starts listening on port `17323`. Leave it running and note this host's address. You'll need the address when you launch your agent.
  </Step>
</Steps>

<Note>
  This runs the proxy in your current terminal, so the proxy stops when the terminal closes. For a persistent setup, use the **Docker** command or the **Kubernetes** manifest from the **Proxy Token** dialog, or [run the proxy with systemd](/documentation/platform/agent-vault/proxies#create-a-proxy-and-start-it).

  Check out the [proxies documentation](/documentation/platform/agent-vault/proxies) for more information.
</Note>

### Create a session

Next, create a [session](/documentation/platform/agent-vault/sessions) with your access bundle attached.

<Steps>
  <Step>
    In the same project, go to **Sessions** and select **Create Session**.
  </Step>
  <Step>
    Select **Your Own Sandbox**, then select the **Create Now** tab.
  </Step>
  <Step>
    Pick the **Access Bundle** the agent should use, set a duration under **Expires**, then select **Create Session**.

    <Frame>
      <img src="/images/platform/agent-vault/session-create-bundle.png" alt="The Create Now tab of the Your Own Sandbox dialog, with an access bundle picked and a seven day expiry" />
    </Frame>
  </Step>
  <Step>
    This creates the session and gives you a command to run your agent with it. Copy the command for the next step.

    <Frame>
      <img src="/images/platform/agent-vault/session-created.png" alt="The Session Created dialog showing the infisical agent-vault run command with the session token" />
    </Frame>
  </Step>
</Steps>

## Step 2: Launch your agent

Start the agent with [`infisical agent-vault run`](/cli/reference#agent-vault-run), which sends the agent's HTTP traffic through the proxy. Calls to services in your access bundle leave the proxy with the real credential attached.

<Tabs>
  <Tab title="Shell">
    <AgentLaunchCommand />

    If you run the agent on a server over SSH, start it inside a [`tmux`](https://github.com/tmux/tmux/wiki/Installing) session, so it keeps running after you disconnect.
  </Tab>
  <Tab title="Docker">
    This tab needs [Docker](https://docs.docker.com/get-started/get-docker/) on the machine that runs the agent, and a service in your access bundle for your model provider's key. The image installs the Infisical CLI and the agent, so the machine doesn't need them.
    <Steps>
      <Step>
        In a new directory, create a `Dockerfile` with the Infisical CLI and the agent. Replace `<cli-version>` with the latest version from the [CLI releases](https://github.com/Infisical/cli/releases).

        <AgentDockerfile />
      </Step>
      <Step>
        Build the image:

        ```bash
        docker build -t agent-vault-agent .
        ```
      </Step>
      <Step>
        <AgentDockerRun />
      </Step>
    </Steps>

    The [Docker guide](/documentation/platform/agent-vault/guides/docker) starts a new container for each task instead, with no internet access except through the proxy.
  </Tab>
</Tabs>

<AgentLaunchNote />

## Step 3: Verify it works

To check that the proxy attaches credentials, call an authenticated endpoint of a service in your access bundle, such as an endpoint that returns your account. Make the call one of two ways:

<Tabs>
  <Tab title="With your agent">
    In your agent's session, ask it to make the call. For example:

    > Run `curl -sS <endpoint-url>` and show me the output.

    The API responds, even though the agent has no API key for it. If you run the same command outside the agent, it fails with an authentication error.
  </Tab>
  <Tab title="With `curl`">
    Run `curl` through the proxy in place of your agent's command:

    ```bash
    infisical agent-vault run --session-token <session-token> --proxy <proxy-host>:17323 -- curl -sS <endpoint-url>
    ```

    The API responds, and the proxy logs the request as `brokered`.
  </Tab>
</Tabs>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication error from the upstream API">
    The credential wasn't applied. Open your access bundle and confirm a service covers the host you called. If one does, the stored token is likely wrong.
  </Accordion>
  <Accordion title="407 from the proxy">
    The session token was missing from the request. Confirm you passed `--session-token`, or that the token appears as the userinfo in your `HTTPS_PROXY` URL (like `http://x-agent-vault:<session-token>@<proxy-address>`).
  </Accordion>
  <Accordion title="403 from the proxy">
    This could be for a few reasons:

    - The session was revoked or has expired (check the **Sessions** page in Infisical, and create a new one if needed)
    - Under the proxy's [strict traffic policy](/documentation/platform/agent-vault/proxies#traffic-policy), no service in the bundle covers the host you called (add a service that does, or use a pass-through service)
    - The service covers the host, but doesn't allow the request's method or path (check the service's [methods and paths](/documentation/platform/agent-vault/http-apis#methods-and-paths))
  </Accordion>
</AccordionGroup>
