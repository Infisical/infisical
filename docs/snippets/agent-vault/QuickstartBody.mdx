This quickstart guide walks you through using Agent Vault to launch an agent that makes authenticated API calls without needing an actual token.

## Step 1: Set up in Infisical

### Create an access bundle

First, create an [access bundle](/documentation/platform/agent-vault/access-bundles) that defines which APIs ([services](/documentation/platform/agent-vault/services)) the agent can access.

<Steps>
  <Step>
    In Infisical, open **Agent Vault** from the product switcher and go to **Access Bundles**.
  </Step>
  <Step>
    Select **Create Access Bundle**. Give the access bundle a **Name**, then select **Create Access Bundle**.

    <Frame>
      <img src="/images/platform/agent-vault/access-bundle-create.png" alt="The Create Access Bundle dialog with code-review entered as the name" />
    </Frame>
  </Step>
  <Step>
    Select the access bundle you just created, then select **Add Service**.

    <ServiceTemplatePick />

    <Frame>
      <img src="/images/platform/agent-vault/service-template-picker.png" alt="The Choose a template panel with GitHub among the available services" />
    </Frame>

    <ServiceTemplatePickNote />
  </Step>
  <Step>
    <ServiceCredentialLine />
  </Step>
  <Step>
    Once you've configured the service, select **Add Service**.
  </Step>
</Steps>

<Tip>
  You can repeat these steps to add as many more services as you like to the access bundle. To give the agent a remote MCP server, such as Linear's or Notion's, [add an MCP server](/documentation/platform/agent-vault/mcp-servers#add-an-mcp-server).
</Tip>

### Create a proxy

Next, create a [proxy](/documentation/platform/agent-vault/proxies) to intercept API calls from your agent.

<Steps>
  <Step>
    Go to **Proxies** and select **Create Proxy**.
  </Step>
  <Step>
    Give the proxy a **Name**, then select **Create**. The **Proxy Token** dialog shows the proxy token once, with a command to start the proxy. Copy the command from the **CLI** tab for the next step.
  </Step>
  <Step>
    On the host that will act as the proxy, run the command from the previous step.

    ```bash
    INFISICAL_AGENT_VAULT_PROXY_TOKEN=<proxy-token> \
    infisical agent-vault proxy \
      --domain <your-instance-url>
    ```

    The proxy starts listening on port `17323`. Leave it running and note this host's address. You'll need the address when you launch your agent.
  </Step>
</Steps>

<Note>
  This runs the proxy in your current terminal, so the proxy stops when the terminal closes. For a persistent setup, use the **Docker** command or the **Kubernetes** manifest from the **Proxy Token** dialog, or [run the proxy with systemd](/documentation/platform/agent-vault/proxies#create-a-proxy-and-start-it).

  Check out the [proxies documentation](/documentation/platform/agent-vault/proxies) for more information.
</Note>

### Create a session

Next, create a [session](/documentation/platform/agent-vault/sessions) with your access bundle attached.

<Steps>
  <Step>
    Go to **Sessions** and select **Create Session**.
  </Step>
  <Step>
    Pick the **Access Bundle** the agent should use, set a duration under **Expires**, then select **Create Session**.

    <Frame>
      <img src="/images/platform/agent-vault/session-create.png" alt="The Create Session dialog with code-review picked and a seven day expiry" />
    </Frame>
  </Step>
  <Step>
    This creates the session and gives you a command to run your agent with it. Copy the command for the next step.

    <Frame>
      <img src="/images/platform/agent-vault/session-created.png" alt="The Session Created dialog showing the infisical agent-vault run command with the session token" />
    </Frame>
  </Step>
</Steps>

## Step 2: Launch your agent

On the host where the agent runs, paste the command you copied in the previous step. Replace `<proxy-host>` with your host's actual domain or IP address, and `<agent-command>` with your agent's own command.

<AgentLaunchCommand />

<Tip>
  Instead of passing `--session-token` and `--proxy`, you can set the [`INFISICAL_AGENT_VAULT_SESSION_TOKEN` and `INFISICAL_AGENT_VAULT_PROXY_ADDRESS` environment variables](/cli/reference#agent-vault-run).
</Tip>

The CLI adds the proxy's certificate authority to the agent process' trusted CAs and starts the agent with its HTTP traffic routed through the proxy. Any calls to services in your access bundle leave the proxy with the real credential attached, while calls to any other host go out normally.

<Note>
  On macOS, you'll need to enter your user password when running your agent for the first time. This is because macOS needs your approval to add the proxy's certificate to your keychain.
</Note>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication error from the upstream API">
    The credential wasn't applied. Open your access bundle and confirm a service covers the host you called. If one does, the stored token is likely wrong.
  </Accordion>
  <Accordion title="407 from the proxy">
    The session token was missing from the request. Confirm you passed `--session-token`, or that the token appears as the userinfo in your `HTTPS_PROXY` URL (like `http://x-agent-vault:<session-token>@<proxy-address>`).
  </Accordion>
  <Accordion title="403 from the proxy">
    This could be for a few reasons:

    - The session was revoked or has expired (check the **Sessions** page in Infisical, and create a new one if needed)
    - Under the proxy's [strict traffic policy](/documentation/platform/agent-vault/proxies#traffic-policy), no service in the bundle covers the host you called (add a service that does, or use a pass-through service)
    - The service covers the host, but doesn't allow the request's method or path (check the service's [methods and paths](/documentation/platform/agent-vault/http-apis#methods-and-paths))
  </Accordion>
</AccordionGroup>
