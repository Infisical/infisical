If you're working with Go, the official Infisical Go SDK package is the easiest way to fetch and work with secrets for your application.

- [Package](https://pkg.go.dev/github.com/infisical/go-sdk)
- [GitHub Repository](https://github.com/infisical/go-sdk)

# Basic usage

```go
package main

import (
  "fmt"
  "os"
  "context"
  infisical "github.com/infisical/go-sdk"
)

func main() {

	client := infisical.NewInfisicalClient(context.Background(), infisical.Config{
		SiteUrl: "https://app.infisical.com", // Optional, default is https://app.infisical.com
    AutoTokenRefresh: true, // Whether or not to let the SDK handle the access token lifecycle. Defaults to true if not specified.
	})

	_, err := client.Auth().UniversalAuthLogin("YOUR_CLIENT_ID", "YOUR_CLIENT_SECRET")

	if err != nil {
		fmt.Printf("Authentication failed: %v", err)
		os.Exit(1)
	}

	apiKeySecret, err := client.Secrets().Retrieve(infisical.RetrieveSecretOptions{
		SecretKey:   "API_KEY",
		Environment: "dev",
		ProjectID:   "YOUR_PROJECT_ID",
		SecretPath:  "/",
	})

	if err != nil {
		fmt.Printf("Error: %v", err)
		os.Exit(1)
	}

	fmt.Printf("API Key Secret: %v", apiKeySecret)

}
```

This example demonstrates how to use the Infisical Go SDK in a simple Go application. The application retrieves a secret named `API_KEY` from the `dev` environment of the `YOUR_PROJECT_ID` project.

<Warning>
  We don't recommend hardcoding your [Machine Identity
  Tokens](/documentation/platform/identities/machine-identities). Setting it as
  an environment variable would be best.
</Warning>

# Configuration

Import the SDK and create a client instance.

```go
client := infisical.NewInfisicalClient(context.Background(), infisical.Config{
		SiteUrl: "https://app.infisical.com", // Optional, default is https://api.infisical.com
	})
```

# Automatic token refreshing

The Infisical Go SDK supports automatic token refreshing, **enabled by default**. After using one of the auth methods such as Universal Auth, the SDK will automatically renew and re-authenticate when needed.
You can opt-out by setting `AutoTokenRefresh` to `false` in the client settings.

```go
  client := infisical.NewInfisicalClient(context.Background(), infisical.Config{
    AutoTokenRefresh: false, // <- Disable automatic token refreshing
  })
```

### Client lifecycle

When using automatic token refreshing it's important to understand how your application uses the Infisical client. If you're instantiating new instances of the client often, it's important to cancel the context when the client is no longer needed to avoid the token refreshing process from running indefinitely.

```go
  ctx, cancel := context.WithCancel(context.Background())
  defer cancel() // Cancel the context when the client is no longer needed

  client := infisical.NewInfisicalClient(ctx, infisical.Config{
    AutoTokenRefresh: true,
  })

  // Use the client
```

This is only necessary if you're creating multiple instances of the client, and those instances are deleted or otherwise removed throughout the application lifecycle.
If you're only creating one instance of the client, and it will be used throughout the lifetime of your application, you don't need to worry about this.


## Authentication

### Authentication methods

The SDK supports a variety of authentication methods. The most common authentication method is Universal Auth, which uses a client ID and client secret to authenticate.

<AccordionGroup>
  <Accordion title="Universal Auth">
    **Using environment variables**

    Call `.Auth().UniversalAuthLogin()` with empty arguments to use the following environment variables:

    - `INFISICAL_UNIVERSAL_AUTH_CLIENT_ID` - Your machine identity client ID.
    - `INFISICAL_UNIVERSAL_AUTH_CLIENT_SECRET` - Your machine identity client secret.

    **Using the SDK directly**

    ```go
    _, err := client.Auth().UniversalAuthLogin("CLIENT_ID", "CLIENT_SECRET")

    if err != nil {
      fmt.Println(err)
      os.Exit(1)
    }
    ```

### Sub-organization authentication

<Note>
  This section is only relevant to you if your organization is utilizing [sub-organizations](/documentation/platform/sub-organizations) within Infisical.
</Note>

All SDK authentication methods support logging into a sub-organization that your machine identity has access to. This is optional and only necessary when attempting to authenticate into a sub-organization using an identity created at the root organization.

Use the `.Auth().WithOrganizationSlug("<organization-slug>")` method to specify which organization to authenticate against:

```go
_, err := client.Auth().WithOrganizationSlug("ORGANIZATION_SLUG").UniversalAuthLogin("CLIENT_ID", "CLIENT_SECRET")

if err != nil {
  fmt.Println(err)
  os.Exit(1)
}
```

<Tip>
  If no organization slug is provided, the authentication session defaults to
  the organization where the machine identity was originally created.
</Tip>

## Secrets

### List secrets

`client.Secrets().List(options)`

Retrieve all secrets within the Infisical project and environment that client is connected to.

```go
secrets, err := client.Secrets().List(infisical.ListSecretsOptions{
  ProjectID:          "PROJECT_ID",
  Environment:        "dev",
  SecretPath:         "/prod/backend",
  AttachToProcessEnv: false,
})
```

### Retrieve secret

`client.Secrets().Retrieve(options)`

Retrieve a secret from Infisical. By default `Secrets().Retrieve()` fetches and returns a shared secret.

```go
secret, err := client.Secrets().Retrieve(infisical.RetrieveSecretOptions{
  SecretKey:   "API_KEY",
  ProjectID:   "PROJECT_ID",
  Environment: "dev",
})
```

## Agent Vault sessions

`client.AgentVault().Sessions()` manages [Agent Vault sessions](/documentation/platform/agent-vault/sessions). A session lets an AI agent use the [services](/documentation/platform/agent-vault/services) in one [access bundle](/documentation/platform/agent-vault/access-bundles), the [inline services](/documentation/platform/agent-vault/inline-services) sent with the session, or both, until the session expires or someone revokes it.

What the client can do with sessions depends on the [role](/documentation/platform/agent-vault/access-control#product-membership) that the user or machine identity the client logs in as has in the Agent Vault project:

| Role | Can create sessions with | Can list, get, label, and revoke |
| --- | --- | --- |
| **Admin** | Any access bundle (on behalf of a user, [only access bundles that the user can use too](#create-a-session-on-behalf-of-a-user)), and [inline services](#create-a-session-with-inline-services) | Every session |
| **Member** | The access bundles [granted](/documentation/platform/agent-vault/access-bundles#grant-access) to the member | The member's own sessions |

<Note>
  `AgentVault()` requires `github.com/infisical/go-sdk` version 0.10.0 or newer.
</Note>

### Create a session on behalf of a user

If the client logs in as a machine identity with a [delegation](/documentation/platform/agent-vault/sessions-on-behalf-of-users#set-up-a-delegation), the client can create sessions on behalf of the users that the delegation covers. For each of those sessions, the proxy uses the user's [personal values](/documentation/platform/agent-vault/http-apis#member-provided-values) instead of the machine identity's.

```go
session, err := client.AgentVault().Sessions().Create(infisical.AgentVaultCreateSessionOptions{
  ProjectID:    "<project-id>",
  AccessBundle: "<access-bundle-name>",
  OnBehalfOf:   &infisical.AgentVaultOnBehalfOf{UserEmail: "<user-email>"},
})
```

- The session can use an access bundle only if both the user and the machine identity [can use the bundle](/documentation/platform/agent-vault/sessions-on-behalf-of-users#access-bundles-and-personal-values)
- The session belongs to the machine identity, so the user can't see the session unless they're an Agent Vault admin
- In each session that the `Get`, `List`, `Update`, and `Revoke` methods return, `OnBehalfOf` is the user, or `nil` if the session is the machine identity's own

To find the access bundles that a session on behalf of the user can use, set `OnBehalfOf` in [`AccessBundles().List`](#list-access-bundles). The proxy refuses a session's requests to services that still need the user's personal values, so also set `RequiresSetup` to `infisical.BoolPtr(false)` to leave out the access bundles with those services.

### Create a session with inline services

If the client logs in as a user or machine identity with the **Admin** role in the Agent Vault project, the client can send inline services with a session, instead of or beside an access bundle. Inline services let you pass along credentials that your code already holds, without setting anything up in Agent Vault in advance.

```go
session, err := client.AgentVault().Sessions().Create(infisical.AgentVaultCreateSessionOptions{
  ProjectID: "<project-id>",
  TTL:       "1h",
  Services: []infisical.AgentVaultInlineService{
    infisical.AgentVaultInlineHTTPService{
      Name:           "github",
      HostPattern:    "api.github.com",
      AllowedMethods: []string{"GET"},
      Credential:     infisical.AgentVaultBearerCredential{Value: "<github-token>"},
    },
  },
})
```

- Each service is an HTTP API (`AgentVaultInlineHTTPService`), an MCP server (`AgentVaultInlineMCPService`), or a [database or SSH server](/documentation/platform/agent-vault/databases-and-ssh) (`AgentVaultInlineDatabaseService` or `AgentVaultInlineSSHService`)
- Credentials, custom header values, and substitution values can't contain text in double braces, such as `{{GITHUB_TOKEN}}`, because inline services can't use [variables](/documentation/platform/agent-vault/variables)
- A session can have up to 20 inline services, and no two of its services can have the same name or host pattern, including the services in its access bundle
- If a machine identity creates the session on behalf of a user, the machine identity needs the **Admin** role and the user doesn't, and the inline services don't use the user's personal values
- In each session that the `Create`, `Get`, `List`, and `Update` methods return, `Services` lists the inline services without their secrets

For the fields that each type of service takes, and for when Infisical deletes the services' secrets, see [Inline services](/documentation/platform/agent-vault/inline-services).

### Revoke access

Revoke an access bundle from users, machine identities, or groups. Pass at least one ID, and at most 100 in total.

- If someone with the **Member** role no longer has any grant on the access bundle, the proxy stops attaching the bundle's credentials to their sessions and to the sessions that machine identities created on their behalf (see [Access changes](/documentation/platform/agent-vault/sessions#access-changes); a session's inline services keep working, so to stop every credential, [revoke the session](#revoke-session))
- Admins can use every access bundle without a grant, so their sessions keep getting credentials after you revoke their grants (to stop one of their agents, [revoke its session](#revoke-session))

## Agent Vault delegations

`client.AgentVault().Delegations()` manages [delegations](/documentation/platform/agent-vault/sessions-on-behalf-of-users), which let a machine identity [create sessions on behalf of users](#create-a-session-on-behalf-of-a-user).

To use any method in this section, the client must log in as a user or machine identity with the **Admin** role in the [Agent Vault project](/documentation/platform/agent-vault/access-control#product-membership). A machine identity without the role can still get its own delegation.

### Get delegation

Get which users a machine identity can create sessions on behalf of.

```go

  ProjectID: "<project-id>",
})
```

**Parameters:**

<ResponseField name="machineIdentityID" type="string" required>
  The ID of the machine identity.
</ResponseField>

<ResponseField name="options" type="AgentVaultProjectOptions" required>
  <Expandable title="properties">
    <ResponseField name="ProjectID" type="string" required>
      The ID of the [Agent Vault project](/documentation/platform/agent-vault/projects#find-the-project-id) to get the delegation from.
    </ResponseField>
  </Expandable>
</ResponseField>

**Returns:**

<ResponseField name="delegation" type="AgentVaultDelegation">
  The delegation, including `MissingAccessBundles`.
</ResponseField>

If the machine identity has no delegation, `Get` returns an `*errors.APIError` whose `StatusCode` is `404`. The `errors` package is `github.com/infisical/go-sdk/packages/errors`.

`MissingAccessBundles` lists the access bundles that the delegation's users can use and the machine identity can't. A session on behalf of a user can use only an access bundle that both the user and the machine identity can use, so the machine identity can't create sessions with those access bundles. If a machine identity without the **Admin** role gets its own delegation, `MissingAccessBundles` is empty.

### Set delegation

Set which users a machine identity can create sessions on behalf of. The new delegation replaces any delegation that the machine identity has.

```go
delegation, err := client.AgentVault().Delegations().Set("<machine-identity-id>", infisical.AgentVaultSetDelegationOptions{
  ProjectID: "<project-id>",
  Scope:     infisical.AgentVaultDelegationScopeSelected,
  UserIDs:   []string{"<user-id>"},  // Optional
  GroupIDs:  []string{"<group-id>"}, // Optional
})
```

**Parameters:**

<ResponseField name="options" type="AgentVaultSetDelegationOptions" required>

    </ResponseField>
    <ResponseField name="Scope" type="AgentVaultDelegationScope" required>
