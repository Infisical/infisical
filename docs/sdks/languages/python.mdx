If you're working with Python, the official Infisical Python SDK package is the easiest way to fetch and work with secrets for your application. 

### Migrating to version 1.0.3 or above

We have recently rolled out our first stable version of the SDK, version `1.0.3` and above.

The 1.0.3 version comes with a few key changes that may change how you're using the SDK.
1. **Removal of `rest`**: The SDK no longer exposes the entire Infisical API. This was necessary as we have moved away from using an OpenAPI generator approach. We aim to add support for more API resources in the near future. If you have any specific requests, please [open an issue](https://github.com/Infisical/python-sdk-official/issues).

2. **New response types**: The 1.0.3 release uses return types that differ from the older versions. The new return types such as `BaseSecret`, are all exported from the Infisical SDK.

3. **Property renaming**: Some properties on the responses have been slightly renamed. An example of this would be that the `secret_key` property on the `get_secret_by_name()` method, that has been renamed to `secretKey`.

With this in mind, you're ready to upgrade your SDK version to `1.0.3` or above. 

You can refer to our [legacy documentation](https://github.com/Infisical/python-sdk-official/tree/9b0403938ee5ae599d42c5f1fdf9158671a15606?tab=readme-ov-file#infisical-python-sdk) if need be.

## Requirements

Python 3.7+

## Installation

```bash
pip install infisicalsdk
```

## Getting started

```python
from infisical_sdk import InfisicalSDKClient

# Initialize the client
client = InfisicalSDKClient(host="https://app.infisical.com")

# Authenticate (example using Universal Auth)
client.auth.universal_auth.login(
    client_id="<machine-identity-client-id>", 
    client_secret="<machine-identity-client-secret>"
)

# Use the SDK to interact with Infisical
secrets = client.secrets.list_secrets(project_id="<project-id>", environment_slug="dev", secret_path="/")
```

## InfisicalSDKClient parameters

The `InfisicalSDKClient` takes the following parameters, which are used as a global configuration for the lifetime of the SDK instance.

- **host** (`str`, _Optional_): The host URL for your Infisical instance. Defaults to `https://app.infisical.com`.
- **token** (`str`, _Optional_): Specify an authentication token to use for all requests. If provided, you won't need to call any of the `auth` methods. Defaults to `None`
- **cache_ttl** (`int`, _Optional_): The SDK has built-in client-side caching for secrets, greatly improving response times. By default, secrets are cached for 1 minute (60 seconds). You can disable caching by setting `cache_ttl` to `None`, or adjust the duration in seconds as needed.

```python
client = InfisicalSDKClient(
  host="https://app.infisical.com", # Defaults to https://app.infisical.com
  token="<optional-auth-token>", # If not set, use the client.auth() methods.
  cache_ttl = 300 # `None` to disable caching
)
```

## Core methods

The SDK methods are organized into the following high-level categories:

1. `auth`: Handles authentication methods.
2. `secrets`: Manages CRUD operations for secrets.
3. `dynamic_secrets`: Manages dynamic secrets and leases.
4. `kms`: Perform cryptographic operations with Infisical KMS.
5. `folders`: Manages folder-related operations.
6. `agent_vault`: Manages [Agent Vault](/documentation/platform/agent-vault/overview) sessions, proxies, access bundles, and delegations.

### `auth`

The `Auth` component provides methods for authentication:

#### Universal auth

```python
response = client.auth.universal_auth.login(
    client_id="<machine-identity-client-id>", 
    client_secret="<machine-identity-client-secret>"
)
```

#### AWS auth

```python
response = client.auth.aws_auth.login(identity_id="<machine-identity-id>")
```

#### OIDC auth

```python
response = client.auth.oidc_auth.login(
    identity_id="<oidc-identity-id>",
    jwt="<your-oidc-jwt-token>"
)
```

**Parameters:**
- `identity_id` (str): The ID of the OIDC identity configuration in Infisical.
- `jwt` (str): The OIDC JWT token obtained from your identity provider.

This authentication method is useful when integrating with OIDC-compliant identity providers like Okta, Auth0, or any service that issues OIDC tokens.

#### LDAP auth

```python
response = client.auth.ldap_auth.login(
    identity_id="<machine-identity-id>",
    username="<ldap-username>",
    password="<ldap-password>"
)
```

**Parameters:**
- `identity_id` (str): The ID of the LDAP identity configuration in Infisical.
- `username` (str): Your LDAP username.
- `password` (str): Your LDAP password.

<Info>
  Please note that this authentication method requires LDAP credentials. Please
  [read more](/documentation/platform/identities/ldap-auth/general) about this
  authentication method.
</Info>

#### Token auth

```python
response = client.auth.token_auth.login(token="<your-token>")
```

**Parameters:**
- `token` (str): The access token to authenticate with. This can be a [machine identity token](/documentation/platform/identities/token-auth) or a user access token.

### `secrets`

This sub-class handles operations related to secrets:

#### List secrets

```python
secrets = client.secrets.list_secrets(
    project_id="<project-id>",
    environment_slug="dev",
    secret_path="/",
    expand_secret_references=True, # Optional
    view_secret_value=True, # Optional 
    recursive=False, # Optional
    include_imports=True, # Optional
    tag_filters=[] # Optional
)
```

**Parameters:**
- `project_id` (str): The ID of your project.
- `project_slug` (str): The slug of your project.
- `environment_slug` (str): The environment in which to list secrets (e.g., "dev").
- `secret_path` (str): The path to the secrets.
- `expand_secret_references` (bool): Whether to expand secret references.
- `view_secret_value` (bool): Whether or not to include the secret value in the response. If set to false, the `secretValue` will be masked with `<hidden-by-infisical>`. Defaults to true.
- `recursive` (bool): Whether to list secrets recursively.
- `include_imports` (bool): Whether to include imported secrets.
- `tag_filters` (List[str]): Tags to filter secrets.

**Note:** Exactly one of `project_id` or `project_slug` is required. If both are provided, `project_id` takes precedence.

**Returns:**
- `ListSecretsResponse`: The response containing the list of secrets.

#### Create secret

```python
new_secret = client.secrets.create_secret_by_name(
    secret_name="NEW_SECRET",
    project_id="<project-id>",
    secret_path="/",
    environment_slug="dev",
    secret_value="secret_value",
    secret_comment="Optional comment",
    skip_multiline_encoding=False,
    secret_reminder_repeat_days=30,  # Optional
    secret_reminder_note="Remember to update this secret",  # Optional
    secret_metadata=[{"key": "metadata_key", "value": "metadata_value"}], # Optional
    tags_ids=["tag_id_1", "tag_id_2"] # Optional
)
```

**Parameters:**
- `secret_name` (str): The name of the secret.
- `project_id` (str): The ID of your project.
- `project_slug` (str): The slug of your project.
- `secret_path` (str): The path to the secret.
- `environment_slug` (str): The environment in which to create the secret.
- `secret_value` (str): The value of the secret.
- `secret_comment` (str, optional): A comment associated with the secret.
- `skip_multiline_encoding` (bool, optional): Whether to skip encoding for multiline secrets.
- `secret_reminder_repeat_days` (Union[float, int], optional): Number of days after which to repeat secret reminders.
- `secret_reminder_note` (str, optional): A note for the secret reminder.
- `secret_metadata` (List[Dict[str, Any]], optional): Metadata associated with the secret.
- `tags_ids` (List[str], optional): IDs of tags to associate with the secret.

**Note:** Exactly one of `project_id` or `project_slug` is required. If both are provided, `project_id` takes precedence.

**Returns:**
- `BaseSecret`: The response after creating the secret.

#### Update secret


**Parameters:**

- `secret_path` (str): The path to the secret.
- `environment_slug` (str): The environment in which to update the secret.
- `secret_value` (str, optional): The new value of the secret.
- `secret_comment` (str, optional): An updated comment associated with the secret.
- `skip_multiline_encoding` (bool, optional): Whether to skip encoding for multiline secrets.
- `secret_reminder_repeat_days` (Union[float, int], optional): Updated number of days after which to repeat secret reminders.
- `secret_reminder_note` (str, optional): An updated note for the secret reminder.
- `new_secret_name` (str, optional): A new name for the secret.
- `secret_metadata` (List[Dict[str, Any]], optional): Metadata associated with the secret.
- `tags_ids` (List[str], optional): IDs of tags to associate with the secret.

**Note:** Exactly one of `project_id` or `project_slug` is required. If both are provided, `project_id` takes precedence.

- `BaseSecret`: The response after updating the secret.

- `version` (str, optional): The version of the secret to retrieve. Fetches the latest by default.

**Note:** Exactly one of `project_id` or `project_slug` is required. If both are provided, `project_id` takes precedence.

### `dynamic_secrets`

This sub-class handles operations related to dynamic secrets. Dynamic secrets generate credentials on-demand with automatic expiration. For more information, see the [Dynamic Secrets documentation](/documentation/platform/dynamic-secrets/overview).

#### Create dynamic secret

```python
from infisical_sdk import DynamicSecretProviders

dynamic_secret = client.dynamic_secrets.create(
    name="postgres-dev",
    provider_type=DynamicSecretProviders.SQL_DATABASE,
    inputs={
        "client": "postgres",
        "host": "localhost",
        "port": 5432,
        "database": "mydb",
        "username": "admin",
        "password": "admin-password",
        "creationStatement": "CREATE USER \"{{username}}\" WITH PASSWORD '{{password}}';",
        "revocationStatement": "DROP USER \"{{username}}\";"
    },
    default_ttl="1h",
    max_ttl="24h",
    project_slug="my-project",
    environment_slug="dev",
    path="/",
    metadata=[{"key": "team", "value": "backend"}]  # Optional
)
```

**Parameters:**
- `name` (str): The name of the dynamic secret.
- `provider_type` (Union[DynamicSecretProviders, str]): The provider type (e.g., `DynamicSecretProviders.SQL_DATABASE`).
- `inputs` (Dict[str, Any]): The provider-specific configuration inputs. See the [Dynamic Secrets API documentation](/api-reference/endpoints/dynamic-secrets/create) for provider-specific inputs.
- `default_ttl` (str): The default time to live for leases (e.g., "1h", "30m").
- `max_ttl` (str): The maximum time to live for leases (e.g., "24h").
- `project_slug` (str): The slug of your project.
- `environment_slug` (str): The environment in which to create the dynamic secret.
- `path` (str, optional): The path where the dynamic secret will be created. Defaults to "/".
- `metadata` (List[Dict[str, str]], optional): Optional list of metadata items with 'key' and 'value'.

**Returns:**
- `DynamicSecret`: The created dynamic secret.

### `dynamic_secrets.leases`

This sub-class handles operations related to dynamic secret leases. A lease represents a set of generated credentials with a specific TTL.

#### Create lease

Create a lease to generate credentials from a dynamic secret:

```python
lease_response = client.dynamic_secrets.leases.create(
    dynamic_secret_name="postgres-dev",
    project_slug="my-project",
    environment_slug="dev",
    path="/",
    ttl="30m"  # Optional
)

# Access the generated credentials
username = lease_response.data["DB_USERNAME"]
password = lease_response.data["DB_PASSWORD"]
lease_id = lease_response.lease.id
```

**Parameters:**
- `dynamic_secret_name` (str): The name of the dynamic secret to create a lease for.
- `project_slug` (str): The slug of your project.
- `environment_slug` (str): The environment in which to create the lease.
- `path` (str, optional): The path to the dynamic secret. Defaults to "/".
- `ttl` (str, optional): The time to live for the lease (e.g., "1h", "30m").

**Returns:**
- `CreateLeaseResponse`: Response containing:
  - `lease`: The lease object with ID, expiration, and metadata.
  - `dynamicSecret`: The associated dynamic secret.
  - `data`: The generated credentials. The structure depends on the dynamic secret provider.

#### Get lease

```python
lease = client.dynamic_secrets.leases.get(
    lease_id="<lease-id>",
    project_slug="my-project",
    environment_slug="dev",
    path="/"
)
```

**Parameters:**
- `lease_id` (str): The ID of the lease to retrieve.
- `project_slug` (str): The slug of your project.
- `environment_slug` (str): The environment in which to retrieve the lease.
- `path` (str, optional): The path to the dynamic secret. Defaults to "/".

**Returns:**
- `DynamicSecretLease`: The lease with dynamicSecret included.

#### Renew lease

Extend the TTL of an existing lease:

```python
renewed_lease = client.dynamic_secrets.leases.renew(
```

**Parameters:**

- `environment_slug` (str): The environment in which to renew the lease.
- `path` (str, optional): The path to the dynamic secret. Defaults to "/".
- `ttl` (str, optional): The new time to live for the lease.

**Returns:**
- `DynamicSecretLease`: The renewed lease.

### `agent_vault.sessions`

This sub-class manages [Agent Vault sessions](/documentation/platform/agent-vault/sessions). A session lets an AI agent use the [services](/documentation/platform/agent-vault/services) in one [access bundle](/documentation/platform/agent-vault/access-bundles), the [inline services](/documentation/platform/agent-vault/inline-services) sent with the session, or both, until the session expires or someone revokes it.

What the client can do with sessions depends on the [Agent Vault role](/documentation/platform/agent-vault/access-control#product-membership) of the user or machine identity that the client logs in as:

| Role | Can create sessions with | Can list, get, label, and revoke |
| --- | --- | --- |
| **Admin** | Any access bundle (on behalf of a user, [only access bundles that the user can use too](#create-a-session-on-behalf-of-a-user)), and [inline services](#create-a-session-with-inline-services) | Every session |
| **Member** | The access bundles [granted](/documentation/platform/agent-vault/access-bundles#grant-access) to the member | The member's own sessions |

<Note>
  `agent_vault` requires `infisicalsdk` version 1.2.0 or newer.
</Note>

#### List sessions

```python
from infisical_sdk import AgentVaultSessionScope, AgentVaultSessionStatus

sessions = client.agent_vault.sessions.list(
    scope=AgentVaultSessionScope.MINE, # Optional
    statuses=[AgentVaultSessionStatus.ACTIVE], # Optional
    search="nightly deploy", # Optional
    limit=20, # Optional
    offset=0 # Optional
)
```

**Parameters:**
- `scope` (Union[AgentVaultSessionScope, str], optional): whose sessions to list, either `AgentVaultSessionScope.MINE` (`"mine"`) for your own sessions or `AgentVaultSessionScope.ALL` (`"all"`) for every session if you're an admin (defaults to `AgentVaultSessionScope.MINE`)
- `statuses` (List[Union[AgentVaultSessionStatus, str]], optional): the statuses to include, from `AgentVaultSessionStatus.ACTIVE` (`"active"`), `AgentVaultSessionStatus.REVOKED` (`"revoked"`), and `AgentVaultSessionStatus.EXPIRED` (`"expired"`) (defaults to all three)
- `search` (str, optional): text to find in each session's [label](/documentation/platform/agent-vault/sessions#label-a-session), owner name, owner email, access bundle name, or the name or email of the user that the session was [created on behalf of](/documentation/platform/agent-vault/sessions-on-behalf-of-users)
- `limit` (int, optional): the maximum number of sessions to return, from 1 to 100 (defaults to `20`)
- `offset` (int, optional): the number of sessions to skip (defaults to `0`)

**Returns:**
- `ListAgentVaultSessionsResponse`: the sessions in `sessions`, and the total number of matching sessions in `totalCount`

#### Get session

```python

    session_id="<session-id>"

```

**Parameters:**
- `session_id` (str): the ID of the session

**Returns:**
- `AgentVaultSession`: the session

#### Create session

```python
session = client.agent_vault.sessions.create(
    access_bundle="<access-bundle-name>",
    ttl="1h", # Optional
    label="nightly deploy" # Optional
)
```

**Parameters:**
- `access_bundle` (str, optional): the name of the access bundle that the agent can use during the session (pass `access_bundle`, `services`, or both)
- `ttl` (str, optional): how long the session lasts, as a duration of at least one minute such as `30m`, `8h`, or `7d`, or as `never` for a session that doesn't expire (defaults to `7d`, or to `1h` for a session on behalf of a user)
- `label` (str, optional): a short description of what the session is for, such as `nightly deploy` (up to 128 characters, without line breaks, tabs, or invisible characters)
- `on_behalf_of_user_email` (str, optional): the email address of the user that the session is [created on behalf of](#create-a-session-on-behalf-of-a-user) (raises a `ValueError` if you also pass `on_behalf_of_user_id`)
- `on_behalf_of_user_id` (str, optional): the ID of the user that the session is created on behalf of (raises a `ValueError` if you also pass `on_behalf_of_user_email`)
- `services` (List[Dict[str, Any]], optional): [inline services](#create-a-session-with-inline-services) to send with the session (Agent Vault admins only, up to 20)

**Returns:**
- `CreatedAgentVaultSession`: the new session, with the session token in `token` (Infisical returns the token only once)

To pass `session.token` to the agent, follow the steps in [Start the agent with the session token](/documentation/platform/agent-vault/sessions-api#step-4-start-the-agent-with-the-session-token).

#### Create a session on behalf of a user

If the client logs in as a machine identity with a [delegation](/documentation/platform/agent-vault/sessions-on-behalf-of-users#set-up-a-delegation), the client can create sessions on behalf of the users that the delegation covers. For each of those sessions, the proxy uses the user's [personal values](/documentation/platform/agent-vault/http-apis#member-provided-values) instead of the machine identity's.

```python
session = client.agent_vault.sessions.create(
    access_bundle="<access-bundle-name>",
    on_behalf_of_user_email="<user-email>"
)
```

- The session can use an access bundle only if both the user and the machine identity [can use the bundle](/documentation/platform/agent-vault/sessions-on-behalf-of-users#what-the-session-can-reach)
- The session belongs to the machine identity, so the user can't see the session unless they're an Agent Vault admin
- In each session that the `get`, `list`, `update`, and `revoke` methods return, `onBehalfOf` is the user, or `None` if the session is the machine identity's own

To find the access bundles that a session on behalf of the user can use, pass the user's email address or ID to [`access_bundles.list`](#list-access-bundles). The proxy refuses a session's requests to services that still need the user's personal values, so also pass `requires_setup=False` to leave out the access bundles with those services.

#### Create a session with inline services

If the client logs in as a user or machine identity with the **Admin** role in Agent Vault, the client can send inline services with a session, instead of or beside an access bundle. Inline services let you pass along credentials that your code already holds, without setting anything up in Agent Vault in advance.

```python
session = client.agent_vault.sessions.create(
    ttl="1h",
    services=[
        {
            "type": "http",
            "name": "github",
            "hostPattern": "api.github.com",
            "allowedMethods": ["GET"],
            "credential": {"type": "bearer", "value": "<github-token>"}
        }
    ]
)
```

- Each service is a dictionary that describes an HTTP API (`"type": "http"`) or an MCP server (`"type": "mcp"`)
- The dictionaries use the API's field names, such as `hostPattern` rather than `host_pattern`
- Credentials, custom header values, and substitution values can't contain text in double braces, such as `{{GITHUB_TOKEN}}`, because inline services can't use [variables](/documentation/platform/agent-vault/variables)
- A session can have up to 20 inline services, and no two of its services can have the same name or host pattern, including the services in its access bundle
- If a machine identity creates the session on behalf of a user, the machine identity needs the **Admin** role and the user doesn't, and the inline services don't use the user's personal values
- In each session that the `create`, `get`, `list`, and `update` methods return, `services` lists the inline services without their secrets

For the fields that each type of service takes, and for when Infisical deletes the services' secrets, see [Inline services](/documentation/platform/agent-vault/inline-services).

#### Update session label

Add, change, or remove a session's label, for example to record what the agent is working on. You can also change the label after the session expires or is revoked, unless someone deleted the session's owner or the user that the session was created on behalf of.

```python
session = client.agent_vault.sessions.update(
    session_id="<session-id>",
    label="support ticket triage"
)
```

**Parameters:**
- `session_id` (str): the ID of the session
- `label` (Optional[str]): the new label, or `None` to remove the label (up to 128 characters, without line breaks, tabs, or invisible characters)

**Returns:**
- `AgentVaultSession`: the updated session

#### Revoke session

Revoke a session when its agent finishes, even if the agent fails. The proxy stops attaching credentials to the session's requests within one [poll interval](/documentation/platform/agent-vault/proxies#poll-interval).

If the agent can run longer than the client's access token lasts, log in again before you revoke the session, because the SDK doesn't renew the access token on its own. Set `ttl` close to how long the agent runs, so that the session expires soon after the agent finishes even if revoking the session fails.

```python
session = client.agent_vault.sessions.create(access_bundle="<access-bundle-name>", ttl="1h")
try:
    run_agent(session.token) # Your code that starts the agent with the session token
finally:
    client.agent_vault.sessions.revoke(session_id=session.id)
```

**Parameters:**
- `session_id` (str): the ID of the session

**Returns:**
- `AgentVaultSession`: the revoked session, with `accessBundle` and `services` set to `None` (call `get` for them)

#### Revoke access

Revoke an access bundle from users, machine identities, or groups. Pass at least one ID, and at most 100 in total.

- If someone with the **Member** role no longer has any grant on the access bundle, the proxy stops attaching the bundle's credentials to their sessions and to the sessions that machine identities created on their behalf, as [Access changes](/documentation/platform/agent-vault/sessions#access-changes) describes (a session's inline services keep working, so to stop every credential, [revoke the session](#revoke-session))
- Admins can use every access bundle without a grant, so their sessions keep getting credentials after you revoke their grants (to stop one of their agents, [revoke its session](#revoke-session))

```python
response = client.agent_vault.access_bundles.revoke(
    access_bundle_id="<access-bundle-id>",
    user_ids=["<user-id>"], # Optional
    machine_identity_ids=["<machine-identity-id>"], # Optional
    group_ids=["<group-id>"] # Optional
)
```

**Parameters:**
- `access_bundle_id` (str): the ID of the access bundle
- `user_ids` (List[str], optional): the IDs of the users to revoke the access bundle from
- `machine_identity_ids` (List[str], optional): the IDs of the machine identities to revoke the access bundle from
- `group_ids` (List[str], optional): the IDs of the groups to revoke the access bundle from

**Returns:**
- `AgentVaultGrantChangeResponse`: the revoked grants in `members`, and the users, machine identities, and groups that didn't have the access bundle in `skipped`

### `agent_vault.delegations`

This sub-class manages [delegations](/documentation/platform/agent-vault/sessions-on-behalf-of-users), which let a machine identity [create sessions on behalf of users](#create-a-session-on-behalf-of-a-user).

To use any method in this section, the client must log in as a user or machine identity with the **Admin** role in [Agent Vault](/documentation/platform/agent-vault/access-control#product-membership). A machine identity without the role can still get its own delegation.

<Note>
  `agent_vault` requires `infisicalsdk` version 1.2.0 or newer.
</Note>

#### List delegations

```python
delegations = client.agent_vault.delegations.list(
    machine_identity_ids=["<machine-identity-id>"], # Optional
    limit=100, # Optional
    offset=0 # Optional
)
```

**Parameters:**
- `machine_identity_ids` (List[str], optional): the IDs of the machine identities whose delegations to list (up to 100)
- `limit` (int, optional): the maximum number of delegations to return, from 1 to 100 (defaults to `100`)
- `offset` (int, optional): the number of delegations to skip (defaults to `0`)

**Returns:**
- `ListAgentVaultDelegationsResponse`: the delegations in `delegations`, and the total number of matching delegations in `totalCount` (each delegation's `missingAccessBundles` is `None`; call `get` for it)

#### Get delegation

Get which users a machine identity can create sessions on behalf of. If the machine identity has no delegation, `get` raises an `APIError` whose `status_code` is `404`. To catch the error, import the class with `from infisical_sdk import APIError`.

```python
delegation = client.agent_vault.delegations.get(
    machine_identity_id="<machine-identity-id>"
)
```

**Parameters:**
- `machine_identity_id` (str): the ID of the machine identity

**Returns:**
- `AgentVaultDelegation`: the delegation, including `missingAccessBundles`

`missingAccessBundles` lists the access bundles that the delegation's users can use and the machine identity can't. A session on behalf of a user can use only an access bundle that both the user and the machine identity can use, so the machine identity can't create sessions with those access bundles. If a machine identity without the **Admin** role gets its own delegation, `missingAccessBundles` is empty.

#### Set delegation

Set which users a machine identity can create sessions on behalf of. The new delegation replaces any delegation that the machine identity has.

```python
from infisical_sdk import AgentVaultDelegationScope

delegation = client.agent_vault.delegations.set(
    machine_identity_id="<machine-identity-id>",
    scope=AgentVaultDelegationScope.SELECTED,
    user_ids=["<user-id>"], # Optional
    group_ids=["<group-id>"] # Optional
)
```

**Parameters:**
- `machine_identity_id` (str): the ID of the machine identity, which must be a member of Agent Vault
- `scope` (Union[AgentVaultDelegationScope, str]): either `AgentVaultDelegationScope.SELECTED` (`"selected"`) for only the users and groups that you pass, or `AgentVaultDelegationScope.ALL_MEMBERS` (`"all-members"`) for every Agent Vault member, admins included
- `user_ids` (List[str], optional): with `AgentVaultDelegationScope.SELECTED`, the IDs of the users that the machine identity can act on behalf of (up to 100)
- `group_ids` (List[str], optional): with `AgentVaultDelegationScope.SELECTED`, the IDs of the groups whose members the machine identity can act on behalf of (up to 100)

**Returns:**
- `AgentVaultDelegation`: the delegation, with `missingAccessBundles`

With `AgentVaultDelegationScope.SELECTED`, pass at least one user or group. With `AgentVaultDelegationScope.ALL_MEMBERS`, pass no users or groups. To stop the machine identity from acting on behalf of anyone, [delete the delegation](#delete-delegation).

Each user and group must be a member of Agent Vault. If a user is in Agent Vault only through a group, pass the group instead.

#### List available users and groups

List the Agent Vault users and groups that you can add to a machine identity's delegation.

```python
from infisical_sdk import AgentVaultMemberType

members = client.agent_vault.delegations.list_available_subjects(
    machine_identity_id="<machine-identity-id>",
    actor_type=AgentVaultMemberType.USER, # Optional
    search="jsmith", # Optional
    limit=20, # Optional
    offset=0 # Optional
)
```

**Parameters:**
- `machine_identity_id` (str): the ID of the machine identity
- `actor_type` (Union[AgentVaultMemberType, str], optional): either `AgentVaultMemberType.USER` (`"user"`) to list only users or `AgentVaultMemberType.GROUP` (`"group"`) to list only groups (defaults to listing both)
- `search` (str, optional): text to find in user names, usernames, email addresses, and group names
- `limit` (int, optional): the maximum number of users and groups to return, from 1 to 100 (defaults to `20`)
- `offset` (int, optional): the number of users and groups to skip (defaults to `0`)

**Returns:**
- `ListAgentVaultMembersResponse`: the users and groups in `members`, and the total number of matching users and groups in `totalCount`

#### Add users and groups

Add users and groups to a machine identity's delegation. The users and groups that are already in the delegation stay in it. Pass at least one ID.

- If the machine identity has no delegation, `add_subjects` creates one with the `AgentVaultDelegationScope.SELECTED` scope
- If the delegation covers all members, you can't add users or groups to it

```python
delegation = client.agent_vault.delegations.add_subjects(
    machine_identity_id="<machine-identity-id>",
    user_ids=["<user-id>"], # Optional
    group_ids=["<group-id>"] # Optional
)
```

**Parameters:**
- `machine_identity_id` (str): the ID of the machine identity
- `user_ids` (List[str], optional): the IDs of the users to add (up to 100)
- `group_ids` (List[str], optional): the IDs of the groups to add (up to 100)

**Returns:**
- `AgentVaultDelegation`: the delegation after the change, with `missingAccessBundles`

#### Remove users and groups

Remove users and groups from a machine identity's delegation. Pass at least one ID.

- If the delegation no longer covers a user, the proxy refuses the sessions that the machine identity created on behalf of the user until the delegation covers the user again (to end those sessions for good, [revoke them](#revoke-session))
- If you remove the last user or group, Infisical deletes the delegation

```python
delegation = client.agent_vault.delegations.remove_subjects(
    machine_identity_id="<machine-identity-id>",
    user_ids=["<user-id>"], # Optional
    group_ids=["<group-id>"] # Optional
)
```

**Parameters:**
- `machine_identity_id` (str): the ID of the machine identity
- `user_ids` (List[str], optional): the IDs of the users to remove (up to 100)
- `group_ids` (List[str], optional): the IDs of the groups to remove (up to 100)

**Returns:**
- `Optional[AgentVaultDelegation]`: the delegation after the change, with `missingAccessBundles`, or `None` if Infisical deleted the delegation

#### Delete delegation

Stop a machine identity from creating sessions on behalf of users. The proxy refuses the sessions that the machine identity already created on behalf of users until a delegation covers those users again. To end those sessions for good, [revoke them](#revoke-session).

```python
delegation = client.agent_vault.delegations.delete(
    machine_identity_id="<machine-identity-id>"
)
```

**Parameters:**
- `machine_identity_id` (str): the ID of the machine identity

**Returns:**
- `AgentVaultDelegation`: the deleted delegation, with `missingAccessBundles` set to `None`
