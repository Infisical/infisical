A Convex Secret Sync pushes secrets from Infisical into a Convex deployment's environment variables, where your Convex functions read them at runtime. Each Infisical secret becomes a Convex environment variable with the same name, unless you customize key names to add a prefix or suffix.

<Note>
    The Convex Secret Sync requires a [Convex app connection](/integrations/app-connections/convex). This guide walks you through creating a project-scoped app connection.
</Note>

## Prerequisites

- A [project with secrets configured](/documentation/platform/secrets-mgmt/quick-starts/deliver-first-secret)
- A [Convex account](https://dashboard.convex.dev) with a deployment you can manage
- A [personal access token](/integrations/app-connections/convex#create-a-personal-access-token-in-convex) for a Convex account that can manage the deployment you plan to sync to

## Step 1: Set up the sync in Infisical

<Tip>
    To create the sync using the API, use the Convex [Create](/api-reference/endpoints/secret-syncs/convex/create) endpoint.
</Tip>

<Steps>
    <Step>
        In your project, go to **Integrations** and open the **Secret Syncs** tab. Select **+ Add Sync**.

        ![Secret Syncs Tab](/images/secret-syncs/general/secret-sync-tab.png)

        Then, select the **Convex** sync.
    </Step>
    <Step>
        Under **Source**, choose which secrets to sync from Infisical:

        - **Environment**: The project environment to retrieve secrets from
        - **Secret Path**: The folder path to retrieve secrets from
        - **Include secrets from all subfolders**: Also syncs the secrets in every folder beneath the path

        <Note>
            Convex rejects an environment variable name if any of the following is true:

            - The name starts with a digit, or contains a character other than a letter, a digit, or an underscore
            - The name is longer than 256 characters
            - The name is `CONVEX_CLOUD_URL` or `CONVEX_SITE_URL`, which Convex sets on every deployment

            If any secret has a name Convex rejects, the sync fails without writing any secrets, and the error names each rejected secret.
        </Note>

        <Tip>
            If you need to sync secrets from multiple folder locations, use [secret imports](/documentation/platform/secret-reference#secret-imports).
        </Tip>

        Then select **Continue**.
    </Step>
    <Step>
        Under **Destination**, create or select the Convex app connection the sync will use, then choose the deployment that receives the secrets.

        <Tabs>
            <Tab title="Create a new app connection">
                Under **Convex Connection**, select **Create Connection** in the dropdown, then fill in:

                <ConnectionFormFields />

                Select **Connect to Convex**. Infisical returns you to the sync form with the new connection selected.

                <Note>
                    This creates a connection scoped to the current project. To share the connection across other projects, [create it at the organization level](/integrations/app-connections/convex#setup-convex-connection-in-infisical) first, then select it here.
                </Note>
            </Tab>
            <Tab title="Use an existing connection">
                Under **Convex Connection**, select the app connection you'd like to use.
            </Tab>
        </Tabs>

        - **Deployment**: The Convex deployment to sync secrets to, from the cloud deployments the connection can access (local deployments aren't listed, because Infisical can't reach them)

        Then select **Continue**.
    </Step>
    <Step>
        Under **Initial Sync Behavior**, choose how Infisical handles environment variables that already exist in the deployment on the first sync:

        - **Overwrite Destination Secrets**: Infisical writes its secrets to the deployment without importing anything first
        - **Import Destination Secrets - Prioritize Infisical Values**: Infisical first imports the deployment's environment variables; if a name exists in both places, Infisical keeps its own value
        - **Import Destination Secrets - Prioritize Convex Values**: Infisical first imports the deployment's environment variables; if a name exists in both places, the Convex value replaces the Infisical value

        Then select **Continue**.
    </Step>
    <Step>
        Under **Sync Options**, choose how secrets are synced:

        - **Prevent secret deletion**: When enabled, Infisical adds and updates environment variables in Convex but never deletes them; enable this if you manage some Convex environment variables outside of Infisical
        - **Auto-sync on changes**: When enabled, secrets sync to Convex automatically as the source changes; turn it off to sync manually only
        - **Customize key names**: Adds a prefix or suffix to every synced name, using `{{secretKey}}` for the original name and `{{environment}}` for the environment slug

        <Warning>
            Convex environment variables belong to the whole deployment, so a sync can change environment variables that were created outside Infisical. If you don't customize key names, the sync treats every environment variable in the deployment as one it manages:

            - If a Convex environment variable has the same name as an Infisical secret, the sync overwrites the Convex environment variable's value
            - If **Prevent secret deletion** is off, every Convex environment variable that isn't in Infisical is deleted

            With customized key names, the sync writes only names with your prefix or suffix, and deletes only Convex environment variables whose names match it.

            Before the first sync, customize key names or keep **Prevent secret deletion** on. **Prevent secret deletion** is on by default when you create the sync in the UI, but off unless you set `disableSecretDeletion` when you create it through the API.
        </Warning>

        Then select **Continue**.
    </Step>
    <Step>
        Give the sync a **Name** and an optional **Description**. The name must be slug-friendly.

        Then select **Continue**.
    </Step>
    <Step>
        Review your Convex Sync configuration, then select **Create Sync**.

        <Check>
            The sync is created. If **Auto-sync on changes** is enabled, it begins syncing secrets to your Convex deployment right away.
        </Check>
    </Step>
</Steps>
