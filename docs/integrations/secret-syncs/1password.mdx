A 1Password Secret Sync pushes secrets from Infisical into a 1Password vault. Each Infisical secret becomes a 1Password item whose title matches the secret's key, with the secret value stored in a field of your choice.

<Note>
    The 1Password Secret Sync requires a [1Password app connection](/integrations/app-connections/1password). This guide walks you through creating a project-scoped app connection.
</Note>

## Prerequisites

- A [project with secrets configured](/documentation/platform/secrets-mgmt/quick-starts/deliver-first-secret)

## Step 1: Set up in 1Password

## Step 2: Set up the sync in Infisical

<Tip>
    To create the sync using the API, use the [Create 1Password Sync](/api-reference/endpoints/secret-syncs/1password/create) endpoint.
</Tip>

<Steps>
    <Step title="Add the sync" titleSize="h3">
        In your Infisical project, go to **Integrations** and open the **Secret Syncs** tab. Select **+ Add Sync**.

        ![Secret Syncs Tab](/images/secret-syncs/general/secret-sync-tab.png)

        Then, select the **1Password** sync:

        ![Select 1Password](/images/secret-syncs/1password/select-option.png)
    </Step>
    <Step title="Configure the source" titleSize="h3">
        Configure the **Source** from where secrets should be retrieved in Infisical:

        ![Configure Source](/images/secret-syncs/1password/configure-source.png)

        - **Environment**: The project environment to retrieve secrets from.
        - **Secret Path**: The folder path to retrieve secrets from.

        <Tip>
            If you need to sync secrets from multiple folder locations, check out [secret imports](/documentation/platform/secret-reference#secret-imports).
        </Tip>

        Then select **Continue** to configure the sync's destination.
    </Step>
    <Step title="Configure the app connection" titleSize="h3">
        The sync needs a 1Password [app connection](/integrations/app-connections) to function:

        <Tabs>
            <Tab title="Create a new app connection">
                Under **1Password Connection**, select an existing app connection, or select **+ Create New Connection** and complete the form:

                <ConnectionFormFields />

                ![1Password Connection Modal](/images/app-connections/1password/app-connection-modal.png)

                Then, select **Connect to 1Password**.

                <Note>
                    This creates a connection scoped to the current project. To share the connection across other projects, you can [create it at the organization level](/integrations/app-connections/1password#create-the-organization-level-connection) first, then select it here.
                </Note>
            </Tab>
            <Tab title="Use an existing connection">
                Under **1Password Connection**, select the app connection you'd like to use.
            </Tab>
        </Tabs>
    </Step>
    <Step title="Configure the target vault" titleSize="h3">
        Next, configure the vault where secrets should be deployed:

        ![Configure Destination](/images/secret-syncs/1password/configure-destination.png)

        - **Vault**: The 1Password vault to sync secrets to.
        - **Value Label**: The label of the 1Password item field that will hold your secret value.

        When you're done, select **Continue**.
    </Step>
    <Step title="Configure the sync options" titleSize="h3">
        Configure the **Sync Options** to specify how secrets should be synced.

        ![Configure Sync Options](/images/secret-syncs/1password/configure-sync-options.png)

        - **Initial Sync Behavior**: How Infisical resolves the initial sync.
            - **Overwrite Destination Secrets**: Removes any secrets at the destination not present in Infisical.
            - **Import Secrets (Prioritize Infisical)**: Imports secrets from the destination before syncing, prioritizing values from Infisical when keys conflict.
            - **Import Secrets (Prioritize 1Password)**: Imports secrets from the destination before syncing, prioritizing values from 1Password when keys conflict.
        - **Key Schema**: Template that transforms secret names when syncing. Use `{{secretKey}}` for the original secret name and `{{environment}}` for the environment.
            <Note>
                We highly recommend using a Key Schema so Infisical only manages the specific keys you intend, keeping everything else untouched.
            </Note>
        - **Auto-Sync Enabled**: When enabled, secrets sync automatically as the source changes. Disable to sync manually only.
        - **Disable Secret Deletion**: When enabled, Infisical does not remove secrets from the destination. Enable this if you intend to manage some secrets manually outside of Infisical.

        When you're done, select **Continue**.
    </Step>
    <Step title="Configure the details" titleSize="h3">
        Give the sync a **Name** and an optional **Description**, then select **Next**. The name must be slug-friendly.

        ![Configure Details](/images/secret-syncs/1password/configure-details.png)
    </Step>
    <Step title="Review and create" titleSize="h3">
        Review your 1Password Sync configuration, then select **Create Sync**.

        ![Review Configuration](/images/secret-syncs/1password/review-configuration.png)

        ![Sync Created](/images/secret-syncs/1password/sync-created.png)

        <Check>
            The sync is created. If [auto-sync](#sync-options) is enabled, it begins syncing your secrets to the selected context right away.
        </Check>
    </Step>
</Steps>

## FAQ

<AccordionGroup>
    <Accordion title="How are different 1Password item types treated?">
        Infisical can only perform CRUD operations on the following item types:
        - API Credentials
    </Accordion>
    <Accordion title="What is a 'Value Label'?">
        It's the label of the 1Password item field which will hold your secret value. For example, if you were to sync the Infisical secret 'API_KEY: sk-1234', the 1Password item equivalent would have an item title of 'API_KEY', and a field on that item 'value: sk-1234'. The field label 'value' is what gets changed by this option.
    </Accordion>
</AccordionGroup>
