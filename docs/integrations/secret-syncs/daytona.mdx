---
title: "Daytona sync"
description: "Learn how to configure a Daytona sync for Infisical."
---

**Prerequisites:**
- Set up and add secrets to [Infisical Cloud](https://app.infisical.com)
- Create a [Daytona connection](/integrations/app-connections/daytona)

<Note>
    Daytona secret names must start with a letter or an underscore, and can contain only letters, digits, hyphens, and underscores. A sync that includes a key Daytona rejects fails and names the offending key, so no secrets are written. Use a **key schema** to reshape names that do not fit.

    The key schema itself is checked against the same rule when you create or update the sync, so a schema containing a slash is rejected up front rather than failing on every run.
</Note>

<Note>
    Infisical does not set the **allowed hosts** list on the secrets it creates, so they are unrestricted in the same way as a secret created in Daytona without one. Daytona substitutes the real value for its placeholder on requests to any host.

    To restrict a secret, set its allowed hosts in Daytona. This sync only ever writes the value, so a list you set there is preserved on later syncs.
</Note>

<Tabs>
    <Tab title="Infisical UI">
        <Steps>
            <Step title="Add sync">
                Navigate to **Project** > **Integrations** and select the **Secret Syncs** tab. Select the **Add Sync** button.

                ![Secret Syncs Tab](/images/secret-syncs/general/secret-sync-tab.png)
            </Step>
            <Step title="Select 'Daytona'">
                Select the **Daytona** option from the list of available secret syncs.
            </Step>
            <Step title="Configure source">
                Configure the **Source** from where secrets should be retrieved, then select **Next**.

                - **Environment**: The project environment to retrieve secrets from.
                - **Secret Path**: The folder path to retrieve secrets from.

                <Tip>
                    If you need to sync secrets from multiple folder locations, check out [secret imports](/documentation/platform/secret-reference#secret-imports).
                </Tip>
            </Step>
            <Step title="Configure destination">
                Configure the **Destination** to where secrets should be deployed, then select **Next**.

                - **Daytona Connection**: The Daytona connection to authenticate with. Its API key determines which Daytona organization receives the secrets.
                - **Organization Name**: A label for that organization. It is shown in Infisical only and does not affect where secrets are written.
            </Step>
            <Step title="Configure sync options">
                Configure the **Sync Options** to specify how secrets should be synced, then select **Next**.

                - **Initial Sync Behavior**: Determines how Infisical should resolve the initial sync.
                    - **Overwrite Destination Secrets**: Removes any secrets in the Daytona organization not present in Infisical.

                    <Note>
                        Daytona never returns a secret's value through its API, so this sync cannot import existing secrets from Daytona into Infisical. Only **Overwrite Destination Secrets** is available as an initial sync behavior.
                    </Note>
                - **Key Schema**: Template that determines how secret names are transformed when syncing, using `{{secretKey}}` as a placeholder for the original secret name and `{{environment}}` for the environment.
                <Note>
                    We highly recommend using a key schema to ensure that Infisical only manages the specific keys you intend, keeping everything else untouched.
                </Note>
                - **Auto-Sync Enabled**: If enabled, secrets are automatically synced from the source location when changes occur. Disable to enforce manual syncing only.
                - **Disable Secret Deletion**: If enabled, Infisical does not remove secrets from the Daytona organization. Enable this option if you intend to manage some secrets manually outside of Infisical.
            </Step>
            <Step title="Configure details">
                Configure the **Details** of your Daytona sync, then select **Next**.

                - **Name**: The name of your sync. Must be slug-friendly.
                - **Description**: An optional description for your sync.
            </Step>
            <Step title="Review configuration">
                Review your Daytona sync configuration, then select **Create Sync**.
            </Step>
            <Step title="Sync created">
                If enabled, your Daytona sync begins syncing your secrets to the destination organization.
            </Step>
        </Steps>
    </Tab>
    <Tab title="API">
        To create a **Daytona sync**, make an API request to the [Create Daytona Sync](/api-reference/endpoints/secret-syncs/daytona/create) API endpoint.

        ### Sample request

        ```bash Request
        curl    --request POST \
                --url https://app.infisical.com/api/v1/secret-syncs/daytona \
                --header 'Content-Type: application/json' \
                --data '{
                    "name": "my-daytona-sync",
                    "projectId": "3c90c3cc-0d44-4b50-8888-8dd25736052a",
                    "description": "an example sync",
                    "connectionId": "3c90c3cc-0d44-4b50-8888-8dd25736052a",
                    "environment": "dev",
                    "secretPath": "/my-secrets",
                    "isAutoSyncEnabled": true,
                    "syncOptions": {
                        "initialSyncBehavior": "overwrite-destination",
                        "disableSecretDeletion": false
                    },
                    "destinationConfig": {
                        "organizationName": "My Daytona Organization"
                    }
                }'
        ```
