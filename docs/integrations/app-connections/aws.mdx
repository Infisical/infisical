An AWS connection authenticates Infisical to your AWS account, either by assuming an [IAM role](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles.html) or with an [IAM user's access keys](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_credentials_access-keys.html). We recommend assuming a role, since Infisical never holds a long-lived credential for it.

With Launch Stack, Infisical opens the AWS CloudFormation console with a stack that creates the role for you. The stack fills in the AWS account to trust and the External ID, and grants permissions for only the integrations you select.

<Note>
    This guide doesn’t configure any behavior—it just authenticates Infisical with AWS. Once the app connection is ready, you can [use it to set up integrations](#step-2-configure-integrations).
</Note>

## Prerequisites

- An AWS account where you can create CloudFormation stacks and IAM roles

<UseCase use="pam-recording" hideWhenEmpty>
    - An [Amazon S3 bucket](https://docs.aws.amazon.com/AmazonS3/latest/userguide/create-bucket-overview.html) for PAM session recordings
</UseCase>

<UseCase use="agent-vault-session-logs" hideWhenEmpty>
    - An [Amazon S3 bucket](https://docs.aws.amazon.com/AmazonS3/latest/userguide/create-bucket-overview.html) for Agent Vault session logs
</UseCase>

<UseCase use="private-ca" hideWhenEmpty>
    - An [AWS Private CA](https://docs.aws.amazon.com/privateca/latest/userguide/create-CA.html) for Infisical to issue certificates from
</UseCase>

<UseCase use="acm-public-ca,acme-route53" hideWhenEmpty>
    - A [Route 53 hosted zone](https://docs.aws.amazon.com/Route53/latest/DeveloperGuide/CreatingHostedZone.html) for the domain you'll issue certificates for
</UseCase>

    Your AWS app connection is ready to use.
</Check>

### Launch Stack on a self-hosted instance

If you self-host Infisical, Launch Stack trusts the AWS account of your instance's credentials. If Infisical can't determine that account, for example because your instance has no AWS credentials, Launch Stack shows the manual steps instead of a launch link.

To choose the account yourself, set `INF_APP_CONNECTION_AWS_TRUSTED_ACCOUNT_ID` to the 12-digit ID of the account to trust.

To load the stack from your own copy of the template, set `INF_APP_CONNECTION_AWS_TEMPLATE_BASE_URL` to the base URL of your copy. Place the template from [`cloudformation/aws-app-connection`](https://github.com/Infisical/infisical/tree/main/cloudformation/aws-app-connection) at `<base-url>/aws-app-connection/v1/infisical-aws-app-connection.yaml`.

Both variables are listed in [Environment variables](/self-hosting/configuration/envars#app-connections).

<UseCase use="pam-recording" hideWhenEmpty>
    ## Add a CORS rule for PAM session recording

    Your browser downloads recordings directly from the bucket during playback, so the bucket needs a CORS rule.

    <Steps>
        <Step>
            In the Amazon S3 console, open the recording bucket, go to **Permissions**, and select **Edit** under **Cross-origin resource sharing (CORS)**.
        </Step>
        <Step>
            Paste this rule, then select **Save changes**. If the bucket already has CORS rules, add this rule's object to the existing array instead of replacing it, so other applications that use the bucket keep working:

            <CodeGroup>
                ```json Infisical Cloud (US)
                [
                    {
                        "AllowedHeaders": ["*"],
                        "AllowedMethods": ["GET"],
                        "AllowedOrigins": ["https://app.infisical.com"],
                        "ExposeHeaders": [],
                        "MaxAgeSeconds": 3600
                    }
                ]
                ```

                ```json Infisical Cloud (EU)
                [
                    {
                        "AllowedHeaders": ["*"],
                        "AllowedMethods": ["GET"],
                        "AllowedOrigins": ["https://eu.infisical.com"],
                        "ExposeHeaders": [],
                        "MaxAgeSeconds": 3600
                    }
                ]
                ```
            </CodeGroup>

            If you self-host Infisical or use a dedicated instance, replace `AllowedOrigins` with your instance's URL.
        </Step>
    </Steps>
</UseCase>

## Add permissions to an existing connection

A role that Launch Stack created has permissions for only the integrations you selected. To use the connection for another integration, update the stack in AWS so the role gets the extra permissions. Infisical doesn't update the stack for you. It opens the update in the AWS console and lists the values to use, and you make the change there.

Update Stack is available only for connections that you created with Launch Stack, and only if you can edit the connection. If you created the role yourself or the connection uses an access key, add the permissions in IAM instead, as in [Set up the connection without Launch Stack](#set-up-the-connection-without-launch-stack).

<Steps>
    <UpdateStackSteps />
</Steps>

<Warning>
    If you clear an integration, updating the stack removes its permissions from the role, and any sync or feature that relies on them fails.
</Warning>

**Mark as updated** doesn't check AWS. It saves the integrations you selected as the record of what the role can do, and nothing is saved if you close the sheet without selecting it.

### Parameters for each integration

Each integration has a toggle parameter on the stack. Some integrations also need the name or ID of the resource they use. Infisical lists the parameters that your selection changes, so you only need this table if you can't use Update Stack, for example because you manage the connection through the API.

In that case, update the stack as in the steps above, with the current template at `https://infisical-static-assets.s3.us-east-1.amazonaws.com/aws-app-connection/v1/infisical-aws-app-connection.yaml`. If you self-host Infisical and load the template from your own copy, use the URL of that copy instead (see [Launch Stack on a self-hosted instance](#launch-stack-on-a-self-hosted-instance)).

| Integration | Toggle parameter | Extra parameters to enter |
| --- | --- | --- |
| AWS Secrets Manager sync | `EnableSecretsManager` | `EnableSecretsManagerKms` set to `true` if the sync uses a customer managed KMS key |
| AWS Parameter Store sync | `EnableParameterStore` | `EnableParameterStoreKms` set to `true` if the sync uses a customer managed KMS key |
| AWS IAM user secret rotation | `EnableIamRotation` | None |
| AWS honey tokens | `EnableHoneyTokens` | None |
| AWS Certificate Manager sync | `EnableAcmSync` | None |
| AWS Elastic Load Balancer sync | `EnableElbSync` | None |
| AWS Secrets Manager certificate sync | `EnablePkiSecretsManager` | None |
| AWS Private CA | `EnablePrivateCa` | `PrivateCaArn` |
| AWS Certificate Manager public CA | `EnableAcmPublicCa` | `Route53HostedZoneId` |
| ACME CA with Route 53 | `EnableAcmeRoute53` | `Route53HostedZoneId` |
| PAM session recording | `EnablePamRecording` | `PamRecordingBucket` |
| Agent Vault session logs | `EnableAgentVaultSessionLogs` | `AgentVaultSessionLogsBucket` and `AgentVaultSessionLogsKeyPrefix` |

Set a toggle to `true` to add the integration's permissions, or to `false` to remove them. Leave every other parameter on its existing value. If you update the stack without Update Stack, Infisical's record of the connection's integrations doesn't change.

## Set up the connection without Launch Stack

Use one of these methods if you can't use Launch Stack, for example because you use an AWS partition other than AWS Commercial. In each method, you create the credentials in AWS, add permissions to them, and then enter them in the connection form.

<Accordion title="Manual role creation" id="manual-role-creation">
    <SelfHostedInstance />

    <Steps>
        <CreateIamRole externalId="required" />
        <AddPermissions />
        <Step>
            In Infisical, open the connection form as in [Step 1](#step-1-create-the-connection-with-launch-stack). Ignore Launch Stack, and fill out the form's fields:

            - **Name**: A descriptive name for the connection
            - **Description** (optional): A note for future reference
            - **Method**: **Assume Role (Recommended)**
            - **Role ARN**: The role's ARN, shown in the **Summary** section of the role in the IAM console (Infisical accepts an ARN in any AWS partition, including a custom one)
            - **STS Endpoint URL** (optional): A regional AWS STS endpoint to use instead of AWS's default, such as `https://sts.us-east-1.amazonaws.com` (leave it empty unless your network can't reach the default)

            Then, select **Connect to AWS**.
        </Step>
    </Steps>
</Accordion>

<Accordion title="Access key" id="access-key">
    <Steps>
        <CreateIamUser />
        <AddPermissions accessKey />
        <Step>
            In Infisical, open the connection form as in [Step 1](#step-1-create-the-connection-with-launch-stack), and fill out the form's fields:

            - **Name**: A descriptive name for the connection
            - **Description** (optional): A note for future reference
            - **Method**: **Access Key**
            - **Access Key ID**: The access key ID you copied from the IAM user
            - **Secret Access Key**: The secret access key you copied from the IAM user

            Then, select **Connect to AWS**.
        </Step>
    </Steps>
</Accordion>
