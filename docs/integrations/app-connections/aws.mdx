An AWS connection authenticates Infisical to your AWS account, either by assuming an [IAM role](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles.html) or with an [IAM user's access keys](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_credentials_access-keys.html).

<Note>
    This guide doesn’t configure any behavior—it just authenticates Infisical with AWS. Once the app connection is ready, you can [use it to set up integrations](#step-4-configure-integrations).
</Note>

## Prerequisites

- An AWS account where you can create IAM roles or users and attach policies to them

## Step 1: Create an IAM role or IAM user

Infisical can assume an IAM role in your account, or sign in as an IAM user with an access key. An IAM role is recommended, because Infisical never holds a long-lived credential for it.

## Step 2: Add permissions

Next, add the required policies to the IAM role or user from [Step 1](#step-1-create-an-iam-role-or-iam-user):

<Steps>
    <Step>
        In the IAM console, open the IAM role or user.
    </Step>
    <Step>
        On the **Permissions** tab, select **Add permissions** > **Create inline policy**.

        ![IAM Role Create Policy](/images/app-connections/aws/assume-role-create-policy.png)
    </Step>
    <Step>
        Switch to the **JSON** editor. Then, add separate inline policies for each integration you want to use the connection with. For each policy, paste

        <AccordionGroup>
            <UseCase use="secrets-manager">
                <Accordion title="AWS Secrets Manager sync">
                    Lets Infisical read, create, update, tag, and delete secrets in [AWS Secrets Manager](/integrations/secret-syncs/aws-secrets-manager):

                    ```json
                    {
                        "Version": "2012-10-17",
                        "Statement": [
                            {
                                "Sid": "AllowSecretsManagerAccess",
                                "Effect": "Allow",
                                "Action": [
                                    "secretsmanager:ListSecrets",
                                    "secretsmanager:GetSecretValue",
                                    "secretsmanager:BatchGetSecretValue",
                                    "secretsmanager:CreateSecret",
                                    "secretsmanager:UpdateSecret",
                                    "secretsmanager:DeleteSecret",
                                    "secretsmanager:DescribeSecret",
                                    "secretsmanager:TagResource",
                                    "secretsmanager:UntagResource"
                                ],
                                "Resource": "*"
                            }
                        ]
                    }
                    ```

                    If the sync encrypts secrets with a customer managed KMS key, add this statement too, and add the IAM role or user as a key user of that key:

                    ```json
                    {
                        "Sid": "AllowKmsKeyForSecretsManager",
                        "Effect": "Allow",
                        "Action": [
                            "kms:ListAliases",
                            "kms:DescribeKey",
                            "kms:Encrypt",
                            "kms:Decrypt",
                            "kms:GenerateDataKey"
                        ],
                        "Resource": "*"
                    }
                    ```

                    ![KMS Key IAM Role User](/images/app-connections/aws/kms-key-user.png)
                </Accordion>
            </UseCase>

            <UseCase use="parameter-store">
                <Accordion title="AWS Parameter Store sync">
                    Lets Infisical read, write, tag, and delete parameters in [AWS Systems Manager Parameter Store](/integrations/secret-syncs/aws-parameter-store). The three tag actions are needed only if the sync adds tags:

                    ```json
                    {
                        "Version": "2012-10-17",
                        "Statement": [
                            {
                                "Sid": "AllowSSMAccess",
                                "Effect": "Allow",
                                "Action": [
                                    "ssm:PutParameter",
                                    "ssm:GetParameters",
                                    "ssm:GetParametersByPath",
                                    "ssm:DescribeParameters",
                                    "ssm:DeleteParameters",
                                    "ssm:ListTagsForResource",
                                    "ssm:AddTagsToResource",
                                    "ssm:RemoveTagsFromResource"
                                ],
                                "Resource": "*"
                            }
                        ]
                    }
                    ```

                    If the sync encrypts parameters with a customer managed KMS key, add this statement too, and add the IAM role or user as a key user of that key:

                    ```json
                    {
                        "Sid": "AllowKmsKeyForParameterStore",
                        "Effect": "Allow",
                        "Action": [
                            "kms:ListAliases",
                            "kms:DescribeKey",
                            "kms:Encrypt",
                            "kms:Decrypt"
                        ],
                        "Resource": "*"
                    }
                    ```

                    ![KMS Key IAM Role User](/images/app-connections/aws/kms-key-user.png)
                </Accordion>
            </UseCase>

                    ```json
                                "Effect": "Allow",
                    ```

                    ```json
                                "Sid": "AllowCertificateManagerAccess",

                                "Action": [
                                    "acm:ListCertificates",
                    ```

            <UseCase use="elb-sync">

                    ```json
                            {
                                "Sid": "AllowCertificateManagerAccess",
                                "Effect": "Allow",
                    ```

            <UseCase use="pki-secrets-manager">
                <Accordion title="AWS Secrets Manager certificate sync">
                    Lets Infisical store certificates as secrets in [AWS Secrets Manager](/documentation/platform/pki/applications/certificate-syncs/aws-secrets-manager):

                    ```json
                    {
                        "Version": "2012-10-17",
                        "Statement": [
                            {
                                "Sid": "AllowSecretsManagerCertificateSync",
                                "Effect": "Allow",
                                "Action": [
                                    "secretsmanager:ListSecrets",
                                    "secretsmanager:GetSecretValue",
                    ```

            <UseCase use="private-ca">
                <Accordion title="AWS Private CA">
                    Lets Infisical issue and revoke certificates through [AWS Private CA](/documentation/platform/pki/ca/aws-pca). Replace the `Resource` with your CA's ARN, or list several ARNs if Infisical uses more than one CA:

                    ```json
                    {
                        "Version": "2012-10-17",
                        "Statement": [
                            {
                                "Sid": "AllowAwsPrivateCAAccess",
                                "Effect": "Allow",
                                "Action": [
                                    "acm-pca:DescribeCertificateAuthority",
                                    "acm-pca:GetCertificateAuthorityCertificate",
                                    "acm-pca:IssueCertificate",
                                    "acm-pca:GetCertificate",
                                    "acm-pca:RevokeCertificate"
                                ],
                                "Resource": "arn:aws:acm-pca:<region>:<account-id>:certificate-authority/<ca-id>"
                            }
                        ]
                    }
                    ```

                    If you restrict `acm-pca:IssueCertificate` with an `acm-pca:TemplateArn` condition, include every template Infisical uses, or issuance fails with a permission error:

                    - `arn:aws:acm-pca:::template/BlankEndEntityCertificate_APICSRPassthrough/V1` for end-entity certificates
                    - `arn:aws:acm-pca:::template/SubordinateCACertificate_PathLen{0,1,2,3}_APICSRPassthrough/V1` for [CA certificates](/documentation/platform/pki/ca/aws-pca#issuing-ca-certificates)
                </Accordion>
            </UseCase>

            <UseCase use="acm-public-ca">
                <Accordion title="AWS Certificate Manager public CA">
                    Lets Infisical request publicly trusted certificates from [AWS Certificate Manager](/documentation/platform/pki/ca/aws-acm-public-ca) and prove domain ownership through Route 53. `acm:RequestCertificate` needs `"Resource": "*"`, because the certificate's ARN doesn't exist until the request succeeds:

                    ```json
                    {
                        "Version": "2012-10-17",
                        "Statement": [
                            {
                                "Sid": "AllowAcmPublicCaAccess",
                                "Effect": "Allow",
                                "Action": [
                                    "acm:RequestCertificate",
                                    "acm:DescribeCertificate",
                                    "acm:ExportCertificate",
                                    "acm:RenewCertificate",
                                    "acm:RevokeCertificate",
                                    "acm:ListCertificates"
                                ],
                                "Resource": "*"
                            },
                            {
                                "Sid": "AllowRoute53ForAcmValidation",
                                "Effect": "Allow",
                                "Action": [
                                    "route53:GetHostedZone",
                                    "route53:ChangeResourceRecordSets"
                                ],
                                "Resource": "arn:aws:route53:::hostedzone/<hosted-zone-id>"
                            }
                        ]
                    }
                    ```

                    The ACM and Route 53 statements can also go on two separate connections, if a different AWS account owns the hosted zone.
                </Accordion>
            </UseCase>

            <UseCase use="acme-route53">
                <Accordion title="Route 53 for an ACME CA">
                    An [ACME CA](/documentation/platform/pki/ca/acme-ca) that proves domain ownership through Route 53 needs permission to write DNS records in your hosted zone. The ACME CA page has the policy.
                </Accordion>
            </UseCase>

            <UseCase use="honey-tokens">
                <Accordion title="AWS honey tokens">
                    Lets Infisical create and delete the IAM users behind [AWS honey tokens](/documentation/platform/honey-tokens/aws/setup). Honey token users are named with an `inf_ht_` prefix, so the IAM statement is limited to them:

                    ```json
                    {
                        "Version": "2012-10-17",
                        "Statement": [
                            {
                                "Sid": "HoneyTokenIAMManagement",
                                "Effect": "Allow",
                                "Action": [
                                    "iam:CreateUser",
                                    "iam:DeleteUser",
                                    "iam:CreateAccessKey",
                                    "iam:DeleteAccessKey"
                                ],
                                "Resource": "arn:aws:iam::*:user/inf_ht_*"
                            },
                            {
                                "Sid": "HoneyTokenStackVerification",
                                "Effect": "Allow",
                                "Action": ["cloudformation:DescribeStacks"],
                                "Resource": "*"
                            }
                        ]
                    }
                    ```
                </Accordion>
            </UseCase>

            <UseCase use="pam-recording">
                <Accordion title="PAM session recording">
                    Lets Infisical store and play back [PAM session recordings](/documentation/platform/pam/sessions/external-storage) in an S3 bucket. Replace `<bucket>` with the bucket you enter in the **Session Recording** card of a PAM account template:

                    ```json
                    {
                        "Version": "2012-10-17",
                        "Statement": [
                            {
                                "Sid": "AllowPamRecordingBucketAccess",
                                "Effect": "Allow",
                                "Action": ["s3:PutObject", "s3:GetObject"],
                                "Resource": "arn:aws:s3:::<bucket>/*"
                            },
                            {
                                "Sid": "AllowPamRecordingBucketTest",
                                "Effect": "Allow",
                                "Action": ["s3:ListBucket"],
                                "Resource": "arn:aws:s3:::<bucket>"
                            },
                            {
                                "Sid": "AllowPamRecordingConnectionTestCleanup",
                                "Effect": "Allow",
                                "Action": ["s3:DeleteObject"],
                                "Resource": "arn:aws:s3:::<bucket>/.test/*"
                            }
                        ]
                    }
                    ```

                    If you set a key prefix, such as `pam/prod`, add it to the two object ARNs: `arn:aws:s3:::<bucket>/pam/prod/*` and `arn:aws:s3:::<bucket>/pam/prod/.test/*`. The `ListBucket` statement keeps the bucket ARN.

                    When Infisical tests the bucket, it writes a probe object under `.test/` and then deletes it. That's the only object Infisical deletes. The bucket's lifecycle rules decide how long recordings are kept.

                    Your browser downloads recordings directly from the bucket during playback, so the bucket also needs this CORS rule. In the Amazon S3 console, open the bucket, go to **Permissions**, and select **Edit** under **Cross-origin resource sharing (CORS)**:

                    ```json
                    [
                        {
                            "AllowedHeaders": ["*"],
                            "AllowedMethods": ["GET"],
                            "AllowedOrigins": ["https://app.infisical.com"],
                            "ExposeHeaders": [],
                            "MaxAgeSeconds": 3600
                        }
                    ]
                    ```

                    If you use EU Cloud, replace `https://app.infisical.com` with `https://eu.infisical.com`. If you self-host Infisical, replace it with your instance's URL.
                </Accordion>
            </UseCase>

            <UseCase use="agent-vault-session-logs">
                <Accordion title="Agent Vault session logs">
                    [Agent Vault session logs](/documentation/platform/agent-vault/session-logs) need an S3 policy and a CORS rule on the bucket. The **Session Logs** dialog in Agent Vault generates both with your bucket and key prefix filled in, so copy them from there. The session logs page walks through the whole setup, including this connection.
                </Accordion>
            </UseCase>
        </AccordionGroup>
    </Step>

## Step 3: Create the app connection

Next, create the app connection in Infisical.

<Tip>
    To create the connection using the API, use the [Create AWS Connection](/api-reference/endpoints/app-connections/aws/create) endpoint.
</Tip>

<View title="Organization-level">
    <Steps>
        <Step>
            In the sidebar, select **Integrations**, then open the **App Connections** tab.

            ![App Connections Tab](/images/app-connections/general/add-connection.png)
        </Step>
        <Step>
            Select **Add Connection** and choose **AWS**.

            ![Select AWS Connection](/images/app-connections/aws/select-aws-connection.png)
        </Step>
        <Step>
            Fill out the form's fields:

            <ConnectionFormFields />

            Then, select **Connect to AWS**.

            ![AWS Connection Form](/images/app-connections/aws/create-assume-role-method.png)
        </Step>
    </Steps>
</View>

<View title="Project-level">
    <Steps>
        <Step>
            Open the project's app connections:

            - **Secrets Manager project:** select **Integrations** in the sidebar, then open the **App Connections** tab
            - **Certificate Manager project:** select **Settings** in the sidebar, then open the **App Connections** tab
        </Step>
        <Step>
            Select **Add Connection** and choose **AWS**.
        </Step>
        <Step>
            Fill out the form's fields:

            <ConnectionFormFields />

            Then, select **Connect to AWS**.
        </Step>
    </Steps>
</View>

When you select **Connect to AWS**, Infisical checks the credentials. For **Assume Role**, it assumes the role, so the role's trust policy has to name the right AWS account and External ID. For **Access Key**, it signs in with the access key. Infisical doesn't check the permissions from [Step 2](#step-2-add-permissions) until an integration uses them.

<Check>
    Your AWS app connection is ready to use.
</Check>
