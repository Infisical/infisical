Every Infisical product that has a CLI workflow starts the same way: install the CLI, log in, and check that the CLI can reach your Infisical instance. This page covers those steps, then links to the CLI guide for each product.

## Prerequisites

- An Infisical account on [Infisical Cloud](https://app.infisical.com) or on a [self-hosted instance](/self-hosting/overview)

## Step 1: Install the CLI

Install the CLI with the package manager for your operating system.

<InstallCli />

Check that the installation worked:

```bash
infisical --version
```

## Step 2: Log in

Log in with your own account when you use the CLI on your own machine. Log in as a [machine identity](/documentation/platform/identities/machine-identities) when the CLI runs without a person present, such as in a CI/CD pipeline or on a server.

<Note>
If your Infisical instance is behind a service that requires its own headers, such as Cloudflare Access, set the headers in the `INFISICAL_CUSTOM_HEADERS` environment variable before you log in. The CLI adds them to every request, including the login request.

```bash
export INFISICAL_CUSTOM_HEADERS="Access-Client-Id=<your-client-id> Access-Client-Secret=<your-client-secret>"
```

Separate each header from the next with a space, in the form `name=value`.
</Note>

<Tabs>
  <Tab title="Your own account">
    <LogIn />

    The CLI saves the instance you select with your login, so later commands use it without asking again. If you've already set an instance with the `--domain` flag, the `INFISICAL_DOMAIN` environment variable, or the `domain` field in [`.infisical.json`](/cli/project-config), `infisical login` uses that instance and skips the prompt.
  </Tab>
  <Tab title="Machine identity">
    <Steps>
      <Step>
        Follow the [Universal Auth guide](/documentation/platform/identities/universal-auth) to create a machine identity and get a **Client ID** and **Client Secret** for it.
      </Step>
      <Step>
        If you use EU Cloud, a dedicated instance, or a self-hosted instance, set `INFISICAL_DOMAIN` to the address of your instance. A machine identity login doesn't save the instance, so without `INFISICAL_DOMAIN` every command goes to US Cloud (`https://app.infisical.com`).

        <CodeGroup>
          ```bash macOS/Linux
          export INFISICAL_DOMAIN="https://your-domain.infisical.com"
          ```

          ```powershell Windows (PowerShell)
          setx INFISICAL_DOMAIN "https://your-domain.infisical.com"
          ```
        </CodeGroup>

        On Windows, `setx` saves the variable for new sessions only, so restart PowerShell before you run the next command.

        Instead of `INFISICAL_DOMAIN`, you can pass `--domain` on every command, or add a `domain` field to your project's [`.infisical.json`](/cli/project-config). If you set more than one, the `--domain` flag takes precedence, then `INFISICAL_DOMAIN`, then `.infisical.json`. The legacy `INFISICAL_API_URL` environment variable still works, but `INFISICAL_DOMAIN` takes precedence if both are set.

        <Warning>
          `.infisical.json` is usually committed to your repository, and the CLI sends every request and credential to the host in its `domain` field. Only set `domain` to an instance you trust.
        </Warning>
      </Step>
      <Step>
        Log in with the client ID and client secret, and store the access token in the `INFISICAL_TOKEN` environment variable:

        ```bash
        export INFISICAL_TOKEN=$(infisical login --method=universal-auth --client-id=<identity-client-id> --client-secret=<identity-client-secret> --silent --plain)
        ```

        `--plain` prints only the token, and `--silent` hides update and tip messages, so the command's output is just the token. The CLI reads `INFISICAL_TOKEN` automatically, so every later command in the same shell is authenticated.
      </Step>
    </Steps>
  </Tab>
</Tabs>

## Step 3: Check that you're logged in

```bash
infisical login status
```

The CLI asks your Infisical instance whether your login is valid. If it is, the output starts with the account or machine identity you're logged in as, followed by the instance the CLI connected to:

```text
✓ Authenticated as <your-email-or-identity-name>
  - Domain: https://app.infisical.com
```

The lines after `Domain` include when your login expires and which organization it belongs to. If the output says `You are not authenticated`, log in again. If it says `Failed to authenticate`, check that the `Domain` line shows your instance, then log in again.
