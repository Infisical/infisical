---
title: "Project configuration"
description: "Configure how the Infisical CLI interacts with your directory."
---

`.infisical.json` links a directory to an [Infisical project](/documentation/platform/project). When you run a command such as [`infisical run`](/cli/reference#run) or [`infisical secrets`](/cli/reference#secrets) in that directory, the CLI reads the project from the file, so you don't have to pass [`--projectId`](/cli/reference#run--flag-projectid).

The file can also [choose an environment for you](#set-the-environment) and [pin the Infisical instance](#set-the-infisical-instance) the project lives on.

<Info>
The `.infisical.json` file doesn't include any sensitive values and is safe to commit to version control.
</Info>

## Create the file

In the root of your codebase, run:

```bash
infisical init
```

Select the project when prompted. The CLI writes `.infisical.json` to the current directory:

```json .infisical.json
{
    "workspaceId": "<project-id>",
    "defaultEnvironment": "",
    "gitBranchToEnvironmentMapping": null
}
```

`workspaceId` is the project's ID. The other fields are empty until you set them, as described in the sections that follow. If you run [`infisical init`](/cli/reference#init) again, the CLI replaces the file with a new one that holds only the project ID, so you lose any settings you added.

<Note>
  If you authenticate as a [machine identity](/documentation/platform/identities/machine-identities), `infisical run`, [`infisical export`](/cli/reference#export), and `infisical secrets` don't read `workspaceId`. Pass the project with `--projectId` or the `INFISICAL_PROJECT_ID` environment variable instead.
</Note>

## Set the environment

Without an environment setting, commands read secrets from your project's [`dev` environment](/documentation/platform/secrets-mgmt/project#project-environments) unless you pass [`--env`](/cli/reference#run--flag-env). To use a different environment by default, set `defaultEnvironment` to the environment's slug:

```json .infisical.json
{
    "workspaceId": "<project-id>",
    "defaultEnvironment": "staging"
}
```

To pick the environment from the Git branch you're on, map branch names to environment slugs in `gitBranchToEnvironmentMapping`:

```json .infisical.json
{
    "workspaceId": "<project-id>",
    "defaultEnvironment": "dev",
    "gitBranchToEnvironmentMapping": {
        "main": "prod",
        "staging": "staging"
    }
}
```

The CLI matches only the last part of a branch name, after the final `/`. For example, the branch `release/staging` matches the key `staging`. If your current branch has no mapping, or you aren't on a branch (such as when you check out a specific commit), the CLI falls back to `defaultEnvironment`.

The CLI picks the environment in this order:

1. The `--env` flag
2. The environment mapped to your current Git branch
3. `defaultEnvironment`
4. `dev`

## Set the Infisical instance

If your project is on EU Cloud, a dedicated instance, or a self-hosted instance, set `domain` to the instance's address:

```json .infisical.json
{
    "workspaceId": "<project-id>",
    "domain": "https://eu.infisical.com"
}
```

`domain` must be a URL that starts with `https://` or `http://`, or the CLI ignores it and prints a warning.

<Note>
We recommend using `https://`, since over `http://`, the CLI sends secrets and credentials unencrypted.
</Note>

The CLI picks the instance in this order:

1. The [`--domain`](/cli/reference#global-flags--flag-domain) flag
2. The `INFISICAL_DOMAIN` environment variable, or the older `INFISICAL_API_URL` if `INFISICAL_DOMAIN` isn't set
3. `domain` in `.infisical.json`
4. US Cloud (`https://app.infisical.com`)

If you log in with your own account, [`infisical login`](/cli/reference#login) uses `domain` to choose the instance to log in to. After that:

- Any commands you run will connect to the instance you logged in to, even if `domain` specifies a different one
- If you pass `--domain` or set `INFISICAL_DOMAIN` to a different instance than the one you logged in to, the command fails

<Warning>
  The CLI sends every request and credential to the instance in `domain`. Because `.infisical.json` is usually committed, anyone who can change the file in your repository can change where the CLI sends them. Each time the CLI uses `domain` from the file, it prints a warning that names the host. Only set `domain` to an instance you trust, and check it when you clone a repository you don't control.
</Warning>

## Use the file from another directory

The CLI looks for `.infisical.json` in the current directory, then in each parent directory up to the root of the file system. This means that if you have an `.infisical.json` file in the root of your codebase, that configuration applies to every directory under it.

To read the project from a file somewhere else, such as one package's directory in a monorepo, pass the directory to `infisical run` with [`--project-config-dir`](/cli/reference#run--flag-project-config-dir):

```bash
infisical run --project-config-dir ./services/api -- npm run dev
```

<Note>
`--project-config-dir` only sets the project. The environment and instance settings still come from the `.infisical.json` the CLI finds from your current directory.
</Note>

## Field reference

<ResponseField name="workspaceId" type="string">
The ID of the project to read secrets from. Not used when you authenticate as a machine identity.
</ResponseField>

<ResponseField name="defaultEnvironment" type="string">
The environment slug to use when `--env` isn't passed and no branch mapping matches.
</ResponseField>

<ResponseField name="gitBranchToEnvironmentMapping" type="object">
Maps branch names to environment slugs, such as `{ "main": "prod" }`. Keys match only the last part of a branch name, after the final `/`.
</ResponseField>

<ResponseField name="defaultSecretPath" type="string">
The folder to read secrets from when [`--path`](/cli/reference#secrets-agent-proxy-run--flag-path) and `INFISICAL_SECRET_PATH` aren't set. Only the [`infisical secrets agent-proxy`](/cli/reference#secrets-agent-proxy) commands read it.
</ResponseField>

<ResponseField name="domain" type="string">
The Infisical instance to connect to, such as `https://eu.infisical.com`. Must start with `https://` or `http://`.
</ResponseField>
