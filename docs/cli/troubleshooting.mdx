---
title: "Troubleshoot failed CLI commands"
description: "Find out why a CLI command failed, using the request ID, status code, and message that the CLI prints."
---

When a CLI command fails on a request to Infisical, the error the CLI prints includes the ID that Infisical gave the request, the HTTP status code, and the message from the server. Save that error, because the request ID in it identifies the request in the Infisical server logs.

## Prerequisites

- The [Infisical CLI](/cli/install), version 0.44.0 or later

## Where the CLI prints the error

When a command fails, the CLI prints the error to stderr as plain text and exits with status `1`. These flags don't change that:

- `--log-format` and `--log-destination` change only the CLI's log messages, so they don't turn the error into JSON or move it to stdout (see the [global flags](/cli/reference#global-flags))
- `--silent` hides update notices and profile notices, but not the error

## Save the error

To keep the error, redirect stderr to a file with `2>`. For example, this command lists the folders at the root of a project's `prod` environment, and if it fails, the error is saved to `infisical.err`:

```bash
export INFISICAL_TOKEN=<access-token>

infisical sm secrets folders get --projectId=<project-id> --env=prod --path=/ --silent 2>infisical.err
```

- The CLI reads the machine identity's access token from `INFISICAL_TOKEN`, so the token doesn't appear in the command
- `2>` saves only stderr, so the folder list the command prints to stdout stays out of the file
- `--silent` keeps update notices out of the file

In a CI pipeline, use your pipeline's secret store to set `INFISICAL_TOKEN`, and keep `infisical.err` as a build artifact.

## What the saved error contains

If the machine identity in the [example](#save-the-error) isn't a member of the project, the command writes a file like this one:

```text
Request: GET https://app.infisical.com/api/v1/folders?directory=%2F&environment=prod&workspaceId=626884b6-d49f-425b-8e63-391a339ec94f
Instance: https://app.infisical.com
Request ID: req-7PQupHqgWGjWDC
Response Code: 403 Forbidden
Message: You are not a member of this project with ID 626884b6-d49f-425b-8e63-391a339ec94f. Please assign this identity to the project with the appropriate permissions, then try again.
Context:
  Check your credentials or verify you're using the correct domain. Current domain: https://app.infisical.com

  • Unable to get folders

If this issue continues, get support at https://infisical.com/slack
```

The error shows the request ID in `Request ID`, the HTTP status code in `Response Code`, and the message from the server in `Message`. It doesn't contain the access token, so you can store it and share it.

## Look up the request ID

Where you look up the request ID depends on where Infisical runs:

- If you self-host Infisical, search your Infisical server's logs for the request ID (every line the server logs for that request includes it, and together those lines show the route, the response status, and the error)
- If you use Infisical Cloud, share the request ID in the [Infisical community](https://community.infisical.com/)
