# v4

This folder is the v4 component source of truth. It is incubating. Product code must not import it. The only UI importer outside this folder is `src/pages/design-system`. Dedicated generation and introspection scripts may read the typed metadata; product code remains fenced from all v4 imports.

For the contribution workflow, read [Infisical UI](skills/infisical-ui/SKILL.md). Its [canonical rules](skills/infisical-ui/rules.json) also drive the workbench Rules page. Every rule, shared or component, has a `detect` field: `lint` names a check in `frontend/scripts/check-v4.ts`, `test` names the test that exercises it, and `review` means only a reader of the change will catch a break. Generation fails on a rule without one.

- Primitives are the shadcn Radix set (`radix-nova`), restyled by `v4.css`. Do not add a second primitive library.
- Colors, type and motion timing (`--v4-duration-*`, `--v4-ease-*`) come from `tokens.json`. Corners are square everywhere: there is no radius scale and no corner mode, so never set a border radius. Do not hard-code hex, raw Tailwind palette classes, or a literal duration or easing.
- The workbench uses a sidebar brand header, a content-width article and responsive comparison cards. Theme and accent sit in the TopBar's workbench menu; there is no floating dock. Brand tokens define its type and color.
- The brand accent is Infisical yellow `--v4-accent` (#e3f047 in both themes), paired with `--v4-on-accent`. The shadcn `bg-accent` role is neutral selection/hover, not the brand accent. Primary (and default, its alias) Buttons are the ink fill for the one main action; only accent Buttons use the shared accent material, for a page's one primary create action (Add new, Create key, New connection) in its header or toolbar, and for approval and grant moments. Save, Confirm, Submit, Download, empty-state actions and every button inside a sheet or dialog stay ink. Keep the global primary role ink and selection neutral: selected and pressed fills step toward a neutral surface in both themes, never a yellow tint. Follow rule/button-material and rule/accent-create in the canonical rules; do not repaint Buttons in examples.
- A fill that is the same in both themes keeps its label color in both themes: on-accent stays near-black on the accent, and the destructive Button is bad-fill with a white on-bad label in both themes. Only fills that flip with theme (ink, the soft status grounds) flip their foreground.
- Use `V4Scope` for the docs boundary and portal container. Workbench theme changes stay local and never update the user's saved theme or analytics.
- Descriptions: every description is optional (PageHeader, Card, Dialog, Sheet, EmptyState, Announcements, ApprovalQueue requests) and used strategically, not removed by reflex. Allowed: a one-sentence page lede, optionally with a Docs link; a one-line dialog or sheet subtitle that scopes the content; short lines that tell cards in a set apart; secondary row lines that carry a state or value. Not allowed: text that restates the title, a lede longer than one sentence, a marketing tagline. A dialog or sheet without a Description is fine: Radix links aria-describedby only while one is mounted (rule/strategic-descriptions).
- Containers: tables are framed (DataTable always; the frameless native Table only inside another surface), lists default to framed and change case by case, and a standalone Card is plain, its default, or no card. Set Card variant framed only for emphasis (org overview product cards, project cards with a footer band) or for a section card that heads part of a page (a detail sidecar, a roles or authentication section, settings sections). Never nest one frame in another (rule/no-nested-frames): Card, DataTable, List, ApprovalQueue and CodeBlock read the frame context from `lib/frame-context.tsx` and provide it to their subtree, so inside a frame a framed Card drops to plain and the others render frameless, embedded on the parent's inset. Overlay portals reset it. A new primitive that draws `frame.frame` must call `useInFrame` and wrap its subtree in `FrameScope`. The `nested-frame` ui:lint check flags an explicit `variant="framed"` inside a framed parent, and a development warning catches the nestings it cannot see (rule/container-defaults). A page CSS module under pages/v4 cannot see the frame it lands in, so it never draws a four-sided border or a non-focus outline around a box: use a frame-aware primitive, the frame's own section or the tint shade, or mark a box that is bordered everywhere with `v4-check-ignore page-css-frame` and the reason (rule/page-boxes-from-primitives, ui:lint page-css-frame).
- Links: Cipher components never import a router. A component that navigates takes `link` and renders `CipherLink` (`lib/link.tsx`); the app types `link` by augmenting `CipherRegister` and wires TanStack once with `V4RouterProvider` (`pages/v4/cipher-router.tsx`) in `V4Root` and the design system. Without the provider, links render plain anchors and Sidebar matches no route. RouteProgress takes `pending` from the app.
- Themes: a theme is a named palette in `tokens.json` `themes.list` (peach, pale, dark; shown as Lightly Peach, Light and Dark) with a `scheme` (light or dark). Every themed token keeps a light and a dark base value; a theme sits on one base (`base`) or extends another theme (`extends`) and lists in `overrides` only what differs, and ui:generate emits one `.v4[data-theme="<id>"]` rule per theme beside the `.v4[data-scheme="dark"]` base. V4Scope sets both `data-theme` (the theme id) and `data-scheme` on its root and portals. Branch on the scheme, never the theme name: `[data-scheme="dark"]` in CSS and `useV4Scheme()` in code (logos, charts, toasts); `useV4Theme()` is only for passing the theme on, such as a `?theme=` preview. Legacy `light` maps to peach and the retired `dark-alt` to dark everywhere a theme is read (V4Scope props, ancestors, stored preferences, `?theme=`). To add a theme, add its entry with only its overrides and run ui:generate; the pickers, the Color page and `docs/themes.md` (contrast per theme) pick it up. The live app keeps light, dark or system in the shared theme preference and remembers the named theme per scheme in localStorage `v4-theme`, so System resolves to the person's chosen light and dark themes (rule/theme-scheme, ui:lint theme-name-branch).
- `V4Scope` portals into `document.body` by default. Pass `portalContainer` to place its overlays inside a frame instead; that element must establish a containing block (transform or `contain: layout`) so fixed overlays stay within it. Popper-based contents pass `useV4CollisionBoundary()` as `collisionBoundary` so they flip and shift inside that frame; it is undefined for body portals.
- Every overlay content, submenus included, portals into that container at the one overlay layer (z-50); a nested overlay mounts after its parent and paints above it by DOM order. Never render overlay content inline inside another overlay or raise one overlay's z-index. Toasts portal into the V4Scope toast layer, a sibling placed right after that container, so they paint above every sheet and dialog on the same z-50 layer. AppShell mounts the one Toaster; Toaster renders once per toaster id, so a page that still mounts its own never duplicates a toast.
- Orgs have no avatar. Composites and compositions don't use avatars until the product supports them: show names and emails as plain text. The Avatar primitive and its docs page stay.
- After UI edits, run `npm run lint` in `frontend/`. Also run `npm run lint:v4` and `npm run ui:lint`. `ui:lint` runs the v4 checks against a baseline that only shrinks: a new finding fails, a fixed one is locked in with `npm run ui:lint -- --update`. Exempt one line with `v4-check-ignore <check> -- <reason>` on it or the line above; the reason is required. `lint:v4` is `@shadcn/lint` (`no-raw-colors`, `no-restyle`) as an Oxlint JS plugin on the docs route, configured in `.oxlintrc.v4.json` and kept out of `npm run lint`. The import fence and the relaxations for `v4/ui` and `v4/hooks` live in `.oxlintrc.json`. Do not add spacing or type classes to a v4 component. Wrap it instead.
- Add components with `npx shadcn@4.22.0 add <name> -y` from `frontend/`, which reads `components.json`. Do not run `shadcn init` here. It would retarget the app. The CLI resolves aliases from the root `tsconfig.json`, which is a solution file and must not gain a `paths` block: that slows the frontend lint past its 15 minute CI cap. If add cannot resolve `@app/*`, copy the `paths` block from `tsconfig.app.json` for that command only, and do not commit it.
- Primitives import `cn` from the `cn` package. That is the registry's helper. Do not rewrite those imports.
- These unrelated upstream items remain outside this React 19 foundation: attachment, bubble, direction, marker, message, message-scroller, questionnaire, trace.

Read the generated component guides in [docs/README.md](docs/README.md) or run `npm run ui:info -- <name>` from frontend. `npm run ui:generate` refreshes tokens, the catalog, documentation and standard registry payloads; `npm run ui:check` detects stale output and missing contracts. Start `npm run dev` and open `/design-system` in the app. Verification recipes in metadata are not passing evidence.

The registry is published publicly as Cipher (`@cipher/<item>`, base item `cipher-base`); see [cipher/README.md](../../../../cipher/README.md). `npm run cipher:release` regenerates it and copies the payloads to `cipher/r/`, which consumers fetch from raw GitHub URLs, so run it only for a release. Every registry file must work outside this app: an item that needs Infisical data, routes or app assets goes in `excludedFromRegistry` in `scripts/generate-ui.ts` with its reason, and generation fails when a published item depends on an excluded one.

## Human examples

Use the shared preview frame and ExampleGrid, ExampleCell and ExampleStage presentation components. Compare supported variants, distinct sizes and applicable states as labeled peers. Captions sit 8px below their own specimen and describe its actual state. Specimens and captions align to the start, and specimens in a row share a bottom baseline, so the captions of a row line up. Equal-appearance aliases share one specimen. Keep specimens in one row of similar height; give a much taller one its own row.

Use only the composition needed to demonstrate the component. Do not add synthetic save/reject/reset controls, request logs, export workflows or stress-test toolbars to Human pages. Ordinary action buttons do not become pressed toggles merely to produce feedback. Keep core interactions working and relevant states visible. Put technical orchestration in component tests and explain constraints in the closed Usage and rules disclosure. Generated Agent examples lower documentation-only presentation wrappers to native layout elements, so they remain portable.

## Icons

The v4 line set (52 glyphs from #8691, ui/icon-data.ts) is the primary icon set: use `<Icon name="..." />`. Use Lucide (`lucide-react`) only for glyphs the set lacks (Kbd keys, the unsorted sort arrows and similar), through `<Icon icon={...} />` or a direct import, drawn at `stroke-icon` (1.7) and the size tokens so it blends in. Do not hand-draw other SVG icons or import another icon library.

## System rules

- Disable, do not hide: a blocked action stays visible and disabled, with a reason, so the layout never shifts. A Button takes the reason as disabledReason, which keeps it focusable and shows the reason in a tooltip. Never wrap a natively disabled Button in a Tooltip or a span anchor: it takes no pointer or focus events, so the reason never reaches keyboard users (rule/disabled-reason-tooltip, ui:lint disabled-in-tooltip). Tooltips are pass-through: TooltipContent has pointer-events none and user-select none and the provider disables hoverable content, and TooltipTrigger opens on keyboard navigation focus only, so focus a menu, dialog or sheet returns never reopens it, and stays closed after a click until the pointer leaves and returns. Hovered, selectable or copyable content uses HoverCard, and actions use Popover (rule/tooltip-pass-through, ui:lint `interactive-tooltip`). Table wraps its rows in TooltipScope, so every Tooltip in a Table or DataTable shares one Radix root that mounts on first use; keep row tooltips uncontrolled (no open, defaultOpen, onOpenChange or delayDuration), or each one falls back to its own root. Gate each action by its own permission only; a person who may view a secret may copy it while it is masked.
- Pickers for entities a person may need to create first (app connections, gateways) pass Combobox `creation` with mode dialog, gated by disabledReason on the create permission. The Combobox owns the Dialog, its Cancel and submit, and routes every close through useDiscardChangesGuard. For app connections use `connectionCreation` with a preset from `pages/v4/data/integrations/connection-presets.ts`; presets take their schemas from `lib/schemas/app-connections.ts`, the same ones the v3 forms use. A redirect method (GitHub App install, OAuth) needs `redirect: connectionRedirect({ returnTo, projectId, option })` (`pages/v4/data/integrations/connection-redirect.ts`) from the caller, where `returnTo` is the calling flow's v4 href: it stores the state and half-filled form under `V4_CONNECTION_REDIRECT_STORAGE_KEY` (`helpers/appConnections.ts`, which main's `OAuthCallbackPage` reads to forward a matching state to v4) and the v4 callback route (`pages/v4/organization/AppConnectionCallbackPage`) creates the connection and returns there with `connectionId` and `connectionName`, so read those search params instead of adding a per-flow callback.
- Row actions are persistent: they live in the table's actions tail, the sticky last column (DataTable `rowActions`, or `TableActionsCell` with `RowActions` in a native Table) and show on every row at rest. Use at most three inline icon actions, then the More menu for the rest. Nothing a hover or focus shows may change a cell's width or the row's layout, so there is no hover reveal and no indicator that swaps out for actions; this overrides matching main's hover actions. The actions tail end-aligns its actions, so the last one sits at the inset on every row, and takes its width from the widest row: size-row (a square) for one, plus size-row-action-step for each further action. Every actions tail (rowActions, TableActionsCell, a column with actions true) caps its Buttons at size-target-row, so a text button like Open is 28px tall like icon-row; never set a width, size or padding on an actions tail. Row stripe, selection and hover are layers the pinned cells repaint opaquely, so a row reads as one band to the frame edge. The DataTable selection column is size-row wide with a persistent line-soft divider on its right.
- One hover color: every neutral hover ground (sidebar rows and tools, table, list, tree and grid rows, menu rows, segments, ghost and outline actions, tiles) is `var(--v4-hover)`, and pressed is `var(--v4-press)`. Both are translucent `mix-ink` (ink, or peach's warm dark neutral), so they land on whatever ground is underneath, darken it in light schemes and brighten it in dark ones, with no per-theme value; tune the strength in one place with `hover-mix` and `press-mix`. Where a fill must be opaque (a pinned cell, a ring that cuts out a dot), mix `var(--v4-mix-ink)` at `var(--v4-hover-mix)` into that ground with `color-mix(in srgb, ...)`, which matches how the overlay composites. `sidebar-current` is `mix-ink` at `current-mix` mixed into the sidebar, a small step past hover, and `selected-surface` takes its alpha from `selected-mix`. The sidebar's hover highlight is `var(--v4-sidebar-hover)`, which follows `sidebar-current` unless a theme quiets it. Never give a hovered element a flat ground such as tint or surface (rule/translucent-hover, ui:lint `flat-hover`).
- Cursor: styled controls keep the default cursor, even when they render an anchor: Button in every variant but link, toggles, Select, Combobox and MultiSelect triggers, menu, Switcher, Sidebar and nav sheet rows, Tabs, crumb switcher triggers, row actions, Checkbox, Radio and Switch. Only links take cursor: pointer: text anchors, RowLink and CardLink, crumb names that navigate, the link Button and unstyled text buttons that read as links (rule/pointer-cursor-for-links, ui:lint cursor-pointer). The check passes a CSS selector that names a link (a, [href], :any-link, or link in a class or attribute name) and flags every Tailwind cursor-pointer and inline pointer cursor. Anything else that reads as a link marks its rule with v4-check-ignore cursor-pointer and the reason; in CSS the marker may sit in a comment right before the rule.
- Line roles: line-soft is the default border, the outward edge of every inset surface, card, plain list, table, popover, dialog and bordered tile, the app shell chrome (AppInset island, band rule, sidebar edge and separators) and every divider that touches one of those edges. line is only for a standalone rule that touches no other border: a section rule, the band's divider marks, a lone hr, a tree guide, the tab track, chart axes. Control borders keep their control tokens (rule/line-roles, ui:lint line-on-edge flags a four-sided line border).
- No left accent bars: never mark a row, card, Alert or current state with a colored stripe or tinted left edge, even where main does. Use a translucent tint over the whole row or surface plus a Badge or icon with text. Tree guides, timeline connectors and dividers in line or line-soft are structure, not accents.
- Loading: while a whole page or its lazy chunk loads, show the page loader (Loader size page) as the Suspense fallback or page body. Inside a rendered page, show Skeleton shapes when the loaded shape is known, the table's loading rows for rows in a table on screen, and Loader only when the shape is unknown.
- Placeholders and values: every field placeholder, in Input, Textarea, SecretInput, the SensitiveEditor replacement box and any textarea or contenteditable value editor (a `::before` or `data-placeholder` placeholder included), is `var(--v4-muted)`, the color of the shared `.field ::placeholder` rule in controls.module.css, so placeholders read the same everywhere. Never dim one to faint, which is for disabled text, or repaint one in a page stylesheet. Secret values, typed or masked, and their placeholders use the body role in the UI sans; keep Geist Mono for read-only literal machine text such as code blocks, IDs and keys.
- Row focus: while a row is being edited in place (its annotation popover, an inline name or value edit), set `focused` on its TableRow or pass DataTable `focusedRowId`, and clear it when the edit closes; the other rows of that body, and of every body that holds it, dim to `opacity-row-dim`. Never use it for selection or a current record, and never dim rows with a page's own opacity or filter (rule table-row-focus).
- No :has(): never write a :has() selector or a Tailwind has-* variant in v4 CSS or classes; Chrome re-checks it on DOM changes far from the element, so one cell update in a large table relayouts the page. Set a data attribute from props, a child's context report (lib/presence-count.ts) or useDescendantFlags (lib/descendant-flags.ts) and select on that (rule/no-has-selectors, ui:lint has-selector).
- Focus: fields, slider thumbs and other glow-focused controls share one glow, size-focus-glow in focus-ring (neutral ink, never the accent).
- Menus: every menu-like popover (Switcher, account menu, DropdownMenu, Select and Combobox lists, ContextMenu, CommandMenu) uses the shared recipe in menu.module.css: pop ground, pop-line edge and shadow-pop, a 3px inset on all four sides, 32px rows as inset blocks, eyebrow labels and one lead-icon column. Separators may span the panel; rows and their tints never touch its edge.
- Shared highlight: every vertical selectable list (menus, Select, MultiSelect, Combobox, CommandMenu, Switchers, the Sidebar nav) draws two translucent thumbs from `ListHighlight` in lib/list-highlight.tsx, rendered as the list's last child. The hover thumb follows the pointer and the keyboard's active row and stays on the last row while the pointer is anywhere in the panel, gaps, labels and separators included; it hides when the pointer leaves the panel, the menu closes or keyboard focus leaves. The selection thumb rests on the current row and shows only while the hover thumb is hidden, cross-fading on fade.enter. Keyboard entry starts the hover thumb on the current row. Thumbs measure offsets inside the list (never viewport rects), stay hidden until their first measurement, appear in place without gliding from a stale spot, and glide on spring.moderate after that; reduced motion jumps. Rows in such a list draw no tint of their own, and the current row keeps its 600 weight and check. An expanded row (aria-haspopup with aria-expanded true or data-state open: a rail flyout, a submenu parent, a Switcher row opening a nested list) pins the hover thumb until its popover closes, even with the pointer inside the popover; ListHighlight derives this from the trigger, so call sites add nothing.
- Triggers defer to Button: a menu, popover or select trigger takes Button's rest, hover, pressed, open and focus states on the whole control. Never draw an inner tint inside a bordered control.
- Fonts: Archivo is the sans for everything people read and name; Geist Mono is only for machine values a person copies or compares character by character (secret keys, IDs, hashes, fingerprints, serials, hosts, paths, env var names, code, key IDs, optionally aligned numbers). Names people chose (project, organization, environment, role, group, identity, user, folder, key, certificate common name, connection) stay in the sans, in crumbs, switchers, titles and table primaries too. A slug takes mono only where it is shown or edited as the slug. Never set a font family on html, body, V4Scope, AppShell or a theme, and reach mono only through a primitive's mono prop or the mono type role on a machine value. DataTable primary is sans; a column opts in with mono (rule/mono-machine-values, ui:lint mono-named-entity).
- Triggers start-align their value: Select, Combobox, MultiSelect and any Button that opens a menu, popover or picker put the label at the start, truncate it and put the chevron at the end. A Button trigger passes `layout="trigger"`, which draws the chevron and takes SelectTrigger's insets; never center the value or add `iconRight="chev-down"` to a plain Button (rule/trigger-start-aligned, ui:lint trigger-start-aligned).
- Tab width: Tabs and ToggleGroup take one width prop that sizes the track and its triggers together. The default, content, fits the track to its triggers; full stretches the track and gives every trigger an equal share. Never set a width, flex or grow on a tab list, track or trigger, so a full-width track never holds content-width triggers (rule/tab-width, ui:lint tab-width). The underline variant's rule is a divider and spans its container under content-width triggers; UNDERLINE_RULE_SPANS in ui/tabs.tsx is the one switch for it.
- Chevron tiles: a trailing chevron sits at the far edge only on an item with its own ground. Use Tile, which is bordered on a bare surface and takes the tint shade instead inside a framed Card, List or DataTable; on an unframed item the chevron follows its content (rule/chevron-tile-frame).
- Kbd: caps are size-kbd-md (20px), size-kbd-sm (18px) or size-kbd-xs (16px, tooltips). Single glyphs are square; longer labels grow with equal side padding. A host slot sets --v4-kbd-host-block and --v4-kbd-host-end so the trailing gap equals the vertical gap.
- What's new: the Overview's "What's new" list (`recentChanges` in `pages/design-system/overview-data.ts`) is kept by hand. Every push with a user-visible system change adds one entry, newest first: `id`, `title`, a one-sentence `description` in v4 voice, `date`, the short `commit`, and `page` (a `workbenchPages` id) when a workbench page shows it. Merge closely related changes into one entry so it reads as a changelog, keep about 15 entries, and drop the oldest past that.

## Workbench navigation and search

The workbench itself runs in a real AppShell on real routes: `/design-system` is the Overview, and every other page is `/design-system/foundations/$page`, `/design-system/components/$group/$component`, `/design-system/patterns/$pattern` or `/design-system/comparisons/$comparison` (virtual routes in `src/routes.ts`, files in `pages/design-system/routes/`). `navigation.ts` is the route manifest: each page carries its typed `link`, and the Sidebar levels, the TopBar crumbs and switchers, and the palette all read it. Route definitions load with main's entry, so they import nothing from the design system or v4 (the bundle fence fails the build otherwise): validation and redirects live in the split components. The layout sends old `#<page>` URLs on `/design-system` to their route (`legacyHashLink`), a page route with an unknown slug and `/design-system/$` (category paths, unknown pages) navigate to the first page they name, and `pendingComponent` is a `lazyRouteComponent`. The TopBar band's breadcrumb reads category, group (components only) and page, its account menu is the Workbench menu (pages, links, theme and accent), the v4 Sidebar takes `levels` (a top level with Overview and the four categories, then one level per category, Components with one eyebrow section per group, each with an icon so the rail shows one flyout row per group), and AppInset. Mod+B toggles the sidebar (AppShell owns the chord, so it works the same in every shell). Mod+K and the TopBar search button open the command palette (`pages/design-system/workbench-palette.tsx`, built on CommandMenu). Its index is derived from `navigation.ts` and the generated catalog, so every page, alias and example section is searchable without a hand-kept list. - Page content width: the size-content token (1160px) sets the page gutter that AppInset derives and PageGutter pads by. Wrap page content in PageGutter; never cap it with mx-auto and an arbitrary max-w.
- Detail pages that pair one details card with stacked content cards use DetailLayout: the sidecar (size-sidecar) sits on the right and stacks above the content below size-sidecar-collapse of the layout's own width. Never hand-build that two-column grid. Record facts in those cards use DataList density compact, with short values paired by span half.
- Status cells: report a state with StatusText (a line icon plus words), never color alone or a brand mark, and derive it only from fields the API returns.
- Bulk selection uses the floating action bar (FloatingActionBar), never an inline bar. Selecting or clearing rows must not move layout. The bar is fixed to the bottom center of the window on every page, even where it crosses the sidebar; it portals into the V4Scope overlay container at z-index 40, above page content and sticky headers and below every z-50 overlay and toast. While it shows it pads AppInset by its height plus its offset, so the last rows and the pagination scroll clear of it. Pass it to DataTable's actionBar when a DataTable holds the selection and never position it yourself (rule/selection-floating-action-bar).
- Tables and list pages follow one recipe:
  - A row that goes to the record's page puts RowLink in its primary cell; never navigate from onRowActivate (rule/row-navigation-link, ui:lint row-activate-navigates).
  - A row that opens its record in a Sheet or Dialog uses onRowActivate plus a quiet link Button (variant link, underline hover: underlined only on hover and keyboard focus) with the record's name in the primary cell. It has no RowLink, so no chevron, and no Open action in the tail; a URL-addressable sheet may use RowLink with chevron={false} (rule/sheet-row-open).
  - Pagination goes in DataTable's pagination slot with variant="compact", never as a sibling after the table (rule/pagination-in-frame, ui:lint pagination-outside-frame).
  - Action results (copied, saved, deleted, moved, uploaded, failed) are toasts, never footer or status-line text; DataTable's persistentStatus holds only state that must stay visible, such as "Showing 5 of 120 after filter" (rule/toast-action-feedback, ui:lint action-feedback-in-status).
  - A hand-built Table row with RowActions or a TableActionsCell wraps itself in RowContextMenu (rule/row-context-menu, ui:lint row-actions-without-context-menu).
  - Resource lists inline the one most-used non-destructive action, such as Edit, Rotate or View logs, then More; destructive actions stay in More (rule/row-actions-inline-primary).
  - Full list pages search and filter with FilterBar, which drops Add filter when it has no fields; a search box with an icon-only filter menu is only for search inside a Card header (rule/list-page-filter-bar).
  - A table inside a Card or SettingsCard is a DataTable; the native Table is for the secrets matrix and dialog, sheet and popover internals (rule/detail-card-data-table, ui:lint raw-table-in-card).
  - A detail page's facts card uses DataList density compact (rule/detail-facts-compact).
  - pages/v4 findings for these checks sit in scripts/check-v4-baseline.json until the sweep fixes them.
- v4 paths: never write the /v4 prefix as a literal in pages/v4 or components/v4 (to=, href=, navigate, redirect, startsWith, regular expressions). Build links through the v4 link helpers in pages/v4/links.ts (orgHref, useGo); the resolver is src/helpers/v4Bridge.ts. Moving v4 to the root at launch is then a change to those modules and the route definitions only. Route definition files and the modules in the check's v4PathModules list (scripts/check-v4.ts) may spell it, and a route ID passed as a from: value or to getRouteApi is exempt because TanStack type-checks it; anything else that must takes v4-check-ignore v4-path-literal with a reason (rule/v4-path-helper, ui:lint v4-path-literal).
