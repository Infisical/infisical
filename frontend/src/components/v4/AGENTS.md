# v4

This folder is the Infisical 2.0 component source of truth. It is incubating. Product code must not import it. The only UI importer outside this folder is `src/pages/design-system`. Dedicated generation and introspection scripts may read the typed metadata; product code remains fenced from all v4 imports.

For the contribution workflow, read [Infisical UI](skills/infisical-ui/SKILL.md). Its [canonical rules](skills/infisical-ui/rules.json) also drive the workbench Rules page. Every rule, shared or component, has a `detect` field: `lint` names a check in `frontend/scripts/check-v4.ts`, `test` names the test that exercises it, and `review` means only a reader of the change will catch a break. Generation fails on a rule without one.

- Primitives are the shadcn Radix set (`radix-nova`), restyled by `v4.css`. Do not add a second primitive library.
- Colors, type and motion timing (`--v4-duration-*`, `--v4-ease-*`) come from `tokens.json`. Corners are square everywhere: there is no radius scale and no corner mode, so never set a border radius. Do not hard-code hex, raw Tailwind palette classes, or a literal duration or easing.
- The workbench uses a sidebar brand header, a content-width article and responsive comparison cards. Theme and accent sit in the TopBar's workbench menu; there is no floating dock. Brand tokens define its type and color.
- The brand accent is Infisical yellow `--v4-accent` (#e3f047 in both themes), paired with `--v4-on-accent`. The shadcn `bg-accent` role is neutral selection/hover, not the brand accent. Primary (and default, its alias) Buttons are the ink fill for the one main action; only accent Buttons use the shared accent material, for a page's one primary create action (Add new, Create key, New connection) in its header or toolbar, and for approval and grant moments. Save, Confirm, Submit, Download, empty-state actions and every button inside a sheet or dialog stay ink. Keep the global primary role ink and selection neutral: selected and pressed fills step toward a neutral surface in both themes, never a yellow tint. Follow rule/button-material and rule/accent-create in the canonical rules; do not repaint Buttons in examples.
- A fill that is the same in both themes keeps its label color in both themes: on-accent stays near-black on the accent, and the destructive Button is bad-fill with a white on-bad label in both themes. Only fills that flip with theme (ink, the soft status grounds) flip their foreground.
- Use `V4Scope` for the docs boundary and portal container. Workbench theme changes stay local and never update the user's saved theme or analytics.
- `V4Scope` portals into `document.body` by default. Pass `portalContainer` to place its overlays inside a frame instead; that element must establish a containing block (transform or `contain: layout`) so fixed overlays stay within it. Popper-based contents pass `useV4CollisionBoundary()` as `collisionBoundary` so they flip and shift inside that frame; it is undefined for body portals.
- Orgs have no avatar. Composites and compositions don't use avatars until the product supports them: show names and emails as plain text. The Avatar primitive and its docs page stay.
- After UI edits, run `npm run lint` in `frontend/`. Also run `npm run lint:v4` and `npm run ui:lint`. `ui:lint` runs the v4 checks against a baseline that only shrinks: a new finding fails, a fixed one is locked in with `npm run ui:lint -- --update`. Exempt one line with `v4-check-ignore <check> -- <reason>` on it or the line above; the reason is required. `lint:v4` is `@shadcn/lint` (`no-raw-colors`, `no-restyle`) as an Oxlint JS plugin on the docs route, configured in `.oxlintrc.v4.json` and kept out of `npm run lint`. The import fence and the relaxations for `v4/ui` and `v4/hooks` live in `.oxlintrc.json`. Do not add spacing or type classes to a v4 component. Wrap it instead.
- Add components with `npx shadcn@4.22.0 add <name> -y` from `frontend/`, which reads `components.json`. Do not run `shadcn init` here. It would retarget the app. The CLI resolves aliases from the root `tsconfig.json`, which is a solution file and must not gain a `paths` block: that slows the frontend lint past its 15 minute CI cap. If add cannot resolve `@app/*`, copy the `paths` block from `tsconfig.app.json` for that command only, and do not commit it.
- Primitives import `cn` from the `cn` package. That is the registry's helper. Do not rewrite those imports.
- These unrelated upstream items remain outside this React 19 foundation: attachment, bubble, direction, marker, message, message-scroller, questionnaire, trace.

Read the generated component guides in [docs/README.md](docs/README.md) or run `npm run ui:info -- <name>` from frontend. `npm run ui:generate` refreshes tokens, the catalog, documentation and standard registry payloads; `npm run ui:check` detects stale output and missing contracts. Start `npm run dev` and open `/design-system` in the app. Verification recipes in metadata are not passing evidence.

## Human examples

Use the shared preview frame and ExampleGrid, ExampleCell and ExampleStage presentation components. Compare supported variants, distinct sizes and applicable states as labeled peers. Captions sit 8px below their own specimen and describe its actual state. Specimens and captions align to the start, and specimens in a row share a bottom baseline, so the captions of a row line up. Equal-appearance aliases share one specimen. Keep specimens in one row of similar height; give a much taller one its own row.

Use only the composition needed to demonstrate the component. Do not add synthetic save/reject/reset controls, request logs, export workflows or stress-test toolbars to Human pages. Ordinary action buttons do not become pressed toggles merely to produce feedback. Keep core interactions working and relevant states visible. Put technical orchestration in component tests and explain constraints in the closed Usage and rules disclosure. Generated Agent examples lower documentation-only presentation wrappers to native layout elements, so they remain portable.

## Icons

The Infisical 2.0 line set (52 glyphs from #8691, ui/icon-data.ts) is the primary icon set: use `<Icon name="..." />`. Use Lucide (`lucide-react`) only for glyphs the set lacks (Kbd keys, the unsorted sort arrows and similar), through `<Icon icon={...} />` or a direct import, drawn at `stroke-icon` (1.7) and the size tokens so it blends in. Do not hand-draw other SVG icons or import another icon library.

## System rules

- Disable, do not hide: a blocked action stays visible and disabled, with a reason, so the layout never shifts. Gate each action by its own permission only; a person who may view a secret may copy it while it is masked.
- Row actions are persistent: they live in the table's actions tail, the sticky last column (DataTable `rowActions`, or `TableActionsCell` with `RowActions` in a native Table) and show on every row at rest. Use at most three inline icon actions, then the More menu for the rest. Nothing a hover or focus shows may change a cell's width or the row's layout, so there is no hover reveal and no indicator that swaps out for actions; this overrides matching main's hover actions. The actions tail end-aligns its actions, so the last one sits at the inset on every row, and takes its width from the widest row: size-row (a square) for one, plus size-row-action-step for each further action. Every actions tail (rowActions, TableActionsCell, a column with actions true) caps its Buttons at size-target-row, so a text button like Open is 28px tall like icon-row; never set a width, size or padding on an actions tail. Row stripe, selection and hover are layers the pinned cells repaint opaquely, so a row reads as one band to the frame edge. The DataTable selection column is size-row wide with a persistent line-soft divider on its right.
- Hover and press overlays on anything with content behind it are translucent ink (opacity-hover and opacity-press), never an opaque fill.
- No left accent bars: never mark a row, card, Alert or current state with a colored stripe or tinted left edge, even where main does. Use a translucent tint over the whole row or surface plus a Badge or icon with text. Tree guides, timeline connectors and dividers in line or line-soft are structure, not accents.
- Loading: while a whole page or its lazy chunk loads, show the page loader (Loader size page) as the Suspense fallback or page body. Inside a rendered page, show Skeleton shapes when the loaded shape is known, the table's loading rows for rows in a table on screen, and Loader only when the shape is unknown.
- Focus: fields, slider thumbs and other glow-focused controls share one glow, size-focus-glow in focus-ring (neutral ink, never the accent).
- Menus: every menu-like popover (Switcher, account menu, DropdownMenu, Select and Combobox lists, ContextMenu, CommandMenu) uses the shared recipe in menu.module.css: pop ground, pop-line edge and shadow-pop, a 3px inset on all four sides, 32px rows as inset blocks, eyebrow labels and one lead-icon column. Separators may span the panel; rows and their tints never touch its edge.
- Shared highlight: every vertical selectable list (menus, Select, MultiSelect, Combobox, CommandMenu, Switchers, the Sidebar nav) draws two translucent thumbs from `ListHighlight` in lib/list-highlight.tsx, rendered as the list's last child. The hover thumb follows the pointer and the keyboard's active row and stays on the last row while the pointer is anywhere in the panel, gaps, labels and separators included; it hides when the pointer leaves the panel, the menu closes or keyboard focus leaves. The selection thumb rests on the current row and shows only while the hover thumb is hidden, cross-fading on fade.enter. Keyboard entry starts the hover thumb on the current row. Thumbs measure offsets inside the list (never viewport rects), stay hidden until their first measurement, appear in place without gliding from a stale spot, and glide on spring.moderate after that; reduced motion jumps. Rows in such a list draw no tint of their own, and the current row keeps its 600 weight and check. An expanded row (aria-haspopup with aria-expanded true or data-state open: a rail flyout, a submenu parent, a Switcher row opening a nested list) pins the hover thumb until its popover closes, even with the pointer inside the popover; ListHighlight derives this from the trigger, so call sites add nothing.
- Triggers defer to Button: a menu, popover or select trigger takes Button's rest, hover, pressed, open and focus states on the whole control. Never draw an inner tint inside a bordered control.
- Kbd: caps are size-kbd-md (20px), size-kbd-sm (18px) or size-kbd-xs (16px, tooltips). Single glyphs are square; longer labels grow with equal side padding. A host slot sets --v4-kbd-host-block and --v4-kbd-host-end so the trailing gap equals the vertical gap.

## Workbench comparisons

`/design-system` has a Comparisons group: one page per product screen with a before/after slider (`pages/design-system/comparison-slider.tsx`). Before is a committed WebP of the current app on main (`assets/comparisons/<screen>-<light|dark>.webp`, 1706x971 at 2x, seeded data). After is an iframe of the screen's routed demo page in the v4 app (`/v4/organizations/demo/...`, see `pages/v4`), laid out at 1706x971, scaled to the stage, and given the workbench theme through `?theme=`. Each comparison's `href` lives in `pages/design-system/navigation.ts`, and the Access captures map to theirs in `access-views.ts`. The handle drags, takes Left and Right (Shift for 10%), Home and End, and Reset returns it to the page's start. "Live, full width" links to the routed page itself.

## Workbench navigation and search

The workbench itself runs in a real AppShell on real routes: `/design-system` is the Overview, and every other page is `/design-system/foundations/$page`, `/design-system/components/$group/$component`, `/design-system/patterns/$pattern` or `/design-system/comparisons/$comparison` (virtual routes in `src/routes.ts`, files in `pages/design-system/routes/`). `navigation.ts` is the route manifest: each page carries its typed `link`, and the Sidebar levels, the TopBar crumbs and switchers, and the palette all read it. Route definitions load with main's entry, so they import nothing from the design system or v4 (the bundle fence fails the build otherwise): validation and redirects live in the split components. The layout sends old `#<page>` URLs on `/design-system` to their route (`legacyHashLink`), a page route with an unknown slug and `/design-system/$` (category paths, unknown pages) navigate to the first page they name, and `pendingComponent` is a `lazyRouteComponent`. The TopBar band's breadcrumb reads category, group (components only) and page, its account menu is the Workbench menu (pages, links, theme and accent), the v4 Sidebar takes `levels` (a top level with Overview and the four categories, then one level per category, Components with one eyebrow section per group, each with an icon so the rail shows one flyout row per group), and AppInset. Mod+B toggles the sidebar (AppShell owns the chord, so it works the same in every shell). Mod+K and the TopBar search button open the command palette (`pages/design-system/workbench-palette.tsx`, built on CommandMenu). Its index is derived from `navigation.ts` and the generated catalog, so every page, alias and example section is searchable without a hand-kept list. - Page content width: the size-content token (1160px) sets the page gutter that AppInset derives and PageGutter pads by. Wrap page content in PageGutter; never cap it with mx-auto and an arbitrary max-w.
- Detail pages that pair one details card with stacked content cards use DetailLayout: the sidecar (size-sidecar) sits on the right and stacks above the content below size-sidecar-collapse of the layout's own width. Never hand-build that two-column grid. Record facts in those cards use DataList density compact, with short values paired by span half.
- Status cells: report a state with StatusText (a line icon plus words), never color alone or a brand mark, and derive it only from fields the API returns.
- Bulk selection uses the floating action bar (FloatingActionBar), never an inline bar. Selecting or clearing rows must not move layout.
